### r2 follow-up: root test scope and source digest

Lead review identified two additional risks in the old CLI: bare `pnpm test` delegates to root `node --test`, whose discovery scope is not an appropriate proof of worktree isolation; and an 85-second command timeout is too short for a workspace build. The verification CLI now enumerates only `.test.mjs`/`.spec.mjs` under the current repository root's `tests/` tree, then calls `node --test --test-concurrency=1` with those explicit paths. This includes tooling tests but excludes sibling `.worktrees` trees. `sourceIdentity` is exported for Lead's harness; it resolves Git status paths and file contents from `process.cwd()`, so call it from the repository root. Its dirty digest length-prefixes each path and contents, covers apps/packages/src/migrations/scripts/tests/test-support, docs, deployment paths, Compose files, pnpm workspace/lock/package inputs and docs gate configuration, and keeps `commit: null` for an uncommitted source tree. A clean tree records HEAD as commit. Command timeout defaults to 600000 ms and accepts `DGOS_VERIFY_COMMAND_TIMEOUT_MS` as an integer at least 1000; each command result records the effective timeout and explicitly marks signal/timeout failure.

Follow-up verification: `node --check` of script and tooling test exited 0; `node --test tests/tooling/verify-release.test.mjs` exited 0 with 8 passed / 0 failed. New assertions cover root-only discovery, length-delimited digest ambiguity and exported dirty-tree identity. `git diff --check` had no diagnostics. No full release script, service start, Redis mutation or additional PG test was run in this follow-up.
