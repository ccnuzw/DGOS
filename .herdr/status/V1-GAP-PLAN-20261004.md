## P0 硬阻塞

### P0-1：候选冻结与文档审批重绑

- 当前 `candidate:freeze` 只能产出 dirty 诊断候选，不能作为正式发布候选。
- `release-gate` 当前失败项：
  - `APPROVAL_STALE`：`docs-evidence.json` 的权威文档 digest 已过期。
  - `SOURCE_CHANGED_SINCE_COMMIT`：审批绑定 commit 后仍有非证据文件变化，包括 `.env.example` 与 `.github/workflows/*`。
- 完成标准：确定冻结边界，生成唯一 commit；重新生成文档证据审批；`release-gate` 的 migration、secret、docs structure、docs release 全部 PASS。

### P0-2：独立 Verify 同候选复验

- 当前 W4 是 Lead 在当前工作树执行的统一证据，不等于独立验收。
- 完成标准：Verify 使用同一冻结 commit 运行 W4；结果不得混入旧 bundle、旧 dist 或旧 manifest。

### P0-3：真实依赖与目标部署证据

- 当前 Provider、MCP、Assistant 和 Native 关键链仍使用 local fixture / loopback / debug bundle。
- 隔离 PostgreSQL/Redis 尚未配置，定向测试中的 `4 SKIP` 不计为 PASS。
- 仍缺真实 Provider、TLS/CA/DNS、KMS/生产 Secret backend、目标部署和发布信任根证据。
- 完成标准：每项外部依赖有日期、环境、构建标识、命令、manifest 和限制；失败证据保留，不用 fixture 结果替代。

## P1 V1 AC 缺口

依据 `.herdr/work/wp-day1-fr-ac-gap.md` 与 `docs/02-产品与版本/当前版本/V1-Day1-FR-AC缺口评估-2026-10-04.md`，正式 V1 仍需按以下顺序推进：

1. **FR-001 桌面与工作区**：补包校验失败无副作用、地区/语言分离、GUI 代理重启生效、双宿主拒绝路径，以及正式签名制品验证。
2. **FR-005 文本任务**：在同一冻结候选补 SSE cursor、刷新恢复、断线/失败/重复提交矩阵，并补真实 Provider 证据。
3. **FR-007 模型平台**：补 Provider 失败停用与既有任务收敛、Model Profile 全量拒绝路径、验证/刷新并发和选择器同步。
4. **FR-010/011 身份与 API Key**：补生产 Cookie/CSRF/Origin、Secret backend、最终迁移候选、双宿主和高风险再认证证据。
5. **FR-012/013 Provider 账号与连接**：补停用传播、跨主体/CAS、活动引用删除保护、真实外部 Provider 和目标 CA/DNS。
6. **FR-014/015 治理与额度**：补高风险入口故障原子性、多存储恢复、全终态 reconciliation、可信 usage UI 与性能批准。
7. **FR-003/009 当前已通过的演示链**：保留回归测试，同时补页面关闭/重载后的持久 Run、动作 registry 生命周期和真实双宿主证据。

## P2 后置范围

FR-004 无限画布与项目、FR-006 Canvas 插件与模板扩展、FR-008 项目资产与生成历史，以及 FR-005/007 的高级多媒体、画布、节点编排和批量队列，不应混入当前 V1 Release 阻塞清单；按 V2–V5 规划继续管理。

## 推荐推进波次

### Wave 0：冻结与证据重建（先做）

- Lead 明确当前 dirty 改动的冻结边界。
- Verify/Planner 检查权威文档与审批绑定。
- 生成唯一候选 commit，重跑 `candidate:freeze`、`release-gate`、W4。

### Wave 1：外部依赖验收

- Worker-AI：隔离 PostgreSQL/Redis、真实 Provider/TLS/CA/DNS。
- Worker-DevOps：KMS/Secret backend、目标部署、发布信任根和回滚证据。
- Worker-Native：正式签名/公证/目标环境启动和升级/回滚。

### Wave 2：V1 AC 收口

- Worker-Platform：FR-010–015 的生产治理、权限、引用保护、恢复与 reconciliation。
- Worker-Web：FR-001/005/007/009 的双宿主状态、刷新恢复、错误矩阵和可访问交互。
- Worker-Test：把每个剩余 AC 映射到可执行测试和 manifest，禁止“只有代码无证据”。

### Wave 3：独立验收与发布决策

- Verify 只验冻结 commit；检查 source drift、候选 digest、证据新鲜度和限制声明。
- Lead 根据门禁结果在 `READY_FOR_RELEASE` / `BLOCKED` 中二选一，不以本地 MVP PASS 推导正式发布通过。

## 不应做的事

- 不修改 `docs-evidence.json` / `docs-gate.json` 伪造审批通过。
- 不把 local fixture、debug bundle、loopback 或历史 manifest 写成真实 Provider、正式签名或生产通过。
- 不为了清理工作树删除其他会话的 dirty 改动；冻结前先划定边界并保留证据。
