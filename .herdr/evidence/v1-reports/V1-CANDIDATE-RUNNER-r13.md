## Binding contract

Lead supplies one fixed repository-relative JSON bindings file. It retains `build_sha256` and `runtime_assets.image` as the candidate image identity; host Node tests do not run in that image.

`runtime_assets.config.files` must bind **all** of these fixed non-secret paths by repository-relative path and SHA-256. The actual integration runtime inputs are `docker-compose.integration.yml`, `apps/api/src/server.mjs`, `apps/worker/src/worker.mjs`, `src/extensions/v1-default-runtime.json`, `.herdr/state/integration-trust-roots-r9.json`, and H's `scripts/v1-ui-management-fixture.mjs`. The production deployment inputs are `docker-compose.production.yml`, `deployment/Dockerfile`, `deployment/Caddyfile`, `scripts/v1-ops-api.mjs`, `scripts/v1-ops-worker.mjs`, and `.herdr/state/package-fixture-r9/trust-roots.json`. Both trust roots are required; production templates alone do not prove the integration runtime. Extra config paths are rejected. `runtime_assets.envelope` must bind `.herdr/state/package-fixture-r9/ai-workbench-envelope.json` (signed workbench 1.0.1), not the older package-fixture path. H's generated private `extensions.json`, certificate, and credentials are dynamic fixture inputs: their non-secret provenance, processes, ports and resource identity belong in H/D's run report, without reading or copying private credentials into this binding.

`runtime_assets.dist` uses `{ "id": "final-web-dist", "root": "apps/web/dist", "files": { "apps/web/dist/index.html": "<sha256>", "apps/web/dist/assets/<actual-js>": "<sha256>", "...all-other-files": "<sha256>" } }`. `verifyRuntimeAssets()` independently walks the real `apps/web/dist` tree, requires a file for every discovered entry and no extra declared entry, then hashes every file. An unchanged HTML with changed JS fails. Optional `runtime_assets.native_app` has the same `root/files` form for `apps/desktop/src-tauri/target/debug/bundle/macos/DGOS.app`, including the `Contents/MacOS/dgos-desktop` executable and every real bundle file. It is a binding extension for F's native manifest, not a substitute for F's actual run.

Paths are confined to fixed config/envelope roots or independently walked dist/native roots; resolved files must stay inside this repository. The runner checks binding files before group execution and after all groups. `verifyCandidateFiles()` independently repeats the same file checks during `--summarize`, so a manifest's self-reported file list alone cannot cover an omitted asset. All groups still require identical runtime binding objects and the existing source/build fingerprint. The final complete binding file is generated by Lead after freeze and supplied to the r12 command; this revision does not write a premature candidate manifest.
