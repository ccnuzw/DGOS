## Implementation facts

1. Sole public deployment lookup is `GET /api/v1/apps/:appId/deployment`, requiring `app.catalog.read`, deriving subject from auth, returning `appId/state/versionNumber/dataRetained/activeRelease`. Missing subject record is 404; retained uninstalled record has `activeRelease: null`. Removed `/apps/installations` route and list service/repository methods. D can use `versionNumber` for update/uninstall `baseVersion`.
2. Migration declares bounded signed JSON top-level moves. Duplicate sources/destinations, source-destination overlap, self moves, unknown fields, and prototype keys reject before data write. Journal stores source and target package digests plus before and after data digests. Recovery checks backup and current data hashes and both package digests; a different release with the same dataVersion cannot commit a pending migration. Legacy prepared rows without package digests are marked rolled_back in 0041; historical 0037 bytes/checksum remain unchanged.
3. Launch binds subject, session, app, instance, active digest and expiry. Static ticket now also requires current authenticated subject/session; bridge rechecks session, current deployment digest, signed release manifest `permissions` intersection `capabilityAllowlist`, catalog state and injected authorization before handler. A bridge receipt binds subject/session/app/instance/requestId/capability/inputDigest/packageDigest. Receipt is private disk state under package root; PostgreSQL advisory lock serializes bridge calls for the same subject/app. Completed same-input replay returns stored result; changed input conflicts. Prepared/failed receipt returns `upstream_outcome_unknown` rather than invoking again. API process restart invalidates the transient launch instance, so a newly authenticated instance cannot replay an old instance receipt.
4. Official AI Workbench manifest uses the seven public SDK names (`dgos.model.list/resolve`, `dgos.aiTask.submit/get/events/cancel`, `dgos.artifact.read`) in both declaration arrays. Package UI selects a text model, resolves it, submits a task with target/intent/input/options, polls task event cursor, reads result and artifacts, and offers cancel/refresh. Event batches are bridge request/response over the version 1 schema; no direct iframe SSE connection or authenticated API access. The sandbox blocks form submission, so the Run command uses a button click. Operator supplied Ed25519 key remains required for signed bundle generation.
