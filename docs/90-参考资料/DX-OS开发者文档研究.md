# DX OS 开发者文档研究

## 1. 资料定位

本文记录对 DX OS 开发者中心的研究结论，作为 DGOS 产品和架构设计输入。DX OS 的协议名、字段名、Bridge、接口路径和实现方式不属于 DGOS 公共契约；DGOS 只吸收其边界划分、生命周期、权限模型和开发者体验思路。

研究入口：`https://dx-os.com/?page=developer`。由于公网域名在当前环境不可直接解析，本轮通过本机运行中的开发者中心界面和已缓存的开发者文档摘要核对，来源版本显示为 `2026.09.17-3`，最低系统版本显示为 `0.3.9`。本地证据摘要见[DX-OS 官网开发者中心摘要](DX-OS官网开发者中心摘要.md)。

本轮重新读取的本地研究输入为：

- `reference/完整开发规范.md`：APP 包、运行时上下文、项目/缓存边界、AI 任务、协作和特权 APP 总规范。
- `reference/DX OS Skill 开发规范.md`：Skill 依赖、包级/子 Skill 身份、工具清单和调用约束。
- `reference/DX OS MCP 开发规范.md`：bundled MCP、秘密、连接、工具发现、stdio 运行和项目文件数据流。
- `reference/Canvas Agent 开发规范.md`：系统 Agent Runtime、Canvas Agent Adapter、节点声明、统一执行器和模板。
- `reference/无限画布插件与节点 SDK.md`：Canvas 节点/插件交付、端口、状态、工作流模板和扩展隔离。

这些文件是研究样本，不是 DGOS 的兼容规范。下文把它们共同表达的边界转译为 DGOS 设计输入；DX OS 的文件名、字段名、API 名和协议版本只保留在来源说明中。

## 2. 观察到的设计模型

### 2.1 开发者面对的是平台契约

DX OS 将普通 APP、Canvas Agent、APP + Skill、APP + MCP 分成可发现的开发类型。每种类型都有清单、入口、依赖、权限和宿主能力边界。应用不是直接操作宿主内部 API，而是通过公开 Bridge 请求系统能力。

这说明开发者中心承担的是“能力契约入口”，而不只是代码示例页。开发者需要在安装前知道：应用能做什么、依赖什么、会产生什么副作用、最低运行时是什么、数据如何迁移，以及失败时系统如何恢复。

### 2.2 应用包和运行数据分离

应用包包含入口和静态资源，项目数据、用户设置、MCP 配置、临时文件和缓存由宿主管理。安装包目录不是运行时数据目录；更新应用代码不能清空项目数据。清单中的版本、build、发布渠道和 dataVersion 共同决定兼容与迁移。

### 2.3 运行时上下文由系统推送

应用需要响应主题、语言、文字方向、显示倍率、色彩方案和生命周期变化，并在启动时主动读取当前上下文。窗口、后台驻留和恢复是宿主职责，应用不能通过重复缩放或覆盖宿主主题来规避系统规则。

### 2.4 能力调用必须经过边界

应用运行在受限容器中，不能读取宿主父窗口属性，也不能直接访问内部 API、密钥、供应商 endpoint 或轮询地址。外部网络、文件导出、项目读写、实时协作和 AI 任务都要使用公开能力并受权限控制。

### 2.5 AI 以统一任务和产物建模

应用先读取模型/目标目录，再根据 intent 和输入数量完成能力握手，之后以稳定 requestId 提交异步任务。宿主 taskId 与供应商任务 ID 分离；查询、事件、取消和产物读取分别建模。动态参数通过 schema 返回，供应商专有字段不进入公共任务协议。

### 2.6 扩展有声明、隔离和提交边界

Skill、MCP 和 Agent 工具需要在清单中声明依赖、输入 schema、权限、风险和副作用。未知安装脚本不能在安装阶段自动执行。长任务由任务服务追踪；Agent 产物应先进入受控工作区，经过校验后才提交到正式项目或 Artifact。

### 2.7 协作项目不是普通项目的隐式升级

协作项目有独立的成员、房间、版本和 ACL。文档更新带 baseVersion，冲突显式返回，实时连接与项目写入分开。普通单用户项目不能因为被某个应用打开就自动变成协作项目。

### 2.8 Canvas Agent 是声明驱动的适配层

开发者中心把 Canvas Agent 视为系统 Agent Runtime、应用声明、节点适配器和统一执行器的组合。节点需要声明可发现的身份、语义角色、能力版本、输入参数和可接受的画布输入；Agent 通过已注册的动作目录选择节点或工作流。手动点击运行和 Agent 触发运行进入同一个 executor，避免两套执行语义造成结果不一致。

节点状态由宿主统一管理，至少区分 idle、running、ready、error、cancel、disabled 和 missing。第三方扩展只提供声明、配置和执行适配，不向主画布注入宿主框架组件、HTML 或 CSS。缺少节点依赖时，已有画布仍可打开并显示可解释的 missing 状态，恢复依赖后再重新绑定。

### 2.9 Skill 是可审查的能力包

Skill 依赖在应用清单中声明，工具入口还需要输入 schema、权限、风险和副作用。Skill 包身份与包内子 Skill 身份分离；展示名可改，稳定调用 ID 不随改名变化。在线来源先解析和预览，再由用户确认安装与授权；输入 `/技能名` 不能绕过安装、启用或权限状态。

### 2.10 MCP 由配置、秘密、连接和工具发现四个边界组成

MCP 的配置可以随 APP 打包，也可以作为外部或系统服务单独安装。包内声明只描述服务、命令、参数、工作目录和依赖关系；真实密钥、Headers、启用状态和用户覆盖值由宿主管理。无密钥且安装后可运行的内置服务可以申请自动启动；需要凭据的服务必须停在待配置状态。

连接状态不能由启用开关推断。工具目录只接受已安装、已启用、已连接并通过权限检查的 server/tool 组合；APP 或 Agent 不能传入任意服务器和工具名。MCP 运行在宿主 MCP Runtime，而不是 APP iframe。普通前台调用在页面关闭后不保证返回结果，持久执行必须进入独立 Task/Run 协议并支持查询、取消和恢复。

### 2.11 MCP 与项目文件采用最小字段数据流

MCP 不因被应用声明就获得项目目录、登录 Cookie、绝对路径或用户身份。应用先通过项目能力读取最小必要字段，再将脱敏后的参数传给 MCP，校验返回结果后再通过项目能力写回。大文件使用受控 Artifact 或项目文件引用，不能塞入 Base64、工具参数或普通文本结果。

### 2.12 五份本地规范进一步暴露的架构约束

1. **静态应用优先，但服务能力归宿主管理**：普通 APP 以无需构建即可运行的静态入口交付；需要 MCP 服务代码时，服务仍由宿主运行时托管。DGOS 可以采用同样的静态优先策略，但不能把页面运行等同于可自行启动进程、安装依赖或写入安装包目录。
2. **应用隔离必须有等价的安全保证**：研究样本使用 opaque-origin iframe，并禁止读取父窗口、直接下载、任意弹窗、Cookie WebSocket 和第三方完整站点嵌入。DGOS 不复制 iframe 作为公共协议，但 V1 必须提供等价的应用隔离、外链/导出代理和网络能力边界。
3. **特权应用是受审批准入，不是普通应用的隐藏开关**：需要系统内部能力的应用必须由管理员安装，声明精确的方法/路径白名单，并接受独立审计；不能通过修改应用 ID 冒充系统应用。
4. **AI 目标先握手再运行**：Target 可能代表模型、应用或工作流。应用先读取目标目录，再按 intent、参考素材数量和动态 descriptor schema 确认可用性及参数，最后提交宿主任务。供应商专有字段留在参数区，不能扩散到 DGOS 公共任务结构。
5. **协作房间不是普通实时连接的别名**：创建、加入、离开、关闭是不同动作；创建成功后加入失败必须清理空房间；实例要有稳定 clientId。DGOS 未来实现协作时应采用独立 realtime 协议，不能把 Cookie WebSocket 或页面生命周期当作项目一致性机制。
6. **Canvas Agent 的声明是节点交付的一部分**：节点至少需要稳定类型/版本、`semanticRoles`、`capabilityVersion`、输入输出端口、可接受的画布输入、动作和执行器绑定。宿主统一渲染节点和状态，手动运行与 Agent 运行进入同一个 executor。

## 3. 可吸收为 DGOS 原则

| DX OS 观察 | DGOS 设计原则 | 进入版本 |
| --- | --- | --- |
| 应用包、清单、入口和资源校验 | DGOS 定义自有 `dgos-app/v1` 设计基线，安装前校验包、入口、资源、权限和依赖 | V1 |
| 系统上下文和窗口生命周期 | 提供 `dgos.system` 上下文与窗口事件；桌面端和 HTTPS Web 共用应用契约 | V1 |
| 项目数据与应用包分离 | 应用私有数据、项目数据、Artifact、缓存和临时文件分目录、分所有权 | V1/V2 |
| Bridge 受限调用 | 通过 DGOS SDK/capability broker 调用系统能力，服务端再次校验权限 | V1 |
| 统一 AI Task | `dgos.model.*`、`dgos.aiTask.*`、`dgos.artifact.*` 统一模型、任务和产物语义 | V1/V3 |
| Agent/Skill/MCP 清单 | 扩展声明 schema、权限、风险和副作用，执行过程可审计 | V1/V4/V5 |
| 协作项目独立建模 | 单用户项目、协作项目、实时房间和成员 ACL 分开冻结 | V6 |
| 发布不可覆盖、健康检查和回滚 | release/version/build 唯一，安装失败只回滚代码和注册状态，不删除用户数据 | V1 |
| Canvas Agent 声明与统一执行器 | 节点声明语义角色、输入和能力版本；手动运行与 Agent 运行共用 executor；宿主统一渲染状态 | V3/V5 |
| Skill 包/子 Skill 分层身份 | 包、子 Skill、版本、启用和授权状态分开保存；在线导入先预览再安装 | V1/V4 |
| MCP 配置/秘密/连接/工具发现分离 | bundled、system、external 来源采用不同安装和凭据流程；工具绑定只能引用已声明组合 | V1/V4 |
| MCP 最小字段文件流 | 应用负责项目读写和权限；MCP 只处理必要字段或 Artifact 引用 | V2/V4 |

## 4. DGOS 不直接复用的内容

- 不使用 `dx-app.json`、`dx-app/v2`、`dx-ai-task/v2` 或 DX OS 的私有协议版本。
- 不使用 `window.dx.invoke`、DX OS Bridge、DX OS 的内部 `/api/*` 路径或旧项目私有 API。
- 不把 DX OS 的供应商名称、模型 endpoint、Authorization、轮询 URL 或下载 URL 写入 DGOS 公共接口。
- 不把 DX OS 的 iframe、浏览器缓存、具体进程拓扑或技术栈当作 DGOS 的实现前提。
- 不把 DX OS 的协作接口、Canvas 节点协议或扩展包格式直接当成 DGOS 的兼容目标。
- 不把 DX OS 的具体清单文件、工具绑定字段、Bridge 方法名或 MCP 配置文件名复制为 DGOS 公共 schema；这些名称只在本研究的来源说明和对照表中出现。
- 不把 DX OS 的具体超时、请求体上限、iframe 行为或进程拓扑当作 DGOS 的永久数值约束；DGOS 需要自行定义版本化配置和能力协商。

## 5. 对 DGOS 定位的影响

DGOS 应明确定位为面向 AI 应用和创作工具的独立桌面与 Web 应用平台。它提供类似操作系统的应用承载、窗口管理、权限、项目、任务、Artifact、扩展运行时和开发者中心；无限画布、文件、天气、对话智能体、Skill 管理和 MCP 管理都是可安装、可启动、可升级的 DGOS 应用。

DGOS 的平台价值在于统一边界和生命周期：应用只依赖公开 DGOS 契约，系统负责安装、运行、权限、数据所有权、任务追踪和失败恢复。具体应用可以快速变化，但不能绕过平台边界读取其他应用数据或系统秘密。

## 6. 对版本路线的影响

1. V1 必须先冻结 DGOS manifest、SDK/capability broker、系统上下文、窗口生命周期、权限、安装更新回滚和最小应用目录。
2. V2 冻结项目作用域、应用私有数据目录、路径安全和项目版本写入，再承载无限画布基础。
3. V3 将统一 AI Task 接入画布工作流，保持任务 ID、运行快照和 Artifact 引用闭包。
4. V4 冻结资产授权、表格、Agent Workspace 和供应商能力握手。
5. V5 冻结插件/模板清单、扩展隔离和 3D 导演台的 Artifact 回写。
6. V6 再冻结协作房间、成员 ACL、冲突合并、市场审核和跨端恢复。

## 7. 待冻结事项

以下内容已形成设计方向，但仍需 DGOS 自身 ADR、字段 schema 和实现证据后才成为公共契约：

- `dgos-app/v1` 的最终 manifest 版本和签名格式。
- `window.dgos` SDK、IPC/HTTP 传输方式及事件订阅协议。
- 普通应用、受信应用、系统应用的信任级别与安装审批流程。
- `permissions` 与 `capabilityAllowlist` 的公开枚举，以及权限请求的交互和审计字段。
- 项目作用域、应用私有数据目录、迁移/回滚和卸载数据保留策略的字段级 schema。
- Model/Target/Provider、动态参数 schema、AI Task 幂等和 Artifact 访问安全边界。
- Agent Run、Agent Workspace、Artifact validate/commit 和子 Agent 限制。
- 桌面发行版与 HTTPS Web 入口的相同点、差异点和能力降级规则。
- 扩展声明中 App、Skill、MCP、Agent Tool 和 Canvas Node 的身份、来源、信任级别与版本快照字段。
- DGOS 内置 MCP 是否允许自动启动、凭据缺失时的 UI 状态、任务恢复协议和 Artifact 传递上限。
- Canvas Agent 的语义角色、动作目录、统一 executor、缺失节点恢复和宿主渲染协议。
