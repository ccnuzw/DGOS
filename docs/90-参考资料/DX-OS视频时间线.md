## 不能从视频直接确认的事项

- 实际 Bridge action、权限名、错误码、数据物理结构和发布审核结果。
- 真实模型供应商、计费、任务重试和网络失败时的最终一致性。
- 画布数据是否由 DX OS 宿主 `project.*` 持久化，需以 DX OS 外部开发者资料和后续代码/截图确认；这不构成 DGOS 的数据契约。

### 媒体与证据限制

- 两集视频均为带中英烧录字幕的 WebM，音频为独立 AAC MP4；音视频时长分别约 22:00 和 36:44，轨道时长匹配。
- 当前环境没有本地语音转录工具，本轮使用烧录字幕、画面和控件文字复核，未把音频内容冒充为逐字稿。
- 视频没有直接证明 DX OS `window.dx` 的具体 action、权限名、错误码、秘密存储实现、任务计费或服务端持久化；这些仍以 DX OS 外部开发者资料和后续本地软件截图为准，不能作为 DGOS 运行时证据。

### 第三轮交叉复核

本轮将视频/烧录字幕与独立音频文件重新对照，并与成熟软件截图、DX OS 外部开发者中心研究摘要和旧项目能力表逐项比对。交叉结果是：视频确认了画布节点、历史入口、任务回写、ComfyUI/插件和 Agent 的产品链路；截图补足了选中集右键命令、资产库筛选、MCP/Skill 管理表单；DX OS 外部资料用于观察 `window.dx`、`project.*`、`ai.task.*`、manifest 权限和公开 Canvas SDK 的产品边界，但不约束 DGOS 的协议或实现；旧项目仅保留节点/资产/工作流交互参考。未发现需要把 V1 无限画布或 3D 导演台前置的证据，因此维持“V1 线性任务 + 平台最小支撑、V2 分阶段创作工作台”的范围决策。
