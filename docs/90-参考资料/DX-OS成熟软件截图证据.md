## 交互与视觉基线

- 参考样本采用苹果风格桌面：顶部系统栏、半透明浅色窗口、圆角窗口容器、左侧设置导航、底部 Dock 和可叠放的窗口/页签；DGOS 自行定义自己的桌面视觉规范。
- 系统设置是可独立聚焦、最大化并与其他窗口并存的模块化 APP；DGOS 的页面不能假设只有一个全屏窗口。
- 窗口内的列表项使用大面积可点击行、右侧状态/控件和分段控件；设置页面按“分类导航 → 页面标题/说明 → 分组设置”组织。
- 系统缩放存在 75%、100%、125%、150%、175% 档位；后续截图验收应覆盖这些倍率，不能只验证默认 100%。
- 视觉风格可以作为 DGOS 外壳参考，但颜色、图标和品牌资产仍需以成熟软件截图与后续 DGOS 截图共同校准。

## 第二批新增边界

- 应用生命周期至少区分：获取/安装、打开、更新、卸载、删除应用数据。
- 权限至少使用 `allow / ask / deny` 三态；APP 清单声明是请求，不是最终授权。
- 文件、MCP、Skill 和 AI 生成能力都必须进入统一权限治理，不能通过另一个入口绕过用户拒绝。
- 任务缓存、临时产物、SQLite 诊断日志与项目数据分离；清理操作需要显示影响范围和可恢复性。
- “删除数据”“删除文件”“清理缓存”“卸载 APP”是不同操作，不能共用一个无差别删除接口。

### 本批产品推断

- 画布是“项目列表 → 画布工作区 → 节点编排”的三级结构；画布列表功能不等于画布编辑器。
- 节点至少分为输入节点（文本、上传文件、生成输入）、处理节点（LLM、生成卡片）和结果/资源节点；基础节点注册协议在 V2 冻结，执行节点协议在 V3 冻结。
- 生成卡片和 LLM 节点都应复用 `ai.models.resolve` 的动态 schema 与 `ai.task.*` 的异步状态，而不是在节点内实现第二套执行器。
- 节点的模板库、扩展、分享、Agent 和云端入口属于 V3–V6 扩展面；它们不能反向扩大 V1 的任务工作区范围。

### 本批不可确认

- 截图不能证明点阵背景、小地图、缩放/平移手势的具体实现库、坐标系或性能策略。
- 截图不能证明 DX OS 的“同步”“分享”“云端画布”是否使用 `project.*`、实时协作协议或专有云服务；这些观察不定义 DGOS 的项目或协作协议。
- 截图不能证明生成卡片和 LLM 节点的字段 schema、模型能力过滤、任务幂等、文件上传协议或 Skill 授权时机。
- 截图不能证明删除浮动工具栏是软删除、节点删除还是同时清理引用；必须由后续协议和验收用例确认。

### 对 DGOS 的范围结论

本批新增的画布列表、点阵画布、节点菜单、节点选中态和连接入口登记为 V2 规格细化；生成卡片和 LLM 节点登记为 V3 规格细化。V1 仍只交付线性 AI 任务工作区、模型配置、状态追踪和 artifact 预览。

### 本批产品推断

- 画布能力应分阶段交付：V2 先完成项目、画布和节点框架；V3 接入生成/LLM 等可执行节点；V4 再加入多维表格、上下文 Agent 和供应商节点；V5 将 3D 导演台作为独立专项，在场景、资产、动画和导出契约成熟后排期。
- 3D 导演台内部的相机、角色/模型、关键帧和导出状态需要作为独立领域数据管理，再以稳定引用与画布项目关联。
- 多节点同屏要求画布布局和导航能力处理不同卡片尺寸、分组区域、连接路径和小地图密度，不能仅以单一节点截图作为验收依据。
- Agent 面板的自动/手动模式、建议任务、素材引用和 Skill 调用应形成明确的确认、权限与审计规则；当前截图只证明界面入口存在。

### 本批不可确认

- 截图不能证明多维表格的公式、类型系统、筛选/排序、导入导出或并发编辑能力。
- 截图不能证明 3D 场景文件格式、渲染引擎、资产库协议、关键帧插值、自动记录持久化或导出结果语义。
- 截图不能证明 Agent 的自动模式是否能直接执行写操作、如何确认副作用，或其与画布节点的双向修改契约。
- 截图不能证明 Midjourney 协议来源、授权方式、参数兼容范围和任务回调实现。
- Image 3 显示的 HTTP 404 和 Image 5 未配置协议属于截图中的实例状态，不作为 DGOS 的预期错误码或默认设置。

### 对 DGOS 的范围结论

### 本批不可确认

- 截图和示例不能证明 DX OS 协议的服务端权限、签名、版本兼容和生产错误语义。
- 示例中的供应商路径、模型名、能力枚举、参数范围和下载地址不能直接成为 DGOS 默认值。
- DGOS 的协议签名、来源信任、版本迁移、审批和发布流程仍需后续 ADR 与实现证据冻结。
