# V1 测试策略

## 1. 测试层级

| 层级 | 目标 | 最低要求 |
| --- | --- | --- |
| 单元测试 | schema、状态转换、引用闭包和幂等计算 | 每个技术设计分支 |
| DGOS API/SDK 集成 | 权限、动作参数、错误和副作用 | 每个公开 DGOS API/SDK 入口 |
| 前端测试 | 画布、表单、加载、错误和成功反馈 | 每个主页面流程 |
| E2E | V1 首发平台与参考 APP 的十二条跨功能闭环；后续版本分别验证画布、工作流、结构化创作、3D 和插件 | `V1-E2E-01/02/03/05/07/09/10/11/12/13/14/15`；E2E-05 覆盖 SSE 与断线恢复，E2E-07 覆盖 `openai-compatible` 和协议注册表，E2E-09 覆盖动作权限/确认/长任务，E2E-10 覆盖系统上下文/设置冲突/权限边界，E2E-11–15 覆盖身份、秘密、Provider 连接、治理和额度；后续用例见[编号迁移](端到端验收/V1-端到端验收规范.md#后续版本编号迁移) |
| 发布门禁 | DGOS Runtime、包校验、回滚、权限/设置边界和外部文本模型 | `V1-RG-001` 至 `V1-RG-003` |

## 2. 每个功能的最低矩阵

- 正常主流程；必填、格式、上下界和协议版本。
- 未授权、权限不足、资源不存在、协议不兼容和依赖停用。
- 重复提交、任务取消、保存冲突、升级回滚和错误恢复。
- 日志、错误和响应不泄露 API Key、token 或完整敏感素材。
- 前端加载、空态、失败态、成功反馈和可继续操作入口。
- 系统设置相关 E2E 必须覆盖系统上下文注入、设置域版本冲突、代理重启标记、语言/地区与项目内容分离，以及 `deny` 优先和 APP 启动权限与能力授权分离；验证不得把页面隐藏按钮当作权限边界。

## 3. 真实依赖原则

本地 mock 只证明 UI/适配器契约；DGOS Runtime 的安装、权限和任务闭环必须在 V1 对应门禁环境执行，`dgos.project.*`、工作流、资产和插件隔离按 V2–V5 用例执行。外部模型可以使用受控替身，但必须另外记录真实依赖验证结果。静态检查不构成测试通过。
