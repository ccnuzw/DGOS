# V1 MVP 演示脚本

工作包：WP-W4-02  
状态：准备稿，须待 WP-W4-01 最终集成验证通过并锁定最终候选后录制  
时长目标：8–12 分钟  
入口：DGOS Web；Native 仅在对应独立 smoke 验收通过后加入单独片段

## 录制前门禁

- 记录最终候选 commit、Web build 标识、manifest/migration 版本与环境；演示期间不切换代码或数据库。
- 使用隔离演示数据库、专用管理员账号和受控 Provider。不得出现真实凭据、密钥、用户个人数据或生产数据。
- 先确认 API/Web 健康、Provider 验证成功、模型目录可刷新、Artifact 可读，且本次演示不会影响其他测试主体。
- 记录浏览器/操作系统、屏幕尺寸、区域/语言、依赖模式（真实 Provider 或受控 fixture）和录制日期。
- 开始与结束各展示一次候选 build 与环境标识。所有失败或重试应保留在证据记录中，不剪辑成“从未发生”。
- W4-01 未通过时只可录制内部排练素材，不得标记为最终演示，也不得用旧证据填充最终结论。

## 镜头流程

| 段落 | 操作 | 屏幕应证明 | 旁白重点 |
| --- | --- | --- | --- |
| 1. 候选与环境 | 展示版本/build、环境和验证批次标识 | 录制绑定到唯一最终候选 | 本视频对应具体候选，不代表未执行的 FR 或发布门禁 |
| 2. 管理员会话 | 登录 DGOS，展示已认证控制台 | 管理员会话建立 | 使用隔离演示主体；不展示密码或 Cookie |
| 3. Provider 验证 | 打开 Provider，执行连接验证 | 成功/失败状态与脱敏原因 | 上游是本次真实配置或受控 fixture，按实际情况说明 |
| 4. 模型目录 | 显式刷新目录，启用一个文本模型 | 目录刷新状态、模型能力和启用状态 | 不暗示图像/视频/音频模型已开放 |
| 5. 工作台启动 | 打开已安装的 DGOS AI Workbench | 应用入口、运行状态与当前版本 | 区分 Web iframe 与 Native 窗口；仅展示已验证宿主 |
| 6. 提交任务 | 输入不含敏感信息的固定提示并提交一次 | 返回 taskId、queued/running 状态 | 同一操作只提交一次；记录上游请求计数 |
| 7. SSE 与结果 | 展示文本增量和终态 | 有序增量、单一终态、结果文本 | 若当前路径不是 SSE，停止并标为失败，不以静态结果代替 |
| 8. Artifact | 在工作台读取产物 | Artifact 内容与 taskId 对应 | 说明 Artifact 是服务端持久化结果 |
| 9. 刷新恢复 | 刷新页面/重新打开 Workbench，恢复同一 taskId | 恢复任务、事件或 Artifact；提交数不增加 | 展示原 taskId 和上游调用计数，证明未重复提交 |
| 10. 平台支撑片段 | 打开应用目录，展示来源/权限/安装健康；可选展示助手确认 | 目录状态与授权确认入口 | 仅作为支撑片段，FR-002/009 完整 AC 仍以其独立验收证据为准 |
| 11. 失败证据 | 展示已验证失败分支的报告/测试结果，不伪造现场失败 | 明确关联 case ID、命令和批次 | 权限拒绝、版本冲突、健康失败回滚引用真实证据；视频不代替 E2E |
| 12. 收尾 | 再展示候选标识与证据索引 | build、日期、manifest 可追溯 | 明确局部验证、未完成范围和外部依赖限制 |

## 录制交付检查

- 原始视频保留于受控 evidence 目录，发布副本另行派生；记录两者 hash 与派生工具版本。
- 视频/截图使用与报告相同的 runId，manifest 记录源文件路径、SHA-256、大小、日期和候选身份。
- 遮蔽账号标识、凭据输入、地址栏中的敏感参数和通知内容；遮蔽不得覆盖状态、错误或验证结果。
- 若任何门禁未通过、环境变更、上游依赖不可用或恢复重复提交，视频标注失败/排练，不作为通过演示。
