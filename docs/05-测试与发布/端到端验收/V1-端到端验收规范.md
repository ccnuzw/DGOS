# V1 端到端验收规范

没有可复现执行记录时，不得仅根据视频、文档或旧项目标记 E2E 通过。所有用例必须在 DGOS 自有 Runtime 和入口执行，并记录环境、包版本、manifest/API/SDK schema 版本和证据。

## E2E 判定标准

- 使用公开 DGOS APP/SDK/API 入口，不直接调用内部函数或 DX OS/旧项目私有 API。
- 验证最终业务结果：项目结构、任务终态、产物引用、安装回滚或插件状态。
- 外部模型可使用受控测试模型；V1 首发要求 DGOS `dgos.aiTask.*` 任务闭环，`dgos.project.*` 画布和后续创作门禁按 V2–V5 分阶段执行。

## 治理用例机器契约与可观察事实

| 用例 | 必须调用的公开 operation | 必须观察的事实 | 失败时必须保持不变 |
| --- | --- | --- | --- |
| `V1-E2E-11` | `bootstrapAdmin`、`adminLogin`、`getAdminSession`、`renewAdminSession`、`revokeAdminSession` | `principalId`、`sessionId`、`sessionVersion`、状态、`requestId`、撤销审计 | 错误认证不创建 Session；撤销后后续读写被拒绝 |
| `V1-E2E-12` | `createApiKey`、`listApiKeys`、`rotateApiKey`、`revokeApiKey` | `keyId`、prefix、scope、rotationGroup、一次性 secret 展示计数、拒绝结果、脱敏日志扫描 | scope 越权不调用目标；轮换失败不撤销旧 Key；日志不含 bearer |
| `V1-E2E-13` | `createProviderAccount`、`bindProviderAccount`、`startProviderConnectionTest`、`getProviderConnectionTest`、`cancelProviderConnectionTest` | account/test 状态、版本、reasonCode、延迟、上游调用次数、目录版本和 AI Task 数量 | 禁止网段不产生网络请求；测试失败不刷新目录、不创建 AI Task |
| `V1-E2E-14` | `queryAuditEvents`、`getGovernancePolicy`、`updateGovernancePolicy`、`executeRetentionSweep`、`getRetentionSweep` | `eventId`、`requestId`、policyVersion、jobId、checkpoint、跳过/失败计数、outbox 状态 | 冲突或 Audit 不可用不产生无审计成功；引用保护不误删 |
| `V1-E2E-15` | `preflightQuota`、`reserveQuota`、`settleUsage`、`queryUsage`、`updateQuotaPolicy` | decision、policyVersion、reservationId、taskId、attemptId、usageEventId、settlement 状态和汇总版本 | 硬额度不足不发 Provider 请求；重放不重复结算；越权查询不泄露用量 |

## V1-E2E-01 桌面到工作区

关联 `V1-FR-001/AC01/AC03`。入口为 macOS DGOS 宿主与 Docker Web 启动台；DGOS 壳层、安装记录和工作区恢复必须真实，外部替身不适用。

Given 同一主体有已安装平台控制面和 AI 工作台，且存在最近工作区。

When 启动 DGOS、打开应用、关闭并重新进入。

Then 窗口和可见应用与安装记录一致，最近工作区只恢复该主体有权的内容；未授权应用不得启动，不创建窗口或改写工作区。最终核对活动安装版本、窗口/工作区状态及拒绝审计。

## V1-E2E-02 APP 审核目录生命周期与失败回滚

关联 `V1-FR-002/AC01–AC03`。入口为开发者中心和普通用户应用目录；审核准入、来源/卸载策略判定、安装状态、健康检查和回滚必须由 DGOS 服务真实执行，允许使用受控无效包、审核拒绝和失败健康检查作为输入夹具；不允许替身直接写活动版本或绕过目录服务。

Given 目录包含官方包、管理员批准的开发者包、待审核包、可卸载预装应用和受保护预装应用；另有一个可启动旧版本和用户设置。

When 普通用户尝试安装/更新/卸载官方与批准包、发现待审核包并尝试卸载两种预装应用；开发者通过有权限的测试流程安装待审核包；再对一个合规升级尝试注入健康检查失败。

Then 官方/批准包可按策略安装、更新和卸载；待审核包不进入普通用户可安装目录，但开发者测试安装不等于审核通过；可卸载预装应用允许卸载，受保护预装应用在副作用前拒绝并保留活动版本/数据并写审计。健康检查失败恢复旧活动版本并记录失败阶段；用户设置和已提交产物不变，不留下半活动版本或重复发布记录。最终核对目录审核状态、安装记录、活动版本、数据/Artifact 引用和拒绝审计。

## V1-E2E-03 Agent 工具权限与超时

关联 `V1-FR-003/AC01/AC02`。入口为官方 Skill/MCP 管理应用与 Agent 工具入口；DGOS Permission、Extension Runtime、任务状态和审计必须真实，可用受控超时工具替代外部 MCP 服务。

Given 工具已登记且主体存在允许与拒绝两种授权样本。

When 分别调用合法 schema、未授权调用和超时工具，并查询/取消运行。

Then 合法调用有 requestId 和可查询终态；拒绝在外部调用前发生；超时/取消可查询且不会重复启动工具，秘密不进入响应或审计。

## V1-E2E-05 线性文本 AI 任务

关联 `V1-FR-005/AC01/AC02/AC08` 与 `V1-FR-007/AC01/AC07`。入口为 DGOS AI 工作台；Provider 配置、任务/事件/产物服务及 `openai-compatible` Adapter 必须真实。允许可控兼容模型和断线夹具；发布门禁另需至少一条真实 Provider 调用链。

Given 已验证且启用的文本模型和可读任务权限。

When 提交文本、读取 SSE 增量、断线后以游标恢复并查询同一 taskId。

Then 增量顺序、唯一终态和 artifact 内容一致，工作台展示结果；重复提交不生成第二个任务或上游请求，失败/取消无成功产物，响应/事件/日志无凭据。核对任务、事件、产物和上游调用次数。

## V1-E2E-07 Provider 与模型策略

关联 `V1-FR-007/AC01/AC02/AC04/AC05/AC07/AC08`。入口为系统设置和 Provider 页面；DGOS 配置、秘密、协议注册表、目录与策略服务必须真实，外部兼容端点可用受控 fixture。

Given 管理员有配置权限且存在已验证 Provider 与可选择模型。

When 新建并验证 `openai-compatible` 配置，显式刷新目录、分类/启用文本模型，再注入验证失败。

Then 文本选择器只显示有效启用模型，媒体入口未开放；验证与刷新分离。更新验证失败后 Provider 进入 disabled/error 并立即从新任务选择器移除；既有任务继续以原 taskId 查询和收敛。失败不得清除秘密引用、目录和策略历史，不得回显秘密或触发新 AI 任务。单独的目录刷新失败只标记目录 stale/unavailable，不误判为验证成功或隐式启用模型。最终核对 Provider 状态、模型选择器结果、活动任务、目录版本和审计。

## V1-E2E-09 助手动作执行

关联 `V1-FR-009/AC01–AC05`。入口为官方助手；Action Registry、Capability Broker、Action Run 和审计必须真实，可替换外部 Provider 为不可用状态及受控长任务 handler。

Given 已登记导航、需确认副作用和不可用动作。

When 无 Provider 执行快捷指令，再尝试未授权动作、取消确认，并确认一个长任务。

Then 快捷指令可打开有权应用；公开且已授权的低风险设置/应用配置动作更新目标状态；关键动作只有确认并重新鉴权后执行。未授权/取消/过期确认/版本冲突不调用 handler且目标配置不变；长任务可查询/取消且仅执行一次，审计不含秘密。最终核对设置/应用配置版本、handler 调用次数、运行终态和审计记录。

## V1-E2E-10 设置与运行时上下文

关联 `V1-FR-001/AC04–AC08`。入口为系统设置及 macOS/Docker Web 应用；Settings、Context Snapshot、Permission Broker 必须真实，允许版本冲突、代理待重启与拒绝策略夹具。

Given 应用已启动并订阅上下文。

When 修改外观、语言/地区、网格、代理与权限，再提交旧 `baseVersion` 和被拒绝的能力请求。

Then 递增 contextVersion 与脱敏快照在两宿主语义一致；冲突不覆盖新值，拒绝先于副作用，界面语言不改项目内容，APP 启动权限不自动授予能力。核对设置版本、权限审计和目标资源未变化。

## V1-E2E-11 管理员认证与会话撤销

关联 `V1-FR-010/AC01–AC04`。入口为管理员认证与会话管理；Identity、Session 和 Audit 必须真实。

Given 部署处于首次引导或存在 active 管理员主体。

When 执行登录、错误因子重试、会话续期、设备撤销和高风险操作再认证。

Then 错误不创建会话，撤销立即阻止后续请求，成功响应和审计只含脱敏主体/会话摘要。

## V1-E2E-12 API Key 生命周期

关联 `V1-FR-011/AC01–AC04`。入口为 Key 管理服务；Secret、Permission 和 Audit 必须真实。

Given 管理员拥有 Key 管理权限并请求明确 scopes。

When 创建、调用、轮换、撤销或使用已过期 Key。

Then 明文只展示一次，scope 越权和撤销/过期请求被拒绝，失败不触发目标副作用且日志无 Key。

## V1-E2E-13 Provider 账号与上游连接测试

关联 `V1-FR-012/013`。入口为 Provider 账号和连接测试；Secret、Provider Adapter 和出站策略必须真实。

Given active Provider account、已发布 Adapter 和有效 ProviderConfig。

When 执行成功探测、鉴权失败、超时、禁止网段和取消测试。

Then 返回脱敏 test 终态和稳定错误分类，不刷新模型目录、不创建 AI Task、不泄露上游响应。

## V1-E2E-14 审计与管理员系统治理

关联 `V1-FR-014/AC01–AC05`。入口为治理和审计查询；Audit Store、策略服务和清理任务必须真实。

Given 管理员提交带 baseVersion 的高风险策略变更或保留清理预览。

When 执行成功、版本冲突、审计不可用和清理失败场景。

Then 成功变更可关联 eventId/requestId，冲突不覆盖，必须审计的写入 fail closed 或落可恢复 outbox，清理可按 checkpoint 重试。

## V1-E2E-15 用量与额度

关联 `V1-FR-015/AC01–AC05`。入口为 AI Task 提交和用量/额度查询；Task、Provider、Usage/Quota 和 Audit 必须真实。

Given 当前主体、账号、模型和额度策略有效。

When 并发提交竞争剩余额度，任务成功/失败/取消并重复投递终态事件，或越权查询用量。

Then 硬额度不超发，reservation 只结算/释放一次，缺失 usage 明确标记，越权查询不泄露他人数据。

## 后续版本编号迁移

旧编号仅用于历史引用，不属于本规范的 V1 用例：`V1-E2E-04A` → 拟定 `V2-E2E-01`；`04B` → `V3-E2E-01`；`04C/08` → `V4-E2E-01/02`；`04D/06` → `V5-E2E-01/02`。正式编号和独立验收正文由对应版本门禁冻结，见[后续版本索引](../../02-产品与版本/后续版本/README.md)。

## 统一执行要求

每次执行在[验证证据](验证证据.md)登记日期、环境、代码/包版本、依赖模式、命令、结果和限制；静态协议检查不构成 E2E 通过。V1 首发门禁包含 `V1-E2E-01/02/03/05/07/09/10/11/12/13/14/15`，执行资产和当前状态以[用例矩阵](用例矩阵.md)为准。Web 入口需 Docker Compose 健康检查，桌面入口需 macOS 验证；Windows 不计入 V1 门禁。
