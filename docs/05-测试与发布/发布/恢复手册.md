# V1 备份与恢复演练

## 1. 目标

V1已有本地Compose与PG恢复子集，见[F报告](../端到端验收/报告/V1-F-整合联调报告.md)及 [r11 运维报告](../../99-历史归档/README.md)，不覆盖生产 Secret/对象引用完整灾备。RPO/RTO 需按目标部署与备份策略落实并作为发布门禁；下表待定值不构成 SLA。

| 指标 | 目标 |
| --- | --- |
| RPO | 待部署拓扑与数据保留策略冻结 |
| RTO | 待部署拓扑与恢复演练冻结 |

## 2. 备份范围

- 主数据库全量备份与连续增量/WAL 能力。
- migration 版本、扩展与必要配置。
- 应用镜像 digest、前端构建与部署配置版本。
- secret 只备份引用和恢复流程，不把明文复制进普通备份。
- 缓存不作为业务终态恢复源；故障后重建短期状态。

## 3. 演练步骤

1. 选择隔离恢复环境和已知备份时间点。
2. 记录备份标识、开始时间和操作者。
3. 暂停 API/Worker 写入并核对 pending Secret、proxy、extension 和 package intents。
4. 运行多存储备份，记录数据库 dump、包文件、ciphertext 和引用摘要 digest；root key 走独立恢复路径。
5. 在全新目标数据库和目录恢复，校验 dump/file hash、AES-GCM tag、数据库引用及 root key。
6. 保持 `restored_read_only_validation_required`，部署对应版本后执行 readiness、只读 smoke 和隔离写入测试。
7. 计算实际 RPO/RTO，记录缺失数据范围、恢复时间线和手工动作。
8. 销毁隔离环境或按证据策略保留。

## 4. 通过条件

- 实际 RPO/RTO 不超过门禁目标。
- 关键业务总账关系一致。
- 敏感数据可按安全流程恢复。
- 没有通过手工覆盖数据来“修复”验证结果。
- 发现的问题有负责人、截止时间和复验批次。
- 本地 fixture 的 observed RPO/RTO 只能作为校准输入，不能自动转为批准目标。
