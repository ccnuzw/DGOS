# DGOS 版本路线图

## 1. 文档目标

本文件维护版本顺序、命名规则、跨版本边界与推进建议；功能级行为进入功能规格，框架与取舍进入架构与决策记录。

## 2. 版本命名规则

| 规则 | 说明 |
| --- | --- |
| 命名 | `V` 加连续数字；阶段可用 `V1-P1` 形式，但阶段自身必须满足进入开发门禁 |
| 编号 | `Vx-FR/NFR/RG`；跨版本延续的功能保持同一功能 ID |
| 状态 | 规划骨架 / 门禁评审中 / 活跃开发 / 验收准备 / 已发布 |

## 3. 业务术语口径

| 术语 | 口径 | 易混项 |
| --- | --- | --- |
| APP | 符合 DGOS manifest、运行时和权限规范的可安装应用包 | 不等于普通网站 |
| DGOS API | DGOS 为应用提供的版本化系统 API/SDK | 不等于 DX OS 私有 Bridge |
| Canvas 插件 | 声明节点、端口和执行器的扩展包 | 不等于普通 APP 页面 |
| AI 任务 | DGOS AI Task API 负责的图片、视频、音频、转录任务 | 不等于 Agent 后台任务 API |

## 5. 跨版本范围决策

| 事项 | 归属版本 | 说明 |
| --- | --- | --- |
| DX OS 核心桌面和系统服务 | 参考资料 | DGOS 不依赖、不嵌入、不复制其私有实现 |
| 浏览器本地存储兼容 | 归档参考 | 旧项目行为不作为新项目契约 |
| 无限画布与项目基础 | V2 | `V1-FR-004` 先交付项目文档、导航、内容节点和图编辑；执行与高级节点后置 |
| 画布生成卡片/LLM/结果节点 | V3 | 复用 V1 模型握手、权限与 AI 任务闭环；不在节点内实现第二套执行器 |
| 项目资产与生成历史 | V4 | `V1-FR-008` 依赖 V3 结果批次、artifact 引用闭包和删除语义 |
| 多维表格、画布 Agent、Midjourney/ComfyUI | V4 | 分别依赖结构化数据持久化、上下文权限审计和供应商协议适配；未满足依赖时显示禁用态 |
| Canvas 插件与模板扩展 | V5 | `V1-FR-006` 依赖稳定节点注册、隔离运行时和模板敏感数据清理 |
| 3D 导演台 | V5 专项 | 需要场景资产、相机/变换、时间线、实时预览和导出契约 |
| 应用目录准入与用户生命周期 | V1 | 官方发布和管理员批准目录包可由普通用户安装/更新/卸载；开发者应用经管理员审核后进入批准目录；预装应用逐项声明是否可卸载。未审核包只允许有权限的开发者测试安装 |
| 商店规模化运营 | V6 | V1 交付最小审核准入和批准目录生命周期；评分、收费、规模化投稿运营及商业分发进入 V6 |
| Provider 协议与厂商覆盖 | V1–V2+ | V1 冻结统一适配器、模型目录、能力 descriptor 和 `openai-compatible`；OpenAI/Grok/DeepSeek/通义等通过 preset 和 contract test 接入；Anthropic Messages、Gemini native 及特定国产协议按 Provider Pack 追加；Claude Code 走 Agent/官方应用路线 |
| 账号登录与个人数据归属 | V1/V2 | V1 提供部署管理员控制面登录、登出、续期和会话撤销；V2 才提供正式终端用户账号、跨设备身份、个人数据归属和安全回跳 |
| 组织/团队与共享开发 | V6 | 需要组织成员、角色、策略、冲突、权限回收和协作审计；范围入口见[V6 规划](后续版本/V6-规划.md) |
| 多人协作与移动端 | V6 | 需要独立冲突、权限、发布和跨端恢复门禁 |

## 6. 研发推进建议

先冻结 DGOS manifest、应用 API/SDK、安装生命周期、权限和最小系统服务，完成独立系统平台闭环；平台控制应用只交付管理闭环，唯一业务示范 APP“DGOS AI 工作台”承担真实 Provider、文本任务和流式输出的纵向验证。随后按 V2 项目基础、V3 画布工作流、V4 结构化创作、V5 3D/插件、V6 协作生态逐级通过门禁。每一版只允许消费已稳定的上游契约，任何跨版本前置都必须记录到版本门禁和决策记录。

### 6.1 版本进入与退出门禁

| 版本 | 进入条件 | 退出条件 | 明确不作为本版完成条件 |
| --- | --- | --- | --- |
| V1 | DGOS manifest、应用 API/SDK、安装包格式、身份/权限边界、Action Registry、Provider Adapter、Secret、Audit、Quota 和系统服务最小集合已冻结 | `V1-E2E-01/02/03/05/07/09/10/11/12/13/14/15` 通过；桌面/Web 可发现、安装、启动、更新/回滚和卸载合规应用；DGOS AI 工作台完成 Provider 验证、模型目录、真实文本 AI 任务、助手安全执行和治理闭环 | 项目、画布、节点执行、资产库、表格、3D、插件、正式终端用户账号中心和组织协作，以及图片/视频/音频创作 |
| V2 | V1 退出；DGOS Project API 读写、版本校验和项目文档 schema 已冻结 | `V2-E2E-01`（拟定）通过；基础图编辑保存/重开/导入/导出可回滚；非法连接不会写入半成品 | AI 节点执行、资产授权、生成历史、表格、Agent、供应商节点和 3D |
| V3 | V2 退出；DGOS AI Task API 幂等、artifact 读取和节点运行状态可被画布消费；详见[V3 规划](后续版本/V3-规划.md) | `V3-E2E-01`（拟定）通过；生成/LLM/结果节点、运行快照、取消/重试和结果回写可追踪 | 跨项目资产授权、供应商专用节点、3D、插件安装和多人协作 |
| V4 | V3 退出；资产授权模型、表格 schema、Agent 审计和供应商能力握手已冻结 | `V4-E2E-01/02`（拟定）通过；表格并发/导入导出、授权撤销、引用/复制导入和供应商失败均有稳定状态 | 3D 导演台、Canvas 插件市场、实时协作和移动端 |
| V5 | V4 退出；渲染能力、导出格式、插件清单和隔离运行时已验证 | `V5-E2E-01/02`（拟定）通过；导演台可恢复和导出，插件升级失败可回滚且数据隔离 | 多人实时协作、市场规模化分发和移动端完整体验 |
| V6 | V2–V5 的数据/权限/扩展协议稳定；协作与规模化市场运营协议单独完成设计评审；详见[V6 规划](后续版本/V6-规划.md) | 协作冲突、权限变更、规模化市场运营、批量队列和跨端恢复均有独立验收证据 | 未通过门禁的上游能力和未登记的隐式兼容 |

### 6.2 版本调整规则

1. 新能力默认进入最晚满足其依赖的版本；不能因为界面已经出现，就把实现提前计入当前版本。
2. 提前交付必须同时补充依赖、数据/接口影响、验收用例和冻结决策；只展示入口或禁用态不算能力提前交付。
3. 版本延期不回滚稳定需求编号；将功能保留在原编号下，更新归属版本、门禁和变更记录。
4. 任一版本出现跨域高风险（权限、秘密、异步外部副作用、动态制品、协作冲突），必须拆成独立验收目标，不以“同一页面”合并版本范围。
5. 未进入开发门禁的版本，以对应的独立规划文件作为版本级范围入口；路线图和演进矩阵只做聚合索引，不替代规划文件。
