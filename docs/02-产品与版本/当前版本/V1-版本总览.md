## 2. 版本目标

V1 建立 DGOS 独立系统平台的最小闭环：macOS 桌面与 Docker Compose 本地 Web 入口共用 DGOS 自有桌面/窗口壳层、应用规范与运行时、应用目录、安装/启动/更新/卸载生命周期、身份/会话、权限、API Provider 适配、动作目录和必要系统服务。平台控制面应用验证发现、安装、授权、设置、扩展管理和助手动作闭环；唯一业务示范 APP“DGOS AI 工作台”验证从 Provider 配置到真实文本模型调用的完整链路。桌面端与 HTTPS Web 端共用前端应用包和版本化 API。首批真实 Provider 协议为可配置的 `openai-compatible`，文本任务支持 SSE 流式输出。Windows 仅保留后续 DGOS 平台适配边界，不计入 V1 交付。无限画布与项目基础进入 V2，后续依赖按 V3–V6 分阶段交付。

本轮新增治理切片：`V1-FR-010` 管理员登录与会话、`V1-FR-011` API Key 生命周期、`V1-FR-012` Provider 账号与连接、`V1-FR-013` 上游账号连接测试、`V1-FR-014` 审计与管理员系统治理、`V1-FR-015` 用量与额度管理。它们补充 V1 平台控制面和 AI Task 依赖，不改变 `V1-FR-004/006/008` 已迁移到 V2/V5/V4 的版本归属。

当前仓库无产品代码；输入是参考视频、DX OS 外部开发者中心研究资料和 `/Users/apple/Progame/infinite-canvas-ccnuzw` 旧项目参考。旧项目与外部研究资料都不构成 DGOS 实现基线。

## 4. 首发交付范围

功能编号表登记全部规划能力，但 V1 首发按交付层级分组：

### 4.1 基础闭环

| 功能 ID | 范围 | 说明 |
| --- | --- | --- |
| V1-FR-001 | 桌面与应用工作区 | DGOS 自有桌面、Dock/启动台、窗口管理和系统导航。 |
| V1-FR-005 | 多模态 AI 任务工作流（V1 文本子集） | 由 DGOS AI 工作台用 DGOS AI Task API 提交和追踪真实文本任务，支持 SSE 流式增量、终态查询和结果展示；图片/视频/音频和产物工作流后置，不要求画布回写。 |
| V1-FR-007 | 模型平台与工作流配置（基础子集） | 通过 Provider Adapter 配置和验证真实 API Provider，刷新模型目录与能力标签；不交付 ComfyUI/GPU 工作流编排。 |

## 5. 不做范围

| 事项 | 原因 | 归属版本 |
| --- | --- | --- |
| DX OS 核心桌面、私有服务、Bridge 和协议兼容 | DX OS 只属于外部研究参考；DGOS 永久不以兼容层、嵌入或复用其私有服务为目标 | 不做 |
| 移动端完整交互 | 视频和参考项目以桌面为主 | V6 |
| 多人实时协作和市场 | 需要独立冲突、权限和发布门禁 | V6 |
| 旧项目 `/api/canvas/*` 私有 API 兼容 | 与 DGOS 自有版本化 API/SDK 边界不一致 | 不做 |

## 6. 工程落地边界

| 项目 | 边界 |
| --- | --- |
| 技术栈 | V1 采用 React + TypeScript + Vite、Tauri 2 + Rust、Node.js LTS + Fastify、独立 Node/TypeScript Worker、PostgreSQL、Redis、S3/MinIO 和独立 `extension-runner`；桌面/Web 共用前端和 API 契约，Web 提供 Docker Compose 本地部署；Windows 保留 DGOS 平台适配边界。详见 [ADR-0003](../../06-决策记录/ADR/0003-V1技术栈与可替换运行时.md)。 |
| 数据 | DGOS 是应用注册、安装状态、授权和系统配置的权威所有者；V2 引入项目主数据，AI 产物使用 DGOS 自有稳定引用。 |
| 部署 | DGOS 自行校验应用包、版本、签名/来源并管理安装回滚；桌面与 HTTPS Web 是同一 DGOS 前端的两个运行形态，不是 DX OS 嵌入应用。 |

## 11. 最小 Demo 场景

1. 启动 DGOS，打开自有桌面、应用目录和平台控制面入口。
2. 启动 DGOS AI 工作台并完成应用启动权限与能力授权决策。
3. 在工作台配置 Provider、验证连接、拉取并启用文本模型，提交真实文本任务并验证 SSE 增量、任务状态、结果展示与错误恢复。
4. 更新或卸载示范 APP 时，验证健康检查、回滚和用户数据保留规则。
