## 并行任务分组

下面 5 个任务可以从当前基线并行执行。每个任务必须使用独立 worktree、独立分支和独立 commit，不修改其他任务边界。

### 并行任务 A：真实 API/Provider/Web 联调

负责把现有 Provider fixture、Fastify API、PostgreSQL 和 Web Workbench 连成真实链路。

范围：

- 使用真实 fixture HTTP server，不使用 Playwright route mock 作为唯一证据。
- 真实完成 bootstrap/login、Provider account/config、validate、catalog refresh、model policy、AI task、SSE、断线恢复、cancel、Artifact、quota。
- 添加真实 Web E2E 或 integration harness，记录上游调用次数、taskId、attemptId、event sequence、artifact 和 quota 状态。
- 保持 Provider fixture 只作为受控外部替身，不调用真实外部密钥。

验收：

- `V1-E2E-05`、`V1-E2E-07`、`V1-E2E-15` 达到 local-mock Passed 或 staging Passed。
- 测试必须实际启动 Web/API/PostgreSQL/fixture，不能只 mock API route。
- 失败、取消、断线和重复提交均无重复上游请求或重复 quota 结算。

主要文件边界：`apps/web`、`tests/e2e`、`tests/integration`、fixture 启动脚本和报告，不修改 worker bootstrap、Tauri 或认证核心实现。

### 并行任务 B：独立 Worker 宿主 Bootstrap

负责让 `pnpm --filter @dgos/worker start` 真正成为可运行的 PostgreSQL AI Task worker。

范围：

- 构造 PostgreSQL repositories：AI Task、ProviderConfig、Provider Account、Audit、Quota。
- 构造 SecretService、ProtocolAdapterRegistry、ProviderEgress、AiTaskService 和 AiTaskWorker。
- API submit 在 PostgreSQL 模式只入队，不启动 queueMicrotask；worker 负责唯一消费路径。
- 完成 SIGINT/SIGTERM、pool close、heartbeat、poll/backoff、运行错误和 worker startup failure 处理。
- 添加 worker 进程级 integration harness，真实提交 queued task 后由独立 worker 消费。

验收：

- 没有完整依赖配置时 worker 明确失败，不静默消费任务。
- 有完整配置时可独立启动、领取、执行、settle/release、写 Artifact 并退出。
- 两 worker 竞争、worker 终止、lease 到期接管、quota exactly-once 通过真实 PostgreSQL。

主要文件边界：`apps/worker`、worker bootstrap module、必要的 API dispatch wiring、worker integration tests 和 README，不修改 Web UI、Tauri、Provider fixture 协议。

### 并行任务 C：助手 UI、Action Recovery 与 E2E

负责 V1-FR-009、V1-E2E-09，以及与系统设置相关的 Web 体验。

范围：

- Web 增加助手入口、动作列表、参数输入、plan/confirm/execute、run 状态、cancel、错误和审计摘要。
- 增加 Action recovery worker 或通用 action run lease/reclaim，保证长任务重启后可查询和接管。
- 接入现有 Permission Broker、Action Registry、System Settings API，不绕过权限和确认。
- 添加真实 API/session E2E，覆盖 allow/deny/ask、风险确认、过期 confirmation、版本冲突、取消和 handler exactly-once。

验收：

- 未授权、取消、过期确认和版本冲突不产生 handler 副作用。
- 长任务可恢复，run 终态、设置版本和审计记录一致。
- `V1-E2E-09`、`V1-E2E-10` 至少完成 Web local-mock/staging 证据。

主要文件边界：`apps/web`、action worker/runtime、对应 API integration/E2E，不修改 AI Provider adapter、Tauri Rust host 或 API Key 存储实现。

### 并行任务 D：认证、安全与治理 E2E

负责 V1-E2E-11/12/13/14 及安全门禁，不负责桌面和 AI Workbench UI。

范围：

- 管理员 bootstrap/login/session renew/revoke、错误限速、CSRF/Origin、会话失效。
- API Key 一次性展示、scope 隔离、轮换窗口、撤销/过期、秘密扫描。
- Provider account/connection test 成功、认证失败、超时、SSRF/禁止网段、取消和无目录副作用。
- Audit/outbox、治理版本冲突、retention preview/run/checkpoint/retry、审计不可用 fail-closed 行为。
- 补齐 API Key 变更与 audit/outbox 同事务的实现或明确可验证边界。

验收：

- `V1-E2E-11/12/13/14` 有真实 API + PostgreSQL 测试和报告。
- 任意失败场景不泄露 credential/API key，不产生未授权副作用。
- 证据包含 requestId、eventId、keyId、testId、jobId、版本和 commit binding。

主要文件边界：identity、provider account、secret/rate-limit、audit/governance、security tests 和报告，不修改 Web AI task workflow、worker bootstrap 或 Tauri。

### 并行任务 E：Tauri/macOS 最小宿主与桌面 E2E

负责 V1-E2E-01、桌面侧 V1-E2E-02/05/10 运行证据。

范围：

- 将 `apps/desktop` 从 README 占位变成最小可构建 Tauri 2/macOS host。
- 复用 Web 前端/API，不复制业务逻辑。
- 验证窗口启动、登录态、打开 AI Workbench、任务结果、设置/contextVersion、退出和重启恢复。
- 添加 macOS 运行说明、构建命令、测试产物和截图/日志证据。

验收：

- `V1-E2E-01` 通过真实 macOS/Tauri 窗口。
- 桌面与 Docker Web 使用同一 API/SSE 语义。
- 不能以浏览器截图替代 macOS 宿主证据。

主要文件边界：`apps/desktop`、Tauri Rust 配置、桌面 E2E/文档，不修改 API 业务逻辑和 Web 业务组件。
