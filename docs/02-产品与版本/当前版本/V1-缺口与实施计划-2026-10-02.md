# DGOS V1 缺口与实施计划

更新时间：2026-10-02  
基线：`72ab1cb98b064a6e27b9f60a9f8f00881a827a99` + 当前工作树  
适用范围：V1 首发的 12 个 active FR、62 条 AC、12 项首发 E2E、7 项 NFR、3 项发布门禁

## 1. 结论

V1 已具备较完整的后端领域实现、数据库迁移、公开 HTTP 接口、独立 Worker、浏览器 fixture 和部分 macOS 原生证据，但尚未形成可发布候选。当前最大风险集中在四类：

1. **真实宿主闭环未收敛**：签名 Workbench 的 macOS 原生 bridge/iframe/Task/Artifact/reload 链仍有 `webview_result_timeout`、宿主握手超时；Web 与 macOS 尚未绑定到同一最终 dist。
2. **跨边界与真实依赖证据不足**：外部 Provider、目标 CA/DNS、Redis/TLS、Linux sandbox 正负例、双宿主会话和目标部署尚未在同一候选上验证。
3. **部分功能仍是局部实现**：FR-003、FR-005、FR-007、FR-009、FR-012、FR-015 的完整 UI 分支、恢复、准入/结算和审计矩阵仍有缺口；FR-001/002/010/011/013/014 主要缺最终候选与目标环境证据。
4. **发布门禁尚未满足**：全局回归历史批次为 202 pass / 13 fail / 31 skip 且有源码漂移；最新隔离诊断虽为 89 文件 267 pass / 0 fail / 0 skip，但排除了 browser、Redis/TLS、native、外部 Provider 和 release。旧镜像保留 1 Critical / 59 High；提交绑定、开发/E2E/release 报告、审批和风险处置仍缺。

因此当前版本状态应保持“实现进行中/待候选验收”，不能宣布 V1 完成或发布。

## 4. 推荐推进顺序

### 阶段 A：冻结候选输入与解除发布阻断

1. **停止功能扩张，建立候选清单**：固定 commit、47 条 migration（至 0051）、Web dist、macOS 制品、Docker 镜像、测试 fixture、配置和报告目录；所有后续证据只针对该候选。
2. **先修原生宿主阻断**：由桌面/Workbench owner 定位 iframe handshake、sandbox、bridge 生命周期和等待超时；完成一次最小真实前台批次后再扩大业务链。
3. **重建安全基线**：重建最终镜像并重新扫描；对 Critical/High 逐项修复或形成带范围、期限、补偿控制的正式风险接受。完成签名、公证、TLS/Secret/CA 配置。
4. **收敛测试工具链**：Verify 固定 source identity、随机隔离库、候选分组和可组合 E2E 映射；不得把 memory/PG 结果替代 browser/native/release 层证据。

### 阶段 B：完成三条首发业务链

1. **应用生命周期链**：开发者校验 → 管理员审核 → 普通用户安装/更新/卸载 → 健康失败回滚 → 数据保留；覆盖 Web 和 macOS。
2. **Provider 到 AI Task 链**：Provider 账号/Secret → 连接测试 → 显式模型刷新与启用 → 工作台 SSE → 终态/Artifact → 重连、取消和失败恢复；至少接入一条真实外部 `openai-compatible` 服务。
3. **桌面/权限/助手链**：桌面启动与上下文 → 权限决策 → 助手动作发现/计划/确认/执行/取消 → 设置 CAS 与审计；验证高风险拒绝无副作用。

### 阶段 C：补齐治理与扩展横切面

按依赖顺序推进：身份/Key 与可信传输 → Provider/网络边界 → Quota/Usage → Audit/Retention → Skill/MCP sandbox 与 Run 恢复。每个切片必须完成代码、接口、migration、测试、UI、E2E、文档回写，不能只补报告。

### 阶段 D：候选回归与发布门禁

1. 在候选环境执行全部 12 项首发 E2E、7 项 NFR、3 项 RG；每项保存原始日志、manifest、源码/构建身份和限制。
2. 执行 `check-docs`、planning gate、development gate、E2E gate、release gate；处理真实错误，不能填模板报告。
3. Verify 独立复核：无源码漂移、无未解释失败/跳过、证据层级正确、敏感信息脱敏、文档状态与代码一致。
4. Lead 统一回写功能主文档、V1 实现状态、追踪矩阵、公共契约、E2E/发布报告，并提交最终批准。

## 6. 完成判定

只有同时满足以下条件，V1 才能从“本地验证/实现进行中”升为“待发布”或“已完成”：

- 12 个 active FR 的 AC 均有实现、测试和文档回写；
- `V1-E2E-01/02/03/05/07/09/10/11/12/13/14/15` 在同一候选通过；
- 7 项 NFR、3 项 RG 和 development/e2e/release gates 通过；
- Web、macOS signed APP、Worker、47 条 migration、镜像和配置身份一致，无源码漂移；
- 外部 Provider、TLS/CA/DNS、Redis、Linux sandbox、Secret backend 等真实依赖证据齐全；
- 安全扫描、签名/公证、备份恢复、RPO/RTO、监控脱敏、容量与故障演练有真实报告；
- Verify 独立复核通过，Lead 完成需求、实现状态、追踪矩阵、契约和发布空间回写并取得批准。
