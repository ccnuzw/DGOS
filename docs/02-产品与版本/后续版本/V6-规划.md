# V6 协作与生态规模化规划

## 文档定位与状态

本文是 V6 的独立版本规划文件，维护协作、生态和规模化能力的范围方向。V6 尚未通过[版本进入开发门禁](../版本进入开发门禁.md)，本文不是直接编码输入，不分配 `V6-FR`、`V6-NFR` 或 `V6-RG` 编号，也不代表相关能力已经实现。

正式开发前，需在上游 V2-V5 稳定协议基础上保留跨版本延续的功能 ID，仅为新增的独立验收目标分配 V6 正式编号；随后拆成功能主文档、技术设计、接口、数据、测试和证据空间。实现状态只维护在届时建立的 V6 实现状态文档。

## 版本目标

把单人创作平台扩展为可治理的组织协作和生态分发平台。团队可以共同编辑项目和资源，开发者可以提交、审核、发布和回滚应用/插件/Skill/MCP，生产任务可以批量排队并在桌面、Web 和后续移动入口之间恢复。

## 做什么

- 组织、团队、成员、角色、策略和主体作用域。
- 多人实时协作、在线状态、变更同步、冲突提示、合并和恢复。
- 共享项目、资产、应用和扩展的授权、回收、审计与数据保留。
- 应用、Canvas 插件、模板、Skill 和 MCP 的投稿、审核、签名、版本、发布、停用和回滚。
- 批量任务队列、暂停/恢复/取消、失败重试、并发和配额控制。
- 生产级观测、调用统计、配额消耗、告警和审计导出。
- 使用同一 DGOS API/SDK 的跨端入口，支持跨端恢复和安全会话边界。

## 明确不做

- 未通过 V2-V5 门禁的项目、画布、资产、3D 或扩展能力。
- 对旧项目、旧 API 或外部平台的隐式兼容和私有协议复用。
- 无审计的组织管理员绕过、未授权跨组织资源访问或静默权限提升。
- 没有签名、来源和审核记录的生态包直接进入生产安装范围。
- 在本版本范围外承诺具体移动操作系统、计费方案或数据驻留区域；这些需单独决策。

## 上游依赖

| 依赖 | 要求 |
| --- | --- |
| V2-V5 | 项目、画布、artifact、扩展、3D 导出和模板契约稳定，且权限边界可被组织策略复用。 |
| 主体与 Session | V1/V2 的主体、Session、所有权和权限模型支持组织/团队扩展。 |
| 发布基础 | 应用/插件/Skill/MCP 的 manifest、版本、签名、安装、升级、停用和回滚已有可调用边界。 |
| 观测与任务 | AI Task、Canvas Run 和外部副作用具有统一事件、幂等、取消和审计语义。 |

## 架构影响

- 协作服务负责房间、在线状态和变更同步；项目服务仍是项目文档的权威所有者，不能由协作通道直接绕过提交规则。
- 实时同步采用 WebSocket/事件流方向，具体使用操作日志、版本向量或文档合并算法需由 ADR 冻结。
- 冲突处理必须可解释、可恢复、可审计；离线变更不能静默覆盖他人提交。
- 生态发布链路拆分投稿、审核、签名、分发和安装回滚，生产安装只消费已批准版本。
- 批量队列与单任务执行器共享 Provider、权限、秘密、取消和审计能力；不复制第二套任务语义。
- 移动端或其他跨端入口消费同一版本化 DGOS API/SDK，平台差异收敛在宿主适配层。

## 数据影响

仅定义方向性实体，待门禁后冻结字段、索引和保留：

- `Organization`、`Team`、`Membership`、`Role`、`Policy`：组织关系、角色和策略。
- `CollaborationRoom`、`Presence`、`Operation`、`Revision`、`Conflict`：协作会话、变更和冲突。
- `Submission`、`Review`、`Release`、`Distribution`：生态投稿、审核、发布和分发。
- `Batch`、`Quota`、`Usage`、`Observation`：批量任务、配额、调用统计和观测。
- `AuditEvent`、授权回收记录和数据保留标记：权限变化、发布动作和跨组织访问证据。

所有权、授权、回收、审计和保留策略必须与项目、artifact、扩展包和任务结果分离建模；任何秘密、私有路径和完整媒体都不得进入协作日志或发布包。

## 接口方向

以下仅表示领域方向，不冻结 schema 或 operationId：

- `dgos.organization.*`、`dgos.team.*`：组织、团队、成员和策略。
- `dgos.collaboration.*`：房间、同步、冲突、合并和恢复。
- `dgos.release.*`、`dgos.market.*`：投稿、审核、签名、发布、分发和回滚。
- `dgos.batch.*`：批量队列、并发、配额、暂停、恢复、取消和重试。
- `dgos.observability.*`：调用统计、审计、告警和受控导出。

权限即时回收、事件顺序、冲突合并、跨端会话和配额计量必须在独立技术设计、ADR 和 OpenAPI/事件契约中冻结后才能实现。

## 验收方向

- 成员加入、离开、角色变化和权限回收在项目、资产和扩展访问中即时生效并可审计。
- 多人同时编辑能显示冲突，按冻结算法合并或恢复，不静默丢失变更。
- 投稿、审核、拒绝、发布、停用和回滚均有版本、签名、审批和安装证据。
- 批量队列支持排队、暂停、恢复、取消、失败重试、并发限制和配额拒绝。
- 桌面、Web 和后续跨端入口能恢复同一主体有权限的项目、运行和协作状态。
- 生产观测、调用统计、配额和审计导出不泄露 API Key、完整媒体或私有路径。

## 主要风险

| 风险 | 影响 | 门禁前处理方向 |
| --- | --- | --- |
| 协作冲突算法与项目提交规则不一致 | 丢失修改或生成不可恢复文档 | 用独立 ADR 冻结合并算法、提交版本和恢复证据。 |
| 组织权限撤销传播延迟 | 已离队成员继续读取资源 | 冻结在线会话失效、缓存失效和授权重检边界。 |
| 生态包审核或签名链薄弱 | 恶意包进入生产安装 | 冻结信任根、审核责任、回滚和下架流程。 |
| 批量队列缺少统一配额 | Provider 超额调用和费用失控 | 冻结主体/组织配额、并发、重试和计量口径。 |
| 跨端与数据驻留边界不清 | 数据越域或审计缺口 | 冻结部署区域、会话范围、保留和导出策略。 |

## 进入开发门禁前未决项

1. 冲突合并采用操作日志、版本向量、CRDT 还是受限文档合并。
2. 组织计费、配额、并发和 Provider 调用统计的计量口径。
3. 市场信任、审核责任、签名根和恶意包处置边界。
4. 移动端首批平台、离线范围和敏感操作限制。
5. 数据驻留、审计保留期限、导出权限和跨组织删除语义。

## 门禁状态

`规划骨架`。V6 尚无正式功能编号、可编码接口契约、数据迁移、测试资产或实现证据；不进入 V1 实现状态、不计入当前交付统计。
