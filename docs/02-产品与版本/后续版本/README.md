# 后续版本规划

未进入开发门禁的版本默认只维护一份独立版本规划（如 `V3-规划.md`），只定义范围、目标、做/不做、依赖、架构影响、数据影响、接口方向、验收方向、风险与交付切片，**不作为直接编码输入**。版本通过开发门禁后，才能分配正式 `Vx-FR/NFR/RG`，拆成功能主文档、技术设计、接口、数据、测试和证据空间。

当前保留的三份规划登记稿是稳定需求编号的历史设计输入例外：它们位于 `03-功能规格/V2`、`V4`、`V5`，必须同时标注 `delivery_scope: future`、`planning_only: true` 和交付切片，不能进入 V1 实现状态、交付统计或开发任务。拆分为可直接编码的功能规格前，仍必须先通过[版本进入开发门禁](../版本进入开发门禁.md)，并重新核对接口、数据、验收和证据。

| 版本 | 规划文件 | 状态 |
| --- | --- | --- |
| V2 | [V2 项目与画布基础规划](V2-规划.md) | 独立主文档；未解锁开发门禁 |
| V3 | [V3 画布工作流规划](V3-规划.md) | 标准单文件规划；未解锁开发门禁 |
| V4 | [V4 结构化创作与资产服务规划](V4-规划.md) | 独立主文档；未解锁开发门禁 |
| V5 | [V5 3D 与扩展生态规划](V5-规划.md) | 独立主文档；未解锁开发门禁 |
| V6 | [V6 协作与生态规模化规划](V6-规划.md) | 标准单文件规划；未解锁开发门禁 |

V2、V4、V5 的功能登记稿保留历史稳定编号，但各版范围以本目录独立主文档为准。所有后续版本在通过门禁前都不得被浏览器、实现状态或开发任务解释为已实现。
