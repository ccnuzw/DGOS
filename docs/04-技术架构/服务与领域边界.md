# DGOS 服务与领域边界

本文件将 DGOS 的独立系统边界落到进程、逻辑领域、数据访问和验收规则。V1 可将多个领域部署在同一模块化单体内，但不得因此取消所有权和权限边界。V1 运行时基线采用 [ADR-0003](../06-决策记录/ADR/0003-V1技术栈与可替换运行时.md)；未来 Worker/API 替换必须保持本文件中的领域与公共契约边界。

## 1. 物理进程

| 进程 | 职责 | 生命周期 | 扩展方式 |
| --- | --- | --- | --- |
| `dgos-shell` | 桌面、窗口、启动台、Dock、系统入口和应用承载 | 用户会话级 | 按桌面会话扩展 |
| `dgos-api` | SDK 网关、身份、权限、应用目录、项目、模型、任务、artifact 和审计 API | 系统服务级 | V1 模块化单体；按领域拆分 |
| `dgos-worker` | AI、导入导出、索引和通知任务 | 队列消费者级 | 按任务类型和并发度水平扩展 |
| `dgos-extension-runner` | Skill、MCP、Agent 及后续插件/节点的隔离执行 | 执行单元级 | 按应用、任务和信任等级隔离 |
| `dgos-storage` | 事务库、对象存储、队列、缓存和搜索适配 | 基础设施级 | 替换适配器或独立托管 |

桌面发行版可以将上述单元打包为一个安装包；打包不改变 API、数据所有权或安全边界。HTTPS Web 入口消费 `dgos-api`，不在浏览器端复制领域逻辑。

## 2. 逻辑领域映射

| 领域 | 进程 | 聚合/实体 | 对外契约 |
| --- | --- | --- | --- |
| Identity & Session | `dgos-api` | User、Session、Device | `dgos.identity.*` |
| Permission & Policy | `dgos-api` | AppGrant、ProjectGrant、AssetGrant、SecretGrant、Decision | `dgos.permission.*` |
| App Catalog & Install | `dgos-api` | AppManifest、AppVersion、Installation、ReleaseChannel | `dgos.app.*` |
| Project & File | `dgos-api` | Project、Folder、FileRef、ProjectVersion | `dgos.project.*`、`dgos.file.*` |
| Model & Provider | `dgos-api` | ProviderConfig、Model、Capability、Health | `dgos.model.*`、`dgos.config.*` |
| AI Task | `dgos-api` + `dgos-worker` | Task、TaskAttempt、Cancellation、RunLog | `dgos.aiTask.*` |
| Artifact & Asset | `dgos-api` + `dgos-storage` | Artifact、ArtifactVersion、AssetRef、ImportRecord | `dgos.artifact.*`、`dgos.asset.*` |
| Audit & Notification | `dgos-api` + `dgos-worker` | AuditEvent、Notification | `dgos.audit.*`、`dgos.notification.*` |
| Extension Runtime | `dgos-extension-runner` | Skill、MCPServer、Agent、ExtensionRun | `dgos.skill.*`、`dgos.mcp.*`、`dgos.agent.*` |

画布、表格和 3D 导演台是后续 DGOS 应用/扩展领域。它们使用项目、任务、artifact、权限和文件公开契约，不成为系统壳层的隐式子模块。

## 3. 数据访问规则

- 每张表、每类对象和每个命名空间只有一个领域所有者；所有者负责 schema、状态迁移、删除和审计。
- 跨领域写入必须通过显式服务接口或事务编排；禁止直接写他人表、对象存储路径或队列主题。
- 应用私有数据使用应用命名空间隔离；项目数据通过项目 API 访问；系统秘密只能通过 Secret Service 使用。
- 权限判定必须在服务端完成，不能以客户端按钮状态、缓存结果或 manifest 声明替代服务端校验。
- 对象存储引用必须绑定 artifact/file 记录和授权范围；裸 URL、路径或外部供应商 ID 不能作为 DGOS 权威引用。
- 派生索引、缓存和通知均可重建；恢复流程以事务存储和对象存储中的权威记录为准。
- 共享状态位于共享存储，水平扩展不得依赖单进程内存；任务消费者必须支持幂等和重复投递。

## 4. 内部接口

V1 逻辑领域即使位于同一进程，也必须通过接口层调用。接口可以是函数/模块调用或本地 IPC，但使用与公开 API 相同的请求、响应、错误和审计语义。

| 接口 | 调用方 | 鉴权 | 用途 |
| --- | --- | --- | --- |
| `PermissionService.authorize` | 所有副作用领域 | 用户会话 + 应用身份 + 资源范围 | 在执行前返回 allow/ask/deny 与原因 |
| `SecretService.resolve` | Model、MCP、Agent、Worker | 短时 capability + 最小范围 | 返回脱敏状态或一次性使用句柄 |
| `AppInstallService.commit` | App Catalog、Updater | 管理权限 + 包签名/哈希 | 提交已校验的安装版本 |
| `ProjectService.read/write` | 第一方应用、画布应用 | 项目授权 + 版本条件 | 读写项目和文件元数据 |
| `ModelService.createTask` | AI 应用、Agent、画布节点 | 模型/项目/秘密授权 | 创建 DGOS AI Task |
| `ArtifactService.put/link` | Worker、项目应用 | artifact 写入 + 项目授权 | 写入产物并建立引用 |
| `ExtensionRunner.execute` | Skill/MCP/Agent 调用方 | 扩展授权 + capability | 在隔离边界中执行扩展 |
| `AuditService.append` | 所有领域 | 内部服务身份 | 追加记录安全与副作用事件 |

## 5. 一致性策略

| 场景 | 策略 | 失败处理 |
| --- | --- | --- |
| 同一领域事务 | 单事务提交状态和版本号 | 回滚事务并返回结构化错误 |
| 安装/更新 | 暂存包 → 校验 manifest、签名和权限 → 原子切换活动版本 | 保留上一版本并写入回滚审计 |
| AI 任务 | 任务记录先落库，再投递队列；消费者按 `taskId` 幂等 | 重试、取消、死信和人工重放均可追踪 |
| artifact 写入 | 二进制先暂存，元数据和引用成功后提交可见 | 清理孤儿暂存对象并保留失败记录 |
| 跨域最终一致 | 事务事件/编排记录驱动下游更新 | 指数退避、补偿任务和对账报告 |
| 权限变更 | 新请求立即使用新决定；已有任务按资源策略继续、暂停或取消 | 写审计，禁止以旧缓存恢复授权 |

## 6. 可观测性边界

- 每个 API、任务、扩展执行和跨域编排生成 `request_id`/`trace_id`，并关联用户、应用、项目和资源 ID。
- 健康检查只证明进程存活；就绪检查聚合必需依赖，扩展供应商不可用不应拖垮 Shell 的基础就绪。
- 审计事件记录谁、哪个应用、何时、对什么资源、作出什么决定以及结果；不记录 API key、秘密值或完整敏感内容。
- 指标按领域暴露请求延迟、错误率、队列积压、任务终态、安装回滚和权限拒绝；入口由部署层保护。

## 7. 本地与生产拓扑

| 环境 | 拓扑 | 与生产差异 | 可证明范围 |
| --- | --- | --- | --- |
| local | Shell + API + Worker + Extension Runner 本地运行，使用本地事务库/对象存储/队列适配器 | 单机、开发秘密、模拟供应商 | 契约、权限、生命周期、任务和回滚逻辑 |
| staging | 与生产相同的 API/Worker/Runner 边界，使用测试身份和供应商 | 容量、数据规模和外部配额较小 | 集成、升级、故障恢复和发布候选 |
| production-gate | 接近生产的隔离环境，使用门禁数据和受控外部能力 | 不承载正式用户数据 | 发布、性能、审计和灾备证据 |
| production | DGOS 独立系统服务与发行包 | 真实容量、身份、数据和供应商 | 运行质量和持续审计 |

## 8. 未来拆分触发条件

只有满足至少一个明确证据，并且跨进程契约已冻结时，才拆分物理服务：

- 扩展/渲染/模型任务需要独立沙箱或资源配额；
- 某领域的吞吐、存储或发布频率显著不同；
- 故障隔离要求一个领域不能影响 Shell 或核心权限服务；
- 合规、数据驻留或秘密边界要求独立部署；
- 监控显示模块化单体已成为容量或恢复瓶颈。

拆分前必须补充 API 版本、超时/重试、幂等、事件顺序、数据迁移、审计和回滚方案；没有这些证据时保持当前边界。

## 9. 验收口径

- 跨领域写入只能通过登记的内部接口或公开 DGOS API，越权直写测试必须失败并产生审计记录。
- 应用无法读取其他应用私有数据、明文秘密或未授权项目/artifact；缓存失效不会扩大权限。
- 安装、更新、卸载、任务取消、artifact 提交和权限撤销均能证明原子性、幂等性和失败恢复。
- 本地、staging 和 production-gate 使用同一契约测试；任何 DX OS 参考资料不作为 DGOS 运行验收证据。
