# V1 数据模型

V1系统注册、安装、权限、设置、Provider及任务由DGOS管理，macOS与Compose Web消费相同语义。存储/事务/migration/恢复遵循[ADR-0006](../../06-决策记录/ADR/0006-V1事务存储与迁移恢复.md)，秘密/出站遵循[ADR-0007](../../06-决策记录/ADR/0007-V1秘密管理与Provider出站安全.md)。2026-10-02仓库已有migrations与F轮本地PG证据；物理表/索引唯一权威为migrations目录。下列逻辑模型及原迁移规划不能当当前物理状态，旧“无DDL/待migration”文字属于实现前计划；当前对应证据统一见[V1实现状态](../../02-产品与版本/当前版本/V1-实现状态.md)和[F报告](../../05-测试与发布/端到端验收/报告/V1-F-整合联调报告.md)。HTTP字段以[OpenAPI](V1-openapi.yaml)为准，future实体不纳入V1。

## V1-FR-010–015 机器契约实体字段

以下字段是 V1 逻辑模型和 OpenAPI 的共同最小集合。它们不是物理表定义；ADR-0006/0007 已冻结物理约束和安全实现基线，但唯一索引、加密实现和 migration 仍需工程文件与执行证据确认。

| 实体 | 权威服务 | 必须字段/关系 | 状态与不变量 | 敏感字段边界 |
| --- | --- | --- | --- | --- |
| `AdminPrincipal` | Identity | `principalId`、`status`、`credentialRef`、`roleRefs`、创建/更新时间 | `invited -> active -> suspended/revoked`；初始化完成后至少一个 active 管理员 | credentialRef 只可由 Identity/Secret 使用 |
| `AdminSession` | Identity | `sessionId`、`principalId`、`state`、`sessionVersion`、`expiresAt`、`revokedAt` | `created -> active -> expired/revoked`；撤销与续期按版本条件更新 | Cookie、续期凭据和完整设备/IP 不落业务响应或日志 |
| `LoginAttempt` | Identity | `attemptId`、主体提示摘要、来源摘要、结果、限速时间 | 只服务限速和审计；不能作为身份真源 | 不保存密码、恢复码或可枚举主体信息 |
| `ApiKeyRecord` / `KeyRotation` | Secret | `keyId`、`ownerId`、prefix、scope、digest、rotationGroup、版本和重叠窗口 | 新 Key 先 active；旧 Key 不得在新 Key 成功前撤销 | 只保存 digest/SecretRef；Authorization 永不落日志 |

| `ConnectionTest` | Provider Test | test/request/account/config/protocol 版本、状态、reasonCode、延迟 | `queued -> running -> succeeded/failed/timed_out/cancelled`；终态只写一次 | 不保存完整 URL query、上游 body、Token 或内部地址 |
| `AuditEvent` / `GovernanceChange` | Audit/Governance | eventId、requestId、actor、action、target、result、policyVersion、摘要 | 事件只追加；策略使用版本条件更新；高风险成功必须可关联 eventId | 密码、Key、Cookie、Token、路径、Prompt、上游 body 禁止进入 |

| `UsageEvent` / `QuotaReservation` | Usage/Quota | usage/reservation ID、taskId、attemptId、metric、amount、状态和期限 | `taskId+attemptId` 唯一；预留原子；结算可重放 | 不保存完整 Prompt、Secret 或上游原始响应 |
| `QuotaPolicy` / `UsageAggregate` | Usage/Quota | scope、metric、limit、window、policy/version、aggregateVersion | 策略变更不追溯改写 UsageEvent；汇总可由事件重建 | 查询按主体授权范围过滤 |

## 关键不变量与失败验证

| 实体/跨域写入 | 不变量与数据库兜底 | 事务/并发/幂等边界 | 失败或补偿结果 | AC/E2E 验证 |
| --- | --- | --- | --- | --- |
| 应用安装 | 单活动版本；唯一索引待 migration | 安装记录与活动指针原子提交；健康检查外部步骤可回滚 | 旧版本和数据保留 | `V1-FR-002/AC02`、`V1-E2E-02` |
| 应用审核/目录准入 | 普通目录只包含官方或管理员批准版本；开发者不能自行提升信任级别 | 审核结果与目录可见状态作为一个可查询状态转换；普通用户安装时重新校验来源/批准状态 | 拒绝或撤回时不新增普通用户可见目录项/安装记录；不可卸载预装包在任何副作用前拒绝卸载 | `V1-FR-002/AC03`、`V1-E2E-02` |
| 权限/设置 | deny 优先；版本比较更新待 migration | 每次副作用前重算，baseVersion 冲突拒绝 | 不部分写入、不执行目标能力 | `V1-FR-001/AC07`、`V1-E2E-10` |
| Provider/模型 | Secret 明文隔离；配置/策略唯一性待 migration | 验证失败停用与新任务准入原子一致；目录刷新独立标 stale | 不创建新任务；已提交任务按原 taskId 收敛，历史目录/策略保留 | `V1-FR-007/AC02`、`V1-E2E-07` |
| AI Task/Artifact | requestId 唯一、事件序号单调、终态唯一；约束待 migration | 本域事务加外部调用幂等/补偿 | 无重复上游调用、无伪成功产物 | `V1-FR-005/AC02/AC08`、`V1-E2E-05` |
| 数据保留/清理 | 任务与已提交 Artifact 保留至用户明确删除；被引用 Artifact 不物理删除；缓存/失败安装记录/撤销会话从各自事件时间起算 30 天；审计从创建时间起算 180 天 | 清理批次按类别幂等执行，先复核引用和主体所有权，再删除可清理记录；V1 无法务保留例外 | 清理失败保留数据并可重试；不得级联误删仍被引用数据；当前只有逻辑规则，未有后台任务/DDL/运行证据 | `D033/D035`；E2E/迁移验证方案待补齐 |

| 实体/事务 | 逻辑不变量与所有权 | 失败边界与无副作用 | 验证入口 |
| --- | --- | --- | --- |
| 应用安装 | 安装服务是活动版本唯一写者；一个主体/设备/appId 至多一个活动版本 | 包校验、迁移或健康检查失败恢复旧活动版本，不删除用户设置、扩展配置和已提交 artifact | `V1-FR-002/AC01/AC02`、`V1-E2E-02`；migration 前后快照比对 |
| 权限与设置 | Permission 的 deny 优先；Settings 按域以 baseVersion 比较并递增 | 版本冲突不部分覆盖；拒绝不调用目标能力；代理凭据不进入快照 | `V1-FR-001/AC04–AC08`、`V1-E2E-10`；并发写与审计核对 |
| Provider/模型 | Secret 拥有明文，Provider 只保存引用；验证不隐式刷新或启用模型 | 验证失败原子停用并阻止新任务；目录刷新失败单独标 stale；不清除策略历史 | `V1-FR-007/AC01/AC02/AC07`、`V1-E2E-07` |
| AI Task/事件/产物 | Task 是终态唯一写者；同一主体/requestId 至多一个 taskId；事件序号单调，Artifact 独立持有原件 | 重试/断线不重复上游调用；失败/取消不生成成功产物；旧事件不覆盖终态 | `V1-FR-005/AC01/AC02/AC08`、`V1-E2E-05` |
| Session | Identity 拥有会话；撤销不删除 UserProfile 或其他资源 | 过期/撤销后不能读他人任务、设置或产物 | `V1-E2E-01/05/10`；权限专项测试待设计 |

跨域写入需按“授权重检 → 本域事务提交 → 外部调用/事件 → 终态记录”设计；Task 与 Provider 外部调用无法共享数据库事务，须以 requestId 幂等和可查询失败状态补偿。管理员会话、API Key、Provider 账号、连接测试、审计和额度的 OpenAPI operation 与最小字段已经冻结为规划契约；PostgreSQL、`READ COMMITTED` 默认隔离、条件更新/目标行锁、唯一约束、expand/backfill/switch/contract migration 和 checkpoint 恢复基线见 ADR-0006，Secret/ProviderEgress 基线见 ADR-0007。上述规则仍需 migration/实现证据确认，不能把设计基线解释为已经由 DDL 保证。

## 约束

1. V2 `connections` 只能引用存在的节点和端口；删除节点必须处理连线。
2. V2 项目文档保存大型媒体的引用和元数据，不保存无限增长的 Base64。
3. `PortDefinition.portId` 在节点生命周期内稳定；连接只能是 `output -> input`，同一端口对去重，单值输入最多一条。
4. 项目图默认是 DAG；整理布局只写选中节点位置；下游批量连接以预览版本为基准并原子提交。
5. task 状态终态不可被旧轮询覆盖；artifact 写入需幂等。
6. V5 插件数据隔离，卸载和回滚保留可解释的迁移/清理结果。
7. ProviderConfig 的秘密字段由 DGOS 秘密边界保存和脱敏；所有真实供应商调用由匹配的 Provider Adapter 代发；模型目录必须带能力标签和可用状态。
8. `ProtocolAdapterRegistration` 是协议扩展的唯一注册入口；前端只消费统一 Provider/Model/AI Task 契约，不根据供应商名称推断能力。`ProviderCapabilityDescriptor` 变化必须递增 descriptor 版本并在任务提交前重新握手。
9. `CapabilityProtocolRegistration` 与 `ProtocolAdapterRegistration` 分离：前者描述 Intent 的声明式 operation/workflow，后者描述连接与模型目录。协议 JSON 使用 DGOS `dgos-capability/v1`，不得直接采用 DX OS `dx-protocol/v2` 作为公共契约。
10. 能力协议只允许白名单声明式映射原语 `$map`、`$concat`、`$merge`、`$coalesce`、`$cardinality`、`$dataUrlBase64`、`$keyValue` 和 `omitEmpty`；禁止脚本、eval、函数体、Shell、任意 URL 拼接和未声明重试。异步 workflow 必须同时声明提交/查询状态、错误和结果路径，成功不能只依赖 `completed`。
11. `ModelProfile.match` 必须覆盖站点真实保存的模型名和兼容别名；只有命中 Profile、Intent 映射完整且策略启用的模型才可被 `dgos.model.resolve` 返回为可执行目标。`uiSchemas`、`limits`、`assets` 是模型能力契约的一部分，不能由前端按模型名推断。
12. `ProtocolOperation.response` 的多候选路径使用数组，多层数组使用显式 `[*]`；需鉴权下载的 operation 使用 `responseMode=binary`。上传素材必须由 workflow 显式绑定 upload operation，同一素材在已有合规 URL 时不得重复上传。
13. `AITaskEvent.sequence` 在单个任务内单调递增；SSE 断线后可用 `Last-Event-ID` 或等价游标继续订阅。事件流是增量观察面，任务查询和最终 Artifact 状态是权威面。
14. `ModelCatalog.detectedCapabilities` 是 Provider/Adapter 拉取或推断的只读结果；`ModelCapabilityPolicy.assignedCapabilities` 是用户可编辑分类。只有 active Provider 下 `availability=available`、策略 `enabled=true` 且目标能力在 `assignedCapabilities` 中的模型，才能被任务解析器选中；模型目录刷新不得清除仍存在模型的用户策略，也不得自动启用模型。
15. `ModelCapabilityPolicy.defaultFor` 在同一 Provider 作用域内按能力唯一；写入新默认模型时必须原子清除该能力的旧默认值。默认模型失效后不得自动回退到其他模型，任务入口必须显示未配置状态。
16. V4 AssetRef/GenerationRecord 只保存稳定引用和必要摘要；删除先计算引用闭包，默认使用 hidden/removed 语义。
17. `PermissionDecision` 的 deny 必须在 DGOS 执行层生效；清单声明不能覆盖 DGOS 拒绝，ask 必须产生用户可见确认。
18. `AppInstallRecord` 的卸载与 dataState 清理分离；`TaskCache` 清理不得删除项目文档或仍被任务引用的 artifact。
19. `AppManifest` 的 `permissions` 是声明，`capabilityAllowlist` 是调用白名单，二者都不能替代执行层的实时授权检查；`trustLevel` 由安装服务根据来源和策略确定，应用不能自行提升。
20. `AppInstallRecord` 的安装状态按 `discover -> validate -> stage -> health-check -> migrate -> commit` 推进；任一失败都恢复 `activeVersion`，不得清理项目、用户设置、MCP 配置或已提交 Artifact。
21. V2 起 `CanvasNode` 的 `config`、`inputState`、`runState`、`outputRefs` 和 `layoutState` 分域保存；布局复制/导入不得带入运行态，输入状态必须能由端口和边解释。
22. V3 的 `RunSnapshot` 在执行提交前一次生成并保持不可变；重试复用明确的运行批次/幂等键，旧轮询不得覆盖较新的终态，结果节点按 `runId` 追加而不是覆盖历史。
23. V2/V3 的 `WorkflowPackage` 导出前必须剔除秘密、DGOS 系统服务私有路径、临时 URL 和运行游标；导入按解析、校验、预览、提交四步执行，ID 重映射或任一校验失败时原画布不变。
24. V5 的 `DirectorProject` 的场景对象、机位、时间线和关键帧属于导演台领域数据；画布只保存项目引用、稳定全景边和回写 artifact 引用。`DirectorRunSnapshot` 不得包含临时 Blob、浏览器缓存 key 或私有路径。
25. V5 的 `DirectorCapture.deviceOnly=true` 的截图缓存只在当前设备可见；发送到画布后必须生成新的稳定 artifact。删除导演台节点不得删除已完成的 `DirectorCapture` 输出引用。
26. V1–V5 的资源所有权、授权和审计均使用 `subjectType/subjectId`；V1 至少支持 `user`，V6 增加 `organization` 和 `team`，不得用拼接字符串表达组织共享。
27. Session 表示身份上下文，不等同于权限授权；会话撤销不得删除 UserProfile、项目、Artifact 或安装记录。
28. `SystemAppearanceSettings`、`SystemLocaleSettings` 和 `NetworkProxySettings` 是 DGOS 系统层统一配置的权威记录；应用私有主题、语言或代理值不能覆盖它们的运行时语义。
29. `uiLocale/effectiveLocale/regionFormat/assistantLanguage/projectContentLanguage` 语义分离；切换界面语言不得修改项目内容字段。
30. `NetworkProxySettings.manualProxyRef` 只能指向秘密边界中的凭据引用；`effectiveRoute`、日志和 API 响应不得包含明文代理凭据。修改代理后 `restartRequired=true` 时，受影响服务必须继续标识旧路由或未重启状态。
31. `AppCapabilityGrant` 是授权记录，`AppManifest.permissions` 和 `capabilityAllowlist` 只是声明/白名单。执行层按主体、APP、capability 和 scope 重新计算，`deny` 优先，`ask` 不得在副作用后出现。
32. `SystemContextSnapshot` 不得包含 API Key、Cookie、绝对路径、内部 endpoint、完整网络代理地址或其他 APP 私有数据；上下文变化必须带递增 `contextVersion`。
33. `SystemGridSettings` 是 DGOS 系统层提供的网格默认和吸附语义，不等于某个 APP 的画布数据。支持网格的 APP 必须读取系统 token；V2 画布可在项目范围保存布局/可见性，但不能改变 DGOS 系统层的颜色 token、倍率和权限语义。

## 资产分享与跨项目复用边界

`AssetGrant` 是来源资产到明确主体的能力授权，不因进入资产库、加入来源项目或拥有目标项目成员身份自动生成。`capabilities` 只允许功能规格定义的能力名：`metadata.read`、`preview.read`、`reference.create`、`copy.import`、`metadata.edit`、`share.manage`、`delete` 和 `reshare`。未列出的能力默认拒绝，`reshare` 默认不授予。

`AssetGrant.status` 的业务状态为 `active`、`revoked`、`expired`、`access_revoked`。授权撤销或来源不可用只影响后续访问和 `reference` 解析，不自动删除已经完成的复制副本。

`AssetRef.accessMode` 只能为 `reference` 或 `copy`：

- `reference` 必须带 `sourceProjectId`、`sourceAssetId`、`artifactVersion` 和 `grantId`，以便在撤销、来源删除或版本不可用时显示可解释状态。
- `copy` 指向目标项目自己的资产，并通过 `AssetImportRecord` 保存来源、导入者、固定版本和 `provenance`；来源分享变化不改变副本所有权。

`AssetImportRecord.status` 至少包括 `pending`、`completed`、`failed` 和 `cancelled`。只有 `completed` 记录才能被资产库检索；失败重试必须复用 `requestId` 并避免重复目标资产。

权限决策必须由执行层在写入授权、项目文档或 DGOS artifact 前重新计算；缓存的列表结果、页面按钮和本地节点状态不能作为授权依据。审计摘要只保存稳定 ID、能力、状态、主体摘要和时间，不保存秘密、私有路径、完整媒体或临时下载地址。
