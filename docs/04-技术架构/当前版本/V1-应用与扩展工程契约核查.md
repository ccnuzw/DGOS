## FR-002 唯一工程契约与一次迁移

权威顺序：D030/D029–035业务不变量 → 已接受ADR → 本应用契约/机器schema → 实现与migration事实。已有OpenAPI未定义manifest字段，不能作为代码旧枚举优先的依据。唯一新输入为 [V1-app-manifest.schema.json](V1-app-manifest.schema.json)：format=dgos-app/v1；build/dataVersion为非负安全整数；backgroundPolicy=release/keep-alive；trustLevel=standard/trusted/system；uninstallPolicy=user-removable/protected-preinstall。此工程收敛不改变业务范围。

有效trustLevel、catalogState和卸载策略由已验证发行身份/管理员授权决定。官方来源不自动等于system权限，管理员批准目录也不自动等于trusted；无额外授权时有效信任为standard。请求trusted/system但未被授予时拒绝，不静默提权。受保护预装必须有受控发行/管理员策略依据。

G在0028–0030增量迁移区间采用expand→backfill→switch；0006/0011及签名包原文/digest不改。旧trust_level的official/admin_approved/developer/approved只作为旧来源线索保存，**不得直接映射成trusted/system**；重新校验签名/授权后写新有效字段，无法证明则保持不可启动/需重新验证，不擅自删除现有数据或伪造审核。catalog_state沿用现有枚举以减少迁移。旧数字字符串build/dataVersion仅迁移阶段无损转整数；非数字/溢出记录拒绝迁移并报告，不猜测序号。none→release、allowed→user-removable、protected→protected-preinstall仅在迁移器中使用，protected还须验证发行策略；不得在新公开API长期接受旧别名。旧manifest保存原始快照用于审计；公开投影只有新语义，重新发行签名包使用新格式。

G可据此解除核心manifest字段阻塞；签名算法/包传输限制属于已授权工程选型，需G提交准确DTO和受控信任根接口供Planner登记，无需重开D030产品决策。

## FR-003 稳定身份与安全字段

现有HTTP管理operation为listSkills/installSkill/setSkillState/uninstallSkill及listMcpServices/installMcp/setMcpState/uninstallMcp，字段以OpenAPI为准。新增查询、预览和执行操作须登记后交给D使用，不通过前端直接调用内部对象。

| 字段类别 | 已冻结约束 | 不可直接推导/禁止 |
| --- | --- | --- |
| requestId / baseVersion | 重放参数一致返回原结果；参数不同冲突；状态变更按版本竞争 | 生成新requestId不能掩盖重复副作用 |
| source / packageId / skillId | source是受信目录或受控本地引用，稳定ID与展示名分离 | 安装命令、任意宿主路径、脚本或外部URL不能直接执行 |
| config / credentialStatus | 非秘密配置schema与Secret绑定分开；普通读只返回凭据状态 | config任意对象不是允许传入任意环境变量、cwd或命令的授权 |
| sourceId / operationId | 工具绑定只能来自已声明依赖与真实发现目录 | 调用者任意替换服务或工具名禁止 |
| enabled / connectionState | enabled不等于connected；缺凭据不伪造ready | 状态名需统一序列化，不能从UI开关推断 |
| runId / sequence / cancel_requested | Run先落盘后执行，事件单调，取消未确认时保持可查询中间态 | 前台Promise、单inputDigest、收到取消请求即写cancelled均不足以证明持久执行 |
