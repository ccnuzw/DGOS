# V1 手动代理秘密配置契约

2026-10-02 / P0-DOC r6。依据FR001 AC06、[ADR-0007](../../06-决策记录/ADR/0007-V1秘密管理与Provider出站安全.md)及Lead书面包.herdr/v1-proxy-provisioning-doc-r6.md，采用I候选endpoint、可选username/password、非秘密displayName和幂等receipt。唯一机器字段为[主OpenAPI](V1-openapi.yaml)的provisionManualProxy与ManualProxyProvisionRequest/Receipt。此为最小工程投影，不是实现、网络连通或发布批准。

## 唯一入口与用户流程

POST /api/v1/system/network/proxy-configurations：active且新鲜的管理员Session、system.settings.write、CSRF；API Key、普通APP、任意subject/purpose/secretRef覆盖均拒绝。只创建用途固定的代理配置，不增加用户账号、通用Secret查询/列表/导出/删除接口，不注册可由APP调用的写秘密capability。

D在网络设置页让有权管理员填写非秘密名称、代理endpoint和可选Basic账号/密码，确认提交前保持未激活。密码只在该次表单内存中，提交后清空，不持久到localStorage/URL/调试事件。通过HTTPS或满足同等身份/传输边界的本机宿主调用本接口。201后仅显示displayName及存储状态，保留返回manualProxyRef用于下一次**独立**PATCH /system/settings：{requestId,baseVersion,domain:"network",patch:{proxyMode:"manual",manualProxyRef}}。该PATCH遵既有CAS、权限及新鲜度治理，旧effectiveRoute保持、restartRequired=true；随后按已有服务重启/全实例版本确认规则激活。provisioning本身不改settingsVersion/contextVersion、不连代理/探测上游、不发Task、不确认lease、不改变路由或restartRequired。

每次新配置创建新引用，不接收旧manualProxyRef作覆盖目标。更新代理地址/密码也采用新provisioning意图→独立Settings PATCH→显式重启，旧引用在新引用保存/切换失败时保持可用。旧引用撤销遵部署既有受控Secret运维与引用保护，当前接口不擅自立即删除仍被旧进程/回滚使用的秘密。

## 输入验证及存储边界

- endpoint仅代理origin（HTTPS、主机、可选端口、可选根斜线），拒绝userinfo、query/fragment、非根路径、控制字符及非规范编码；不接受任意请求method/header、CA、TLS关闭、allowLocalFixture、allowlist、用途和环境覆盖。只在隔离测试profile允许loopback HTTP；生产不得因该接口开放HTTP。受控内网/本地代理例外须来自既有部署host/CIDR/端口/用途授权，未授权仍拒绝，不能借输入拓宽SSRF。
- username/password成对或都省略；有认证时服务端固定构造Basic，用户不提交authorization字符串。拒绝username中的冒号和两字段控制字符；不把password修剪/强转。按schema长度及UTF-8/base64总字节预算校验，避免运行时512字符上限截断。无认证时不写空Basic header。
- 使用与运行链一致的代理配置规范化和部署策略校验；保存可做受控DNS解析/策略判定但不能建立代理/目标连接。实际连接仍逐次DNS、IP pinning、TLS主机名/CA、目标host策略、重定向/超时/体积检查，保存不等于连接验证。
- endpoint及Basic材料作为SecretService拥有的一个受控配置值（内部兼容{url,authorization?}），purpose固定network-proxy、runtime subject固定system；创建者principal只作为授权/审计/幂等所有权记录。manualProxyRef由服务端随机生成proxy_标识并限制用途，知道引用不等于能读取秘密。不能将这个system域设定暴露成普通客户端可选字段。
- Secret必须能跨API/worker与正常重启保留，短时的是resolve/read句柄；不得继承内存/Redis测试put默认60秒TTL成为产品代理持久策略。若backend仅支持TTL，显式使用部署持久策略并给失效诊断，不声称永远可用。认证材料只进入Secret backend，不落业务DB JSON、普通receipt、日志、审计、错误或报告；endpoint也不回显。
- displayName是用户提供的非秘密标签；有界、去首尾空白、拒控制字符/明显URL或凭据形式。不能用endpoint/username自动生成名称；敏感检测拒绝时错误不能复述输入。服务端不能保证任意自由文字天然无秘密，UI明确只填写非秘密名称。

## 幂等、事务与补偿

幂等键为authenticated principalId+requestId。首次校验授权/字段/策略后，先持久化不可重复的prepared意图（服务端生成引用、非秘密名称/认证类型、受控请求指纹），再写Secret。指纹覆盖规范化endpoint、原始认证字节、名称和政策绑定，使用服务端受控HMAC/密钥版本，不使用可公开离线猜测密码的裸digest；指纹不返回API、不进入普通审计，密钥变更时保留验证已存在意图的能力。

同键相同输入：committed直接201重放原非秘密receipt，不重写Secret、不刷新Secret版本/期限、不重复审计；即便以后配置失效，原stored只是提交回执，不能解释为当前可连接。prepared/compensating返回409 request_conflict和requestId，重试复用原ID，不新建第二引用；同ID改变任何意图字段409 version_conflict。重放仍需当前有效新鲜Session/权限和CSRF，不靠旧receipt越权。

新引用Secret写入与业务DB不可能被假设为同一数据库事务。实现需持久化意图/恢复阶段，Secret写后验证其用途/所有权/版本可用，再在一个业务事务提交receipt与审计/outbox，成功才允许返回引用并供Settings引用。提交前的临时引用不能成为可用manualProxyRef，即便Secret里已存在。

失败处理：

| 失败窗口 | 必须结果 |
| --- | --- |
| 权限/fresh/CSRF/字段/策略失败 | 无Secret写入，无可用引用，不改设置/路由 |
| Secret put拒绝或超时结果未知 | 意图保留prepared/compensating；按唯一ref核metadata确认结果，不盲目生成新ref，503稳定脱敏错误 |
| Secret已写，DB/审计/outbox提交失败 | 不发成功receipt；对新临时ref登记可恢复撤销补偿，完成前禁止其用于Settings；旧ref不动 |
| 补偿本身失败/进程崩溃 | 持久待补偿意图可重试，恢复只处理自己生成且未committed/无活动引用的ref，不能通用扫描或清空Secret库 |
| 事务已提交，响应丢失 | 原requestId重放committed receipt，不撤销成功ref、不写第二份秘密 |
| provisioning成功，后续Settings CAS失败 | 保留新receipt供重试、旧设置/路由不变；不能误当provisioning失败撤旧秘密 |

准备/提交/补偿状态仅内部治理，不新增公开Secret状态读取API。拒绝/失败审计只含actor/requestId/固定operation/稳定错误类别及无敏感内容的结果；完整endpoint、用户名、认证header、秘密值或可猜测摘要都禁止。HTTP响应no-store，错误沿ErrorResponse脱敏，错误分类参主OpenAPI/ADR0007；503不能伪报已连接或已激活。
