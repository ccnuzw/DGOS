# V1 接口契约

本文登记 DGOS 自有版本化 API/SDK 的目标逻辑边界。HTTP 字段与响应形状以 [V1-openapi.yaml](V1-openapi.yaml) 为唯一权威；该文件已登记 V1 HTTP 的公共鉴权、错误、幂等和六个治理功能 operation，但桌面 IPC/SDK 投影仍需独立机器 schema 和契约测试，因此下表全部为 **Draft（已声明，不等于 Ready 或已实现）**。Web 目标为 HTTPS JSON + SSE，桌面投影须在独立契约冻结后保持语义一致。事务、migration、Secret 和 Provider 出站规则分别受 [ADR-0006](../../06-决策记录/ADR/0006-V1事务存储与迁移恢复.md) 与 [ADR-0007](../../06-决策记录/ADR/0007-V1秘密管理与Provider出站安全.md) 约束。DX OS Bridge、`dx-app/v2` 和外部资料仅作研究，不构成 DGOS 接口。

`dgos.project.*` 归 V2，`dgos.canvasRun.*` 归 V3，`dgos.asset.*` 归 V4，导演台/Canvas 扩展归 V5，组织协作/市场/批量任务归 V6。后续版本 operation 不得在 V1 实现状态或验收中作为已可调用操作。版本范围见[后续规划](../../02-产品与版本/后续版本/README.md)。

## DGOS API 公共规则

- APP 调用 DGOS SDK/系统 API，所有请求携带 requestId 并返回可追踪的结果。
- 权限在清单中声明；API Key 不返回给 APP。
- 所有 V1 JSON 请求使用 `requestId`；写操作重复请求必须返回第一次业务结果或稳定冲突，不得重复外部副作用；需要并发保护的资源使用 `baseVersion` 或状态条件更新。
- 首次引导/登录是公共认证入口；受保护 operation 使用可撤销 `dgosSession` 或最小权限 `dgosApiKey`。Session 是身份上下文，不等于业务授权；副作用前仍须重新计算 capability、scope 和 policyVersion。
- 错误响应统一包含 `errorKey`、安全 `message` 和 `requestId`；不得枚举主体或资源，不得返回 Secret、Cookie、Token、完整 Provider 地址、完整 prompt 或上游 body。
- Secret/API Key 仅在创建或轮换成功响应中一次性出现；持久化和普通查询只允许 digest、SecretRef、prefix、credentialState 等脱敏信息。
- 连接测试必须使用已发布 Adapter 的探测定义，经统一 ProviderEgress 执行 DNS、重定向、TLS 和出站策略检查；禁止任意 URL、私网、link-local 或云元数据探测，不隐式刷新模型目录或创建 AI Task。具体秘密句柄和出站规则见 ADR-0007。
- `AuditEvent` 只追加；高风险副作用必须与审计同事务提交或进入可恢复 outbox。清理通过 checkpoint 和引用保护恢复，不级联误删。
- Quota reservation 是调用 Provider 前的硬额度边界；`taskId+attemptId` 是用量去重键，结算可恢复但不得重发 Provider 请求。
- 模型任务使用 DGOS `dgos.aiTask.*`；Agent/Skill/MCP 执行记录使用 DGOS `dgos.agent.*` 或对应扩展执行 API，不能混用。未加 `dgos.` 命名空间的 `task.*` / `ai.task.*` 仅是外部研究资料中的旧名称，不属于本契约。
- V2 项目写入使用 DGOS Project API；协作更新携带 `baseVersion`，冲突不得静默覆盖。V6 才启用多人协作写入和冲突合并。
- Provider 连接协议通过 `ProtocolAdapterRegistry` 注册；V1 首发 `protocolType=openai-compatible`。能力协议通过 `CapabilityProtocolRegistry` 注册，使用 DGOS `dgos-capability/v1` 声明式 schema。前端只依赖统一的 Provider/Model/AI Task schema。Provider 验证与模型目录刷新是独立动作：`validate` 不隐式拉取目录，必须显式调用 `models/refresh`。
- `dgos.aiTask.events` 通过 SSE 返回脱敏事件；客户端可发送 `Last-Event-ID` 或等价游标恢复。`dgos.aiTask.get/query` 是终态权威。

## V1 系统设置与运行时上下文

`system.settings.read` 返回按域分组的 `SystemSettingsSnapshot`；`system.settings.write` 只接受一个设置域的版本化 patch，并要求 `baseVersion`，避免桌面和 Web 同时修改时静默覆盖。V1 设置域为 `appearance`、`locale`、`network`、`grid`、`privacy` 和 `appPermissions`。成功响应同时返回 `settingsVersion`、当前生效值、`restartRequired`、受影响服务和脱敏审计摘要；无效字段不得部分写入。

### 设置字段

| 域 | 公共字段 | 约束 |
| --- | --- | --- |
| `appearance` | `appearanceMode`、`windowMaterial`、`interfaceMode`、`displayScale`、`lightWallpaperRef`、`darkWallpaperRef`、`wallpaperFollowsAppearance` | `displayScale` 允许 75/100/125/150/175；壁纸引用是 DGOS 资产引用，不返回任意本地路径 |
| `locale` | `uiLocale`、`effectiveLocale`、`regionFormat`、`assistantLanguage`、`projectContentLanguage` | `effectiveLocale` 由系统回退规则计算；切换 `uiLocale` 不改写项目内容 |
| `network` | `proxyMode`、`manualProxyRef`、`effectiveRoute`、`affectedServices`、`restartRequired` | `manualProxyRef` 只接受秘密引用；响应和日志不得返回代理凭据或完整认证地址 |
| `grid` | `enabled`、`style`、`spacing`、`majorLineEvery`、`showAxes`、`snapEnabled`、`snapTolerance`、`colorToken`、`opacity` | 只定义宿主默认和语义 token；V2 画布/其他 APP 可以保存项目级可见性，但不得伪造系统设置 |
| `privacy` | capability 默认策略和审计/诊断开关的版本化策略 | 只能配置已注册 capability；`deny` 优先，`ask` 必须在副作用前确认 |
| `appPermissions` | `appId`、`subjectType`、`subjectId`、`capability`、`scope`、`decision` | “打开 APP”与 Agent 能力分开；APP manifest 声明不能直接生成 `allow` |

`dgos.system.context.read` 返回 `SystemContextSnapshot`，包含 `contextVersion`、外观、locale、脱敏网络摘要、网格默认、窗口状态和生命周期状态。应用可以订阅 `dgos.system.context.events`；事件只传递上下文变化，不传递 API Key、Cookie、代理凭据、绝对路径、内部 endpoint 或其他 APP 私有数据。断线后客户端必须重新读取快照，再以 `contextVersion` 去重事件。

`permission.check` 在每次副作用前按 `subject + appId + capability + scope` 重新计算有效决定。`permission.request` 只能创建用户确认请求，不能预先执行操作；`permission.revoke` 立即使缓存授权失效。稳定结果至少包含 `decision`、`reasonCode`、`requestId`、`policyVersion` 和脱敏审计引用。

## V1 统一 Provider 与 AI Task 事件语义

`ProviderCapabilityDescriptor` 至少包含：`descriptorVersion`、`inputs`、`outputs`、`taskModes`、`modelCatalog`、`streaming.text`、`cancellation`、`limits` 和可选的 `tools` 能力组。`tools` 必须逐模型声明支持的函数调用、工具搜索或远程 MCP 类型、参数 schema 约束和权限前置条件；它不能由供应商名称或文本生成能力推断。`protocolType` 是连接注册表键，不是前端通过展示名称推断的供应商类型。

`CapabilityProtocolRegistration` 至少包含 `schemaVersion=dgos-capability/v1`、`kind=model`、稳定 `id`、声明式 `executor`、真实业务 Intent、`operations`、`workflows` 和 `modelProfiles`。`operations` 的 `path` 是连接协议下的真实相对路径，`requestMode` 只能为文档允许的 `json`、`multipart` 或 `binary`；异步 workflow 必须分别声明 submit/query 的状态、进度、错误和结果路径，并在需要时继续 `responseMode=binary` 的 download。`dgos.model.resolve` 返回已命中的 Profile、workflow、defaults、limits、uiSchemas 和 assets。

能力协议解释器只接受 `$map`、`$concat`、`$merge`、`$coalesce`、`$cardinality`、`$dataUrlBase64`、`$keyValue` 和 `omitEmpty` 等声明式原语；禁止 `script`、`eval`、Shell、函数体、任意 URL 拼接和按模型名称猜测参数。多候选 selector 使用数组，多层数组使用 `[*]`。协议验证失败或 Model Profile 未覆盖真实模型名/兼容别名时，不能创建可执行模型目标。

`dgos.aiTask.submit` 的请求包含 `requestId`、`target`、`intent`、`input` 和可选 `options`；响应包含 DGOS 生成的 `taskId`、当前状态和 descriptor 版本。供应商任务 ID、endpoint、凭据和完整供应商响应只保存在 DGOS Provider/Secret 边界内。

`dgos.aiTask.events` 的事件类型至少为 `task.accepted`、`text.delta`、`task.progress`、`task.completed`、`task.failed`、`task.cancelled` 和 `stream.reset`。每个事件带 `eventId`、`taskId`、单调 `sequence` 和 `createdAt`；`text.delta` 只能包含当前任务可见的增量文本。客户端断线恢复后，服务端可以发送 `stream.reset` 和当前摘要，最终结果仍必须通过 `get/query` 确认。

官方 Skill/MCP 应用的管理动作都接受 `requestId` 并返回扩展记录或状态；停用、卸载和断开不会删除项目 Artifact。MCP 的明文凭据永远不出现在应用响应、SSE 事件或审计摘要中。

## 错误语义

稳定错误至少包括：权限缺失、输入不合法、协议不兼容、模型不可用、配置验证失败、凭据不可用、应用审核/目录准入失败、任务失败/取消和产物不可读（V1）；项目读写和结构迁移属于 V2，运行快照/工作流错误属于 V3，资产授权/引用/导入和供应商能力错误属于 V4，插件回滚属于 V5，规模化市场发布、协作冲突与组织级发布运营错误属于 V6。数值错误码在 DGOS API schema 冻结后登记，不能凭空编造。

资产权限的 DGOS 设计能力名为 `metadata.read`、`preview.read`、`reference.create`、`copy.import`、`metadata.edit`、`share.manage`、`delete` 和 `reshare`。这些名称在 DGOS 权限服务中作为能力边界，最终公开字符串由 DGOS API schema 冻结。所有分享、引用和导入动作都必须在执行层重新解析主体、来源资产、目标项目和 artifact 版本；页面入口或已缓存的 `allow` 不能代替校验。
