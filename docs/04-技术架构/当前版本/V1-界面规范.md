# V1 界面与交互规范

> 状态：V1 设计基线，待实现证据验证。本文规定 DGOS 平台壳层、第一方应用和第三方应用必须共同遵守的界面语义。具体组件实现位于 `packages/design-tokens`、`packages/dgos-ui`、`packages/app-shell` 和 `packages/host-adapter`。

## 1. 定位与参考边界

DGOS 是独立的应用操作系统。它需要让系统设置、应用目录、Provider、Skill、MCP、系统助手和业务 APP 看起来属于同一个系统，同时允许应用在自己的领域内表达表格、媒体、画布或其他内容。统一的是结构、状态、权限和交互语义；应用可以自定义领域内容、字段布局和专用工具。

DX OS 网站、开发者文档、视频、截图和旧项目只作为产品研究材料，来源见[DX-OS成熟软件截图证据](../../90-参考资料/DX-OS成熟软件截图证据.md)和[DX-OS开发者文档研究](../../90-参考资料/DX-OS开发者文档研究.md)。DGOS 不复制 DX OS 的品牌、颜色、私有 Bridge、协议名、运行时或视觉资产。初始 token 是 DGOS 的设计决策，后续只能通过新的 ADR 和真实 DGOS 截图证据调整。

## 2. 设计原则

1. **平台一致，领域自由**：窗口、导航、主题、权限、任务、通知、错误、国际化和可访问性由平台统一；领域数据和工具由应用负责。
2. **空间化但克制**：使用清晰的层级、留白和有限材质表达窗口与上下文，不使用大面积渐变、发光、装饰性球体或无意义动效。
3. **先可理解，再高密度**：管理页支持扫描和批量操作；首次使用的空态只说明当前状态和下一步动作，不堆叠教程文字。
4. **每个副作用都有证据**：安装、删除、外部调用、Provider 请求和长任务必须显示发起、进行中、成功、失败、取消和可恢复路径。
5. **跨端同语义**：桌面和 Web 共用路由、组件语义、快捷键名称、任务状态和 API 事件；窗口、文件选择器、钥匙串和通知等差异只能在 Host Adapter 中实现。
6. **可访问且可恢复**：键盘、屏幕阅读器、缩放、减少动态效果、断网、过期会话和权限拒绝都必须有可用路径。

## 3. Design Tokens

组件不得直接写页面级颜色、间距或 z-index。所有值通过 token 暴露，至少提供 `light`、`dark` 两套语义主题。以下为 V1 初始值，不代表已完成视觉验证。

### 3.1 色彩

| 语义 token | 浅色初始值 | 深色初始值 | 用途 |
| --- | --- | --- | --- |
| `color.canvas` | `#F5F6F8` | `#17181B` | 应用工作区背景 |
| `color.surface` | `#FFFFFF` | `#222428` | 面板、窗口内容 |
| `color.surfaceRaised` | `#FFFFFF` | `#2B2E33` | 菜单、弹层、浮动工具 |
| `color.text` | `#1D1F23` | `#F4F5F7` | 主要文字 |
| `color.textMuted` | `#69707D` | `#A8AFBA` | 次要文字 |
| `color.border` | `#D9DDE5` | `#3A3F47` | 分隔线和边界 |
| `color.primary` | `#1769E0` | `#6EA8FF` | 主操作、焦点、链接 |
| `color.success` | `#16834B` | `#55C88A` | 成功和健康 |
| `color.warning` | `#A15C00` | `#F0B45D` | 警告和待配置 |
| `color.danger` | `#C0352B` | `#FF8178` | 错误、删除、拒绝 |
| `color.info` | `#286A9E` | `#7BC4FF` | 信息和进行中 |

语义色不能只靠颜色传达含义，必须同时有文字、图标或状态标签。普通文字与背景对比度至少达到 WCAG AA 4.5:1，大号文字至少 3:1；深色主题单独验算。

### 3.2 字体、间距和尺寸

- 字体优先使用 `-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Inter", sans-serif`；Web 端保留系统回退。代码、ID、数值和日志使用等宽字体。
- 文字级别固定为 `12/13/14/16/18/22/28` px；正文默认 14–16 px，行高 1.5；不使用负字距。
- 间距采用 4 的倍数：`4/8/12/16/20/24/32/40/48`。同一组控件至少间隔 8 px。
- 控件高度为 `32`（紧凑）、`36`（标准）、`44`（触控/主操作）；交互命中区最小 `44×44` px，视觉图标可以小于命中区。
- 控件圆角 6 px，卡片 8 px，窗口 12 px。不得为了装饰把页面区块嵌套成多层卡片。
- z-index 使用 `0/10/20/40/100/1000` 层级：内容、固定工具、浮层、模态、系统提示，不允许组件自定义任意数值。

### 3.3 阴影、材质和动效

- 只定义 `shadow.none/sm/md/lg` 四级；阴影用于表达层级，不用于装饰。
- 模糊和半透明材质只用于窗口标题栏、菜单、弹层和模态背景；不用于正文卡片或整个页面背景。
- 快速反馈 150 ms，普通状态 200 ms，页面/面板 250–300 ms，任何连续动效不超过 400 ms。只动画 `transform` 和 `opacity`，尊重 `prefers-reduced-motion`。
- 动画必须表达打开、关闭、层级变化或状态因果；操作期间不阻塞输入，取消和失败可以立即打断。

## 4. 系统壳层与宿主适配

### 4.1 桌面、Web 和窗口

`AppShell` 提供系统栏、Dock/应用启动器、应用窗口、页签、命令面板、通知中心和全局错误边界。应用不能自行创建第二套窗口管理、主题或权限提示。

- 窗口支持打开、聚焦、失焦、拖动、调整尺寸、最大化、还原、关闭和恢复上次位置；多实例和多页签必须有稳定的 `windowId`/`tabId`。
- 标题栏显示应用图标、名称、当前上下文和最少量窗口操作；领域工具栏放在内容区，不把业务按钮塞进系统控制区。
- Dock/启动器显示安装状态、运行状态和未读任务提示；应用图标不承担错误详情。
- Web 端复用同一 Shell 语义，在浏览器中以可调整面板或路由窗口呈现；不假设原生菜单、钥匙串或系统通知一定存在。
- macOS 的窗口菜单、文件选择器、钥匙串、系统通知和生命周期由 `host-adapter/macos` 提供；Web 和未来 Windows 实现等价能力或明确降级状态。
- 显示倍率至少验证 75%、100%、125%、150%、175%；文本放大不得导致主操作被截断或遮挡。

### 4.2 系统上下文

平台向应用注入 `SystemContextSnapshot`：`theme`、`uiLocale`、`effectiveLocale`、`regionFormat`、`displayScale`、`reducedMotion`、`networkProxyState`、`permissionSummary` 和 `hostCapabilities`。应用可以读取和订阅上下文，但不能覆盖主题、窗口生命周期、网络出口或权限策略。

## 5. UI Kit 组件契约

`dgos-ui` 至少提供以下组件族，并为每个组件提供语义 token、键盘行为、ARIA 语义、加载/禁用/错误状态和浅深色主题。

| 组件族 | 组件 | 统一要求 |
| --- | --- | --- |
| 导航 | `AppLauncher`、`Sidebar`、`Tabs`、`Breadcrumbs`、`CommandPalette` | 当前项可见，支持键盘和深链接，返回行为稳定 |
| 操作 | `Button`、`IconButton`、`SplitButton`、`Menu`、`ContextMenu` | 每个视图只有一个主操作；图标按钮必须有可读标签和 tooltip |
| 输入 | `TextField`、`SecretField`、`Select`、`Combobox`、`Checkbox`、`Switch`、`Slider` | 标签不依赖 placeholder；字段错误就近显示；秘密默认脱敏 |
| 数据 | `DataTable`、`List`、`Tree`、`PropertyList`、`StatusBadge` | 长列表虚拟化；状态同时显示文字；数值采用等宽/表格数字 |
| 反馈 | `Toast`、`InlineAlert`、`Dialog`、`Sheet`、`Progress`、`Skeleton` | toast 不承载唯一错误信息；危险操作提供取消和确认 |
| 内容 | `EmptyState`、`ErrorState`、`MediaPreview`、`CodeBlock`、`LogViewer` | 保留恢复动作、复制入口和稳定尺寸，避免布局跳动 |
| 布局 | `WindowFrame`、`Toolbar`、`Inspector`、`SplitPane`、`ScrollRegion` | 明确滚动归属；固定区域预留内容空间，不覆盖主要操作 |

不使用 Emoji 作为图标；统一采用 Lucide 或具有同一笔画规则的 SVG 图标。纯图标命令必须有 accessible name，陌生命令在 hover/focus 时提供 tooltip。

## 6. 交互状态和通用流程

所有可交互元素至少支持 `rest/hover/focus/pressed/disabled/loading/error`；状态变化应有可见差异且不能只靠颜色。焦点环至少 2 px，键盘顺序遵循视觉顺序；拖放必须有键盘替代路径。

### 6.1 页面状态

| 状态 | 规范 |
| --- | --- |
| 加载 | 首屏超过 300 ms 显示稳定骨架；超过 1 s 显示进度或可取消状态；保留布局尺寸 |
| 空态 | 说明当前没有数据、原因和一个下一步动作；不把空态写成营销文案 |
| 失败 | 就近展示原因、`request_id/taskId`、恢复/重试/联系支持入口；不覆盖已有结果 |
| 成功 | 显示终态、结果摘要和下一步动作；长任务保留打开详情、取消或下载入口 |
| 无权限 | 说明所需能力、当前策略和申请入口，不泄露资源内容 |
| 断网/过期 | 保留本地输入和已完成结果，提供重连、刷新或重新认证 |

### 6.2 表单、秘密和危险操作

- 表单在提交前校验必填、格式、能力和权限；错误贴近字段，提交失败保留用户输入。
- `SecretField` 默认显示已保存/未保存状态和末尾脱敏信息，不回填 API Key；复制、替换、删除都必须经过秘密边界。
- Provider、Skill、MCP 的连接、安装、启用和更新显示明确阶段；重复点击在服务端幂等保护下仍要给出进行中反馈。
- 删除、卸载、清除数据、撤销授权、外部发送和不可逆导出必须二次确认，说明影响范围；若可恢复，优先进入回收站或撤销状态。
- 右键菜单是快捷入口，不是唯一入口；关键动作也必须能从可见按钮或命令面板触发。

### 6.3 异步任务和通知

任务统一显示 `queued/running/paused/succeeded/failed/canceled`，展示进度（若可得）、开始时间、来源应用和稳定任务 ID。SSE 断开后显示连接状态并通过查询恢复，不能把客户端断线当成任务失败。通知只摘要变化，详情页是唯一真源。

## 7. 页面信息架构

管理型页面采用：应用标题与说明 → 页面级主操作 → 搜索/筛选 → 分组列表或表格 → 详情/编辑面板 → 状态和审计信息。左侧分类导航在宽屏固定，窄屏转为抽屉或选择器；长页面的底部保存栏不能遮挡内容。

V1 页面统一如下：

| 应用 | 页面重点 | 平台/应用边界 |
| --- | --- | --- |
| 应用目录 | 已安装、可用、更新、启动和卸载入口 | 平台管理生命周期，应用提供 manifest 展示信息 |
| 系统设置 | 外观、语言地区、网络代理、隐私安全、网格、APP 权限 | 平台写入 `SystemContextSnapshot`；应用只维护内容偏好 |
| Provider/模型 | Base URL、协议、API Key、验证、拉取模型、能力分类、启用和默认模型 | 平台管理连接/秘密/模型目录；协议中心只对开发者开放 |
| Skill | 安装、来源预览、依赖、启用/停用、权限和版本 | 平台执行和审计，Skill 提供声明和领域界面 |
| MCP | 模板、端点、凭据状态、连接/重连、工具发现和删除保护 | 平台隔离秘密和连接，应用消费结构化工具引用 |
| 系统助手 | 动作搜索、自然语言候选、确认、执行、任务历史 | 只能调用 Action Registry 注册且通过权限检查的动作 |
| DGOS AI 工作台 | 模型选择、动态参数、提示输入、流式输出、任务详情和结果 | 应用负责内容；平台负责 Provider、Task、权限和事件 |

V1 的主导航和应用目录应让上述应用可互相深链，但应用不得通过 URL 直接绕过权限或启动副作用。

## 8. 未来版本继承规则

- **V2 项目与画布基础**：继承窗口、主题、命令面板、历史、权限和任务状态；画布可定义点阵、缩放和小地图 token，但不得重定义系统颜色、窗口或权限。
- **V3 画布工作流**：节点必须有稳定尺寸、标题、端口、选中/运行/错误/结果状态；连线反馈、右键菜单、整理算法和撤销均使用 UI Kit 的状态和确认模式。
- **V4 表格、资产、Agent、供应商节点**：表格继承 DataTable 的字段、排序、筛选、并发和错误语义；资产继承来源、授权、版本和导入状态；Agent 和供应商节点继承 Task/Permission/Secret 边界。
- **V5 3D 导演台与扩展**：导演台可拥有独立工具栏和场景区，但通过 `WindowFrame`、`Inspector`、`Progress`、`MediaPreview` 与 Shell 交互；插件 UI 只能使用公开 UI Kit 和 manifest 允许的主题 token。
- **V6 协作和市场**：成员、组织、分享、评论和发布状态沿用统一主体、权限、通知和审计显示；协作冲突不能只用颜色表示。

## 9. 国际化、无障碍、安全和性能

- 支持中文和英文资源；所有用户可见字符串必须有稳定 message key，日期、时间、数字和区域格式使用 `regionFormat`。界面语言变化不自动翻译项目内容、文件名、Skill 或应用私有数据。
- 支持键盘完整操作、VoiceOver/屏幕阅读器、可见焦点、动态字号、`prefers-reduced-motion` 和高对比度。不能依赖 hover、颜色、拖拽或精确点击完成关键操作。
- 所有外部 URL、绝对路径、API Key、Cookie、MCP 凭据和内部 endpoint 按秘密/隐私规则脱敏；日志、toast、截图证据不得泄露秘密。
- 首屏和路由页面按功能拆包；大于 50 行的列表虚拟化；图片/视频预览使用稳定宽高或 `aspect-ratio`；异步内容预留空间，避免布局跳动。
- Web 端不得禁用缩放，不得产生主要内容的水平滚动；窄屏将侧栏、检查器和工具栏折叠为可恢复面板。

## 10. 应用 manifest 的 UI 预留字段

应用 manifest 可声明以下非强制 UI 信息，由平台校验和展示：`displayName`、`icon`、`accentColor`（只能引用允许的语义 token）、`preferredWindow`、`minWindowSize`、`routes`、`deepLinks`、`supportedLocales`、`commands`、`settingsSections` 和 `uiCapabilities`。manifest 不得声明覆盖系统主题、系统字体、窗口生命周期、权限提示或任意 CSS/脚本执行能力。

应用可以提供领域级 token（例如画布节点颜色、表格列宽），但必须引用平台基础 token，并在浅色、深色、缩放和国际化下通过校验。

## 11. 实现分层与验证

| 层 | 职责 |
| --- | --- |
| `packages/design-tokens` | 主题、语义色、字体、间距、尺寸、层级、动效、国际化基础 token |
| `packages/dgos-ui` | 可访问组件、状态机、ARIA、键盘行为、组件文档和视觉测试 |
| `packages/app-shell` | 窗口/页签、导航、Dock、命令面板、通知、任务中心和错误边界 |
| `packages/host-adapter` | macOS Tauri、Web、未来 Windows 的文件、窗口、钥匙串、通知和生命周期差异 |
| 应用包 | 领域路由、数据和工具；通过 SDK/公开 UI Kit 使用平台能力 |

### UI 验收标准

| ID | Given/When/Then | 证据要求 |
| --- | --- | --- |
| UI-AC-001 | Given 浅色或深色主题，When 打开任一第一方应用，Then token、焦点、状态和层级一致 | 组件视觉快照 + 主题切换记录 |
| UI-AC-002 | Given macOS 桌面或 Web，When 打开同一应用路由，Then 业务语义、任务状态和错误 ID 一致 | 双宿主 E2E + 路由/事件记录 |
| UI-AC-003 | Given 键盘、VoiceOver 或缩放用户，When 完成主流程，Then 所有关键控件可达且无截断/遮挡 | Playwright 可访问性扫描 + 手工键盘/VoiceOver 记录 |
| UI-AC-004 | Given Provider、Skill 或 MCP 的异步副作用，When 提交、断线、失败或取消，Then 显示可追踪状态和恢复路径 | 任务事件、截图和错误恢复 E2E |
| UI-AC-005 | Given manifest 声明非法颜色、窗口或权限覆盖，When 安装/加载应用，Then 平台拒绝并说明字段 | manifest 校验报告 |
| UI-AC-006 | Given 75%–175% 显示倍率和中英文，When 浏览 V1 页面，Then 主操作、表单错误和底部操作不重叠 | 多倍率/语言截图证据 |
| UI-AC-007 | Given V2–V5 领域应用，When 使用画布、表格、媒体或 3D 工具，Then 领域自定义仍遵守 Shell、UI Kit、Task、Permission 和 Secret 契约 | 各版本专项 E2E 与组件契约测试 |

本规范只冻结设计系统和交互语义；组件像素级视觉回归、真实 Tauri/Web 截图、Windows 适配和应用插件 SDK 属于实现阶段证据，不得在没有证据时标记为完成。
