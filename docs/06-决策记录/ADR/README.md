# V1 架构决策记录

ADR 记录影响多个功能、长期维护或高风险实现的架构决策。[冻结决策](../V1-冻结决策.md)继续冻结全部业务口径；ADR 为其中需要解释背景、备选方案和后果的架构决策提供完整论证。

## 状态

`Proposed → Accepted → Superseded / Deprecated`

已接受的 ADR 不直接覆盖产品、接口或数据文档。决策改变时先新增 ADR 或把原 ADR 标为 Superseded，再同步更新受影响文档、追踪矩阵和实现。

决策尚未完全冻结时可用“拟采用”并列出未决项与适用范围，但不得据此宣称实现或上线完成。

## 常见类型

| 类型 | 结构侧重 |
| --- | --- |
| 技术选型 | 背景 / 备选方案 / 决策 / 后果 / 验证 |
| 一致性边界 | 背景 / 决策（不变量）/ 验收与故障处理 / 验证 |
| 修复边界 | 背景 / 风险排序 / 决策与不变量 / 验证证据要求 |

## 模板

```markdown
# ADR-NNNN 标题

- 状态：Proposed / Accepted / Superseded / Deprecated
- 日期：YYYY-MM-DD
- 决策人角色：
- 关联需求/决策：

## 背景
为什么必须做这个决策，约束和风险是什么。

## 备选方案
列出至少两个真实可选方案及其优缺点。

## 决策
选择什么，以及为什么。

## 后果
正面后果、代价、运维影响和后续触发重新评估的条件。

## 验证
用什么测试、指标或发布证据证明决策被正确实现。
```
