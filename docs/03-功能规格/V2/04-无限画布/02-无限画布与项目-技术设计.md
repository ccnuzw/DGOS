# 02 无限画布与项目：技术设计

来源：[功能主文档](01-无限画布与项目.md)。本文为历史跨版本 Draft 设计，只有基础图编辑分支属于 V2 规划；节点运行和导演台分支分别以 V3/V5 规划为准。

## 单元契约

### 端口与边数据结构

| 结构 | 字段 | 约束 |
| --- | --- | --- |
| `PortDefinition` | `portId`、`direction`、`dataType`、`semanticType`、`acceptedMimeTypes`、`cardinality`、`required`、`dynamic`、`order` | `portId` 在节点生命周期内稳定；`direction` 为 `input` 或 `output`；`order` 只影响显示/批量排序 |
| `Connection` | `connectionId`、`sourceNodeId`、`sourcePortId`、`targetNodeId`、`targetPortId`、`edgeKind`、`createdAt` | 两端节点和端口必须存在；`edgeKind` 为 `data` 或 `control`；同一端口对只能有一条边 |
| `NodeTypeDefinition` | `type`、`ports`、`accepts`、`allowsCycles` | `ports` 为静态端口定义；动态端口由节点实例创建并继承类型约束 |

节点实例还必须分离保存以下状态域：

| 状态域 | 典型字段 | 持久化规则 |
| --- | --- | --- |
| `config` | 平台、模型、提示词、比例、分辨率、质量、Skill 和节点 schema 版本 | 用户配置版本化保存；不得保存 API Key、供应商私有 endpoint 或临时上传路径 |
| `inputState` | 端口槽位、来源顺序、手工值覆盖状态、缺失输入 | 由端口和边计算出的可解释状态；连接来源优先于同义手工值时必须显示原因 |
| `runState` | `idle`、`blocked`、`queued`、`running`、`done`、`failed`、`stopped`、`requestId`、错误摘要 | 只保存用户可见终态和当前批次摘要；运行中临时轮询游标不得成为项目结构依赖 |
| `outputRefs` | `artifactId`、运行批次、媒体类型、预览元数据 | 只保存稳定 artifact 引用和必要元数据；同一 artifact 幂等去重，历史批次不覆盖 |
| `layoutState` | `x`、`y`、`w`、`h`、折叠态、组成员关系 | 与业务配置分离；复制或导入时可重映射位置，不复制运行态 |

`dataType` 的 V2 基础枚举为 `text`、`prompt`、`image`、`video`、`audio`、`file`、`table`、`artifact`、`control`。不得用无约束的 `any` 代替类型；适配器若接受多个类型，必须在 `accepts` 中显式声明。

### 端口方向、基数与兼容矩阵

1. 只能从 `output` 连接到 `input`。从输入端拖出时，落点必须反转为目标输出到当前输入；两端同为输入或同为输出一律拒绝。
2. `cardinality=one` 的输入最多一条连接；已有连接时，默认拒绝并提示“输入已占用”，不得静默替换。替换必须是独立的“替换输入”命令并产生可撤销记录。
3. `cardinality=many` 的输入允许多个来源；来源顺序由 `order` 和连接创建顺序共同持久化，用户重排只改变边顺序，不改变端口 ID。
4. `required=true` 只影响节点可运行状态，不阻止节点先被创建；缺失必填输入时显示缺口，不自动运行。
5. `dynamic=true` 的输入端口只能通过节点类型定义的端口工厂创建。工厂先生成稳定 `portId` 并写入节点，再写入 `Connection`；任何一步失败都回滚。

| 输出 `dataType` | 可连接的目标输入 | 条件 |
| --- | --- | --- |
| `text` | `text`、`prompt` | 目标明确声明接受该类型 |
| `prompt` | `prompt`、`text` | 目标声明允许提示词转文本时才适配 |
| `image` | `image`、`file`、`artifact` | MIME 必须满足目标白名单；`file` 目标须声明可读图像 |
| `video` | `video`、`file`、`artifact` | 同上，禁止把视频隐式当图片 |
| `audio` | `audio`、`file`、`artifact` | 同上，需声明音频能力 |
| `file` | `file`、`artifact` | 只按 MIME/能力适配，不按文件名猜测 |
| `table` | `table`、`artifact` | `artifact` 目标须声明结构化表格读取能力 |
| `artifact` | 目标声明的具体类型 | 必须检查 artifact kind、版本和读取权限 |
| `control` | `control` | 只能形成流程/触发边，不承载媒体数据 |

典型节点端口（可被节点定义扩展）：

| 节点 | 输出端口 | 输入端口 |
| --- | --- | --- |
| 文本节点 | `text.out` (`text`) | 无 |
| 上传文件/资产节点 | `asset.out` (`file` 或具体媒体类型) | 无 |
| 生成卡片 | `result.out` (`artifact`) | `prompt.in` (`prompt`, one)、`reference.in-*` (`image/video/audio/file`, many)、`control.in` (`control`, one) |
| LLM 节点 | `text.out` (`text`)、`control.out` (`control`) | `prompt.in` (`prompt`, many)、`context.in-*` (`text/table/artifact`, many)、`control.in` (`control`, one) |
| 多维表格 | `table.out` (`table`) | `rows.in` (`table`, many)、`control.in` (`control`, one) |

### 节点类型运行契约

1. **内容节点**只产生引用或可编辑内容，不直接创建 `dgos.aiTask.*`。上传文件先经过 MIME、大小、读取权限和 artifact 登记，节点保存 `artifactId`；媒体编辑每次生成新 artifact，并保留 `derivedFrom` 关系。
2. **分组/提示词组**是复合来源节点。组成员按 `items[]` 顺序提供输入，组边与成员边不能同时把同一来源重复送入同一目标端口；组边接管和拆分必须是可撤销事务。
3. **循环节点**的 `count` 范围为 1–100，`mode` 为 `serial|parallel`，图片批量大小和起始序号必须显式保存；提示词循环的 `《计数》` 展开在运行快照中完成，不能依赖前端渲染文本。
4. **执行节点**运行前生成不可变 `RunSnapshot`：节点配置版本、输入 artifact、端口顺序、能力版本、循环轮次和幂等键都从快照读取。模型/插件字段必须由能力 schema 校验。
5. **结果节点**按 `runId` 追加输出，不以“最新 URL”覆盖历史。结果拖回画布只创建新的引用节点或 artifact 引用，不能把预览 URL 当作项目文件路径。
6. **级联运行**沿合法数据边收集上游执行节点，使用确定性拓扑顺序；失败时停止未开始节点，保留已完成节点的结果，并用相同运行批次支持从失败节点重试。停止必须由 DGOS AI Task 服务确认，前端取消按钮不能自行伪造终态。

### 分组、选择集与工作流迁移

- 将内容节点放入组时，先计算受影响的目标集合，再生成 `GroupAdoptionPreview`，列出将被收敛的边、保留的边和端口顺序；确认后一次写入组成员和边变更。
- 选中集快捷连接可以把图片/提示词临时聚合成复合来源，但预览必须展开成员 ID、来源顺序和最终端口映射。临时聚合节点若未被提交，不得留下项目 ID。
- Alt/Option 复制和工作流导入必须建立完整 `idMap`：节点、端口、边、组成员、运行批次和内部 artifact 引用分别处理；运行态、任务 ID、临时 URL 和外部私有路径清空或剔除。
- 导出包包含 `schemaVersion`、节点类型版本、端口定义快照、边清单、组成员和资源清单。结构 JSON 与资源包均需在导出前执行秘密、权限和引用闭包检查；导入采用“解析—校验—预览—提交”四步，提交失败不改变当前画布。

旧项目的 `connections[{from,to,kind}]`、`inputNodeIds` 和 `sourceNodeId` 只作为迁移输入；新项目保存时必须归一为 `sourceNodeId/sourcePortId/targetNodeId/targetPortId`，不能把旧字段当作新运行时契约。

### 图不变量与失败语义

- 禁止自连接、重复连接、端口不存在、节点不存在、方向错误、类型/MIME/能力不兼容。
- 默认项目图为 DAG。只有节点类型显式 `allowsCycles=true` 且环路边属于其专用控制端口时，才允许环；数据端口不得形成环。
- 所有图编辑命令先在内存副本执行完整校验，再以一次项目文档版本写入；校验或保存失败时回滚整个命令。
- 删除节点先删除关联边，再删除节点；任何保存后的文档都不得包含悬空边。
- 不兼容来源必须返回稳定原因类别：`direction_mismatch`、`type_mismatch`、`mime_not_accepted`、`input_occupied`、`duplicate_connection`、`cycle_detected`、`layout_conflict`、`missing_node_or_port`、`permission_denied`。

### 连接手势与旧项目行为参考

新项目的鼠标/触控实现必须把端口拖拽、节点边缘落点和视频观察到的双击连线续接统一转换为同一个 `previewConnection` 调用，之后才允许写入边。空白处释放只有在源端口声明了默认下游类型时才创建目标节点，否则取消操作。目标节点主体的左右侧推断只能作为视觉辅助，若两侧均不明确则取消连接。

旧项目代码提供以下行为证据，但不构成新契约：

- `canAutoConnectDraggedNode` 只允许单节点、带修饰键拖拽并与目标重叠时自动连接；图片可到图片/循环/提示词，提示词可到图片/循环，循环可到图片，分组可到图片/循环；历史组和分组目标被排除。
- `connectInputNode` 会按来源内容为循环节点打开图像或提示词输入，再写入输入关系；`addConnection` 以 `from/to/kind` 去重。
- 下游遍历沿 `input/flow` 边递归并用画布 `x/y` 稳定排序；输入来源重排同时维护来源顺序和相关边槽位。
- 合并节点会重写入边/出边并去重，删除节点会先清理相关边。这些行为在新项目中分别由端口校验、排序字段和项目事务替代。
- 旧项目将现有连线的双击绑定为删除连线，与视频观察到的双击续接目标不同；不得把该实现直接迁移为 DGOS 交互。

### `整理连接节点`

| 函数 | 前置条件 | 返回 | 副作用 |
| --- | --- | --- | --- |
| `arrangeSelectedConnections(document, selectedNodeIds, options)` | 选中 ID 去重；节点和边可读；布局间距为正 | `LayoutPreview` 或稳定错误 | 成功时只写选中节点的 `x/y`，产生一个可撤销版本 |

算法规则：

1. 取选中集 `S`，只构建内部边 `E(S)={e | source,target∈S}`；未选中节点及其位置不参与移动。跨边保留原样，不能被重定向。
2. 对 `E(S)` 做 Kahn 拓扑排序。根节点入度为 0，根层为 0；其他节点层级为所有内部前驱层级最大值加 1。
3. 若无法消费全部节点，选中子图含环；返回 `cycle_detected`，不提交任何坐标变化。不会通过把节点强行排在同一层来掩盖环路。
4. 层内稳定排序键依次为：与上一层相邻节点的纵向重心、节点当前 `y`、稳定 `nodeId`。无前驱的并列根使用当前 `y`、`nodeId`。
5. 横向按层放置，默认 `columnGap=80` 个画布单位；纵向从上到下放置，默认 `rowGap=28`，节点尺寸取当前尺寸。每层的 `x` 为该层前一层最大右边界加 `columnGap`；每个节点先按相邻前驱的纵向重心生成候选 `y`，再按已排序节点的上一个底边加 `rowGap` 向下推移。
6. 计算预览后检查选中节点之间以及选中节点与未选中固定节点之间的矩形不重叠、端口仍在节点边界内、组成员关系不变；若固定节点导致无法满足间距，返回 `layout_conflict` 而不是移动未选中节点或提交重叠布局。
7. 提交只包含 `{nodeId, before:{x,y}, after:{x,y}}`，不创建/删除/重定向边，不改变节点尺寸、端口定义、组关系、任务状态或 artifact 引用。

### `连接下游节点`

| 函数 | 前置条件 | 返回 | 副作用 |
| --- | --- | --- | --- |
| `previewDownstreamConnection(document, selectedNodeIds, targetType)` | 目标类型存在；选中节点可读 | `ConnectionPreview` | 无写入 |
| `commitDownstreamConnection(document, previewId, mode)` | 预览未过期；文档版本未变化；用户明确确认模式 | 新文档版本和连接摘要 | 原子创建目标节点、动态输入端口和边；不运行任务 |

确定性步骤：

1. 目标类型只允许产品已登记的下游类型，例如 `generation-card` 或 `llm`；当前选中集按画布 `x`、`y`、稳定 `nodeId` 排序。
2. 对每个源节点枚举其 `output` 端口，按端口定义 `order` 排序；对目标静态输入端口计算方向、数据类型、`semanticType`、MIME、读取权限和基数约束。
3. 为每个兼容候选生成映射。一个源端口只能映射到一个目标端口；`many` 输入可为多个源创建稳定的动态端口。目标端口选择按声明顺序，其次按源排序键稳定决胜。
4. 若存在不兼容来源，预览必须逐项显示原因。默认模式 `strict` 要求全部选中来源兼容；显式模式 `compatible_only` 才允许只提交兼容项，不能静默丢弃来源。
5. 预览阶段拒绝自连接、重复边、单值输入占用、数据环路和权限不足；预览 ID 绑定文档版本，版本变化后必须重新预览。
6. 提交时开启项目文档事务：创建目标节点；为每个动态输入调用端口工厂并持久化端口 ID；校验并创建边；再次验证无悬空边和非法环；成功后一次提交。任一步失败则回滚目标节点、端口和所有边。
7. 新目标节点默认处于 `idle`/`blocked`（按必填输入情况）状态，不自动创建 `dgos.aiTask.*`；用户随后点击运行才提交任务。

### 伪代码

```text
function arrangeSelectedConnections(doc, selectedIds, opts):
    S = stableUnique(selectedIds)
    REQUIRE all(id in doc.nodes for id in S)                         // B04-01
    E = internalEdges(doc.connections, S)                            // B04-02
    layers = deterministicTopologicalLayers(S, E)                    // B04-03
    IF layers.hasCycle: RETURN Err("cycle_detected")                 // B04-04
    positions = placeLayers(layers, doc.nodes, opts.columnGap, opts.rowGap) // B04-05
    ASSERT noRectOverlapWithFixedNodes(positions, doc.nodes)          // B04-06
    ASSERT connectionsAndPortsUnchanged(doc, positions)              // B04-07
    BEGIN TRANSACTION                                                 // B04-08
      writeOnlyNodePositions(doc, positions)
      COMMIT OR ROLLBACK
    RETURN LayoutPreview(positions)

function previewDownstreamConnection(doc, selectedIds, targetType):
    REQUIRE nodeTypeExists(targetType)                               // B04-09
    sources = sortNodesByCanvasPosition(doc, selectedIds)             // B04-10
    candidates = enumerateCompatibleMappings(sources, targetType)    // B04-11
    IF candidates.hasSelfLoop OR candidates.hasCycle:                 // B04-12
        candidates.addError("cycle_detected")
    RETURN previewWithReasons(candidates)

function commitDownstreamConnection(doc, preview, mode):
    REQUIRE preview.baseVersion == doc.version                       // B04-13
    REQUIRE mode in ["strict", "compatible_only"]                  // B04-14
    IF mode == "strict" AND preview.errors: RETURN Err(preview.errors)
    BEGIN TRANSACTION                                                 // B04-15
      target = createNode(preview.targetType)
      FOR mapping IN preview.acceptedMappings:
          port = ensureDynamicInputPort(target, mapping.targetSpec)   // B04-16
          createConnection(mapping.source, port)                     // B04-17
      ASSERT graphValid(doc)                                          // B04-18
      COMMIT OR ROLLBACK
    RETURN target
```

## 3D 导演台专项边界

3D 导演台的产品与数据语义见[3D 导演台专项](../../V5/04-无限画布/03-3D导演台专项-技术设计.md)。通用画布技术设计只登记以下集成边界：

- 导演台作为一个节点实例保存独立 `directorProject` 引用；项目内部的场景对象、机位、时间线和关键帧由导演台领域模型管理，不能把每个 3D 对象伪装成普通画布节点。
- 全景图输入必须通过稳定端口和 artifact 引用进入，保留投影模式和来源边；解除连接是一次图编辑事务，已回写截图/视频不受影响。
- 截图和导出使用不可变 `DirectorRunSnapshot`，包含场景版本、活动机位、时间线版本、输出尺寸/FPS 和可见能力；结果按运行批次追加到 `outputRefs`。
- 本地模型缺失、能力握手失败、渲染取消和导出失败都进入可解释状态；不得把中间 Blob、临时 URL 或浏览器缓存 key 写入可迁移工作流包。
- 画布回写通过稳定 artifact 和新节点/边完成，不能依赖导演台 iframe、内部消息或节点仍然存在；具体 DGOS Project API 待确认。

## 约束备注

布局算法是纯函数加一次 DGOS 项目版本写入；随机数、当前渲染顺序和供应商返回顺序不得影响结果。端口和边的最终约束必须在项目写入层再次校验，前端高亮只能改善交互，不能作为安全或完整性依据。旧项目中自动拖拽兼容的图片/提示词/循环节点映射只能作为行为参考；新项目必须由 `NodeTypeDefinition` 显式声明。多人协作冲突合并暂不冻结，版本冲突按 `dgos.project.version_conflict` 失败并要求重新预览。
