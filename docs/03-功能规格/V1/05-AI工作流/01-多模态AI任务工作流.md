本主文档的验收范围只有 V1 工作台线性文本任务的提交、状态追踪、SSE 和产物预览。跨版本方向见 [V3 规划](../../../02-产品与版本/后续版本/V3-规划.md)和 [V4 规划](../../../02-产品与版本/后续版本/V4-规划.md)；历史编号保留但后续行为不属于本版 AC。

## 目标

用户可以在 DGOS AI 工作台按模型能力返回的动态参数提交文本任务，追踪同一任务并展示结果。

## 功能边界

V1 包含：模型目录/握手、文本任务、基础输入校验、异步提交/查询/取消、失败重试、结果读取和展示；文本任务必须支持 SSE 流式增量输出。图片、视频、音频任务的公共契约可以在 V1 预留，但不计入 V1 首发验收。

V3 画布节点与 V4 多媒体/供应商方向仅在各版规划中维护，本版不定义其执行行为或验收。

不包含：供应商 endpoint 拼接、API Key 管理、计费、模型训练和私有旧 Canvas API。

## 来源与追踪

- 需求：`V1-FR-005`

## 完成定义

V1 至少一条真实 `openai-compatible` 文本链路通过 DGOS AI 工作台和 `dgos.aiTask.*` 完成提交、SSE 增量、断线恢复、终态查询和结果展示；失败、取消和重复提交可验证。V3 再补充画布回写，V4 再补充图片/视频/音频、供应商节点和高级工作流。

## 需求说明

### 用户故事

作为用户，我希望在 DGOS AI 工作台提交文本提示词并看到流式输出、进度与结果，以便确认任务闭环。

### 业务规则

1. 提交前必须使用 `dgos.model.resolve` 返回的动态参数和输入约束；平台和模型不能由 UI 写死为供应商名单。
4. 同一逻辑重试复用 requestId；pending 只轮询 DGOS 返回的 taskId。
5. 文本任务的增量内容通过 `dgos.aiTask.events` 的 SSE 事件发送；增量事件只表达当前任务的可见输出，不包含 Provider 私有响应、API Key、内部 endpoint 或供应商任务 ID。
6. SSE 断线后，客户端可用 `Last-Event-ID` 或等价游标重新订阅，也可通过 `dgos.aiTask.get/query` 恢复当前增量摘要和最终终态；旧事件不能覆盖已写入的终态。
7. 成功结果通过 artifactId 读取，本版仅在任务工作区预览；应用不得把预览 URL 当作稳定产物引用。

### 前置依赖与执行边界

本功能依赖已验证且启用的 Provider/Model 配置（`V1-FR-007`）、Permission、AI Task 服务、Worker、Artifact 服务和 SSE 事件网关。提交前必须确认主体有任务权限、模型 Profile/能力 descriptor 匹配 `text.chat`、输入通过机器 schema、Provider 状态为可用，并由服务端生成或复用 `requestId`。Provider endpoint、凭据、供应商任务 ID 和完整响应只属于 Provider/Secret 边界；工作台只能使用 DGOS operation 和脱敏事件。V3/V4 画布、媒体和复杂工作流不是 V1 的前置依赖。

### 主流程

1. 获取模型目录并按能力筛选。
2. 握手得到执行模式、参数和输入 schema。
3. 提交任务，进入 pending。
4. 订阅事件推进任务和文本增量；断线时通过游标或查询恢复，再推进到 succeeded/failed/canceled。
5. 读取 artifact，在任务工作区预览并提供重试或取消入口。

### 异常与边界

- 模型 unavailable/legacy：禁用运行并提示配置问题。
- 网络错误：继续使用原 taskId 查询，不新建重复任务。
- 产物读取失败：保留任务终态和错误，不伪造结果节点。
- 文本输入不符合握手 schema：阻止提交并指出具体字段，不创建任务。

### 页面与交互

V1 DGOS AI 工作台展示文本 intent、模型、动态参数、任务状态、进度、重试/取消、SSE 输出和结果展示。

### 领域数据语义

任务由 DGOS Permission、AI Task 和 Worker 服务负责鉴权与执行；本版任务记录保存 prompt 摘要、taskId、artifactId、状态和用户可见错误。

### 本版本不做

不承诺所有供应商和所有模型均可用；以当前模型目录和握手结果为准。API 渠道、Base URL、API Key 归 `V1-FR-007`；画布回写属于 V3，ComfyUI 工作流、供应商节点和生成历史属于 V4。

V1 不做画布回写、ComfyUI/GPU 工作流、复杂多图输入编排和生成历史；这些能力在 V3/V4 以独立 E2E 验收。

## 接口契约

`dgos.model.list/resolve`、`dgos.aiTask.submit/query/get/events/cancel`、`dgos.artifact.read`；`events` 使用 SSE 或等价单向事件订阅；不允许新增供应商私有 URL。

### 接口清单

| 能力 | 方向 | 业务约束 |
| --- | --- | --- |
| 提交 AI Task | 写 | 校验模型能力、权限和幂等 requestId |
| 查询任务 | 读 | 终态不可被旧轮询覆盖 |
| 订阅事件 | 读/流 | 断线可重连，事件顺序可审计 |

### OpenAPI operation 映射

| 业务能力 | operationId | 当前状态 |
| --- | --- | --- |
| 提交任务 | `submitAiTask` | V1 OpenAPI 已声明 |
| 查询任务 | `getAiTask` | V1 OpenAPI 已声明 |
| 订阅任务事件 | `streamAiTaskEvents` | V1 OpenAPI 已声明 |

### 逐操作契约约束

请求字段、响应字段和 SSE event schema 只以 [V1-openapi.yaml](../../../04-技术架构/当前版本/V1-openapi.yaml) 为权威；下表补充任务业务终态和运行治理。

| operationId | 前置条件 | 成功终态 | 关键失败与无副作用 | 幂等 | 并发 | 重试/超时 | 观测/恢复 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `submitAiTask` | 主体有 task 权限、模型可用、输入通过 descriptor/schema | 返回唯一 `taskId`、`requestId` 和 `queued/running` 状态 | 输入/权限/Provider 失败不创建 Task、不调用上游、不写 Artifact | `requestId + subject + target + inputDigest` 唯一；重复返回原 taskId | 同一 requestId 加唯一约束；不同 requestId 是否并发由配额决定 | Provider 调用 2 次指数退避，10s 预算；超时收敛 `timeout` | requestId/taskId、调用次数、状态指标；失败可查询/取消 |
| `getAiTask` | 任务属于当前主体且 taskId 存在 | 返回权威任务快照和唯一终态 | 越权不返回 prompt、结果或 Provider 字段，不改变任务 | 不适用：只读；替代验证：同 taskId 终态只读一致 | 终态版本条件读取，旧轮询不得覆盖新状态 | GET 可重试 2 次、2s；服务不可用返回稳定错误 | requestId/taskId、读取审计；继续轮询或人工处理 |
| `streamAiTaskEvents` | 任务属于当前主体且订阅权限有效 | 按 eventId/sequence 返回脱敏增量和终态事件 | 断线不创建新任务、不重复调用 Provider、不泄露凭据 | 不适用：订阅；替代验证：Last-Event-ID/sequence 去重 | 事件按 taskId 单调 sequence；终态后不再倒退 | 断线按 1s/2s/4s 重连，5s 连接预算；不得重复提交 | requestId、连接/事件序号/断线指标；重连后 query/get 校准 |

### 错误矩阵

| 场景 | error_key/结果 | 处理要求 |
| --- | --- | --- |
| 模型或输入不支持 | `invalid_request` | 提交前返回可解释字段错误 |
| Provider 不可用 | `provider_unavailable` | 任务不进入成功态，允许重试 |
| 任务取消/超时 | `cancelled` / `timeout` | 保留 taskId 和终态事件 |

## 数据与事务

V1 任务状态与产物预览状态分开，任务终态不可被过期轮询覆盖；V3 画布节点写入产物引用和节点状态时必须幂等。

### 涉及数据

AI Task、输入摘要、模型与 Provider 引用、事件序号、状态、错误摘要、artifactId 和脱敏审计。

### 约束与事务

提交、状态变更和事件记录按 taskId 关联；requestId 幂等；终态只允许一次；事件流断线重连不得重复产生副作用。

### 字段读写矩阵

| 数据 | AI 工作台 | Task 服务 | Worker/Provider |
| --- | --- | --- | --- |
| prompt/输入摘要 | 写入脱敏值 | 读取/固化 | 最小必要读取 |
| task 状态/事件 | 读取 | 读写 | 推进状态 |
| artifact 引用 | 读取 | 写入引用 | 产出引用 |

### 状态与生命周期

任务：`queued` -> `running` -> `succeeded`/`failed`/`cancelled`/`timed_out`；事件按单调序号追加，终态后禁止状态倒退。

### 物理约束与迁移

taskId、requestId 和事件序号唯一；输入摘要与结果引用分离存储；schema 变更需版本化，旧任务仍可查询。

### 数据所有权

DGOS Task 服务拥有任务状态和事件；Provider 拥有其运行凭据；artifact 服务拥有产物；工作台仅持有引用和展示状态。

### 安全与保留

prompt、结果和凭据按最小权限访问；日志和事件脱敏；临时输入/输出按任务保留策略清理，不影响已固化 artifact。

## 验收标准

#### AC01 文本任务闭环

Given 文本模型握手成功且提示词满足 schema。

When 用户提交任务并持续查询同一 taskId。

Then 任务进入终态，结果可读取并在 DGOS AI 工作台展示。

#### AC02 失败和重复提交

Given 网络中断或用户重复点击生成。

When 任务提交/查询发生异常。

Then UI 展示稳定错误或进行中状态，不产生未经授权的重复任务，用户可重试或取消。

并且 HTTP 响应、Task 状态和审计记录可观察；网络错误或重复提交不得创建第二个 taskId、重复调用 Provider、重复写入 Artifact 或改变已进入终态的任务。

#### AC08 文本流式输出与断线恢复

Given 已验证的 `openai-compatible` 文本模型支持流式能力，且用户提交文本任务。

When 客户端订阅 `dgos.aiTask.events`，接收增量后发生断线并重新订阅或查询任务。

Then 客户端按事件顺序显示增量，断线后不重复或丢失已确认内容，最终以同一 taskId 的 succeeded/failed/canceled 终态为准；事件和日志不泄露凭据或 Provider 私有字段。

旧 `AC03–AC07` 是跨版本设计记录，已移至 [V3 规划](../../../02-产品与版本/后续版本/V3-规划.md)与 [V4 规划](../../../02-产品与版本/后续版本/V4-规划.md)；V1 不复用这些编号，也不将其计入当前交付。
