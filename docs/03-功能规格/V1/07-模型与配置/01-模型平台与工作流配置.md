本主文档只验收 V1 Provider/模型配置基础切片：真实 API Provider Adapter、凭据托管、连通性验证、显式模型目录和文本能力策略。V3 画布工作流与 V4 供应商运行时见各版独立规划。

## 目标

用户可以查看可用的文本模型，安全配置 Provider 参数并验证连接。

## 功能边界

V1 包含：快速设置、Provider 列表、名称与 Base URL、连接协议、API Key/Token 等凭据输入与 DGOS 秘密托管、Provider Adapter 连通性验证、显式模型目录拉取、模型能力分类、模型启用/停用、按能力设置默认模型，以及供 AI Task 使用的统一模型解析契约。验证与模型拉取是两个独立动作：验证只确认协议、地址和凭据可用；用户点击“拉取模型”后才刷新目录。V1 不提供 Provider 配置导入/导出，也不提供手动添加模型；配置需要在当前设备或部署中重新填写凭据并验证。V1 首发协议为 `openai-compatible`；协议由可扩展的 `ProtocolAdapterRegistry` 注册，前端不得把协议写死为供应商名称。

普通用户的 Provider 流程保持简单：选择已注册的 Adapter，填写 Base URL 和 API Key/Token，点击验证，显式拉取模型，勾选需要启用的模型并保存默认选择。用户不需要编写能力协议 JSON、填写 operation/path、维护 workflow 或理解供应商内部参数。协议中心只面向开发者和平台管理员，用于注册、校验、测试、启停和版本管理 Adapter、能力协议及 Model Profile；协议中心的条目经过注册表发布后，才会出现在普通用户的 Adapter 和模型选择器中。

### Provider 覆盖策略

V1 首发优先交付协议能力和 Provider preset，而不是把供应商名称写进前端。OpenAI、xAI Grok、DeepSeek、通义百炼以及其他通过 contract test 的服务可以共用 `openai-compatible` adapter；preset 只提供默认 Base URL、区域/模型目录提示和文档链接。Anthropic Claude Messages 与 Gemini native 保留为独立 adapter，按 Provider Pack 在 V1 核心闭环稳定后接入。Claude Code 属于本地 Agent/CLI 应用，需要终端、文件、工作目录、进程生命周期和权限审计，不作为普通模型 Provider。

每个 Provider/模型能力必须通过官方协议和真实模型夹具验证；不能因为供应商提供文本 API，就自动把模型标记为生图、生视频、工具调用或流式模型。新增 Provider 不复制 AI Task、权限、秘密或错误状态机。

### 协议分层与声明式能力协议

Provider 配置分为三层，三层必须分别持有版本和状态：

| 层 | 解决的问题 | DGOS 责任 | V1 规则 |
| --- | --- | --- | --- |
| 连接协议（Connection Protocol） | 如何连接服务 | Base URL、鉴权方式、模型目录入口、连接验证和秘密引用 | 首发 `openai-compatible`；不能把供应商名称当作协议类型 |
| 能力协议（Capability Protocol） | 如何执行一个业务 Intent | `operations`、`workflows`、状态/错误/结果解析、上传和下载、动态参数与素材规则 | 使用 DGOS 自有 `dgos-capability/v1`；只允许声明式执行 |
| Model Profile | 哪些真实模型可以使用哪些能力 | 真实模型名/兼容别名、Intent 映射、默认值、限制、UI schema 和素材能力 | 只有 Profile 命中并启用的模型才能进入能力选择器 |

能力协议必须按真实 API 文档声明 `submit`、`query`、`download`、`upload` operation（不适用的 operation 不创建）；每个 Intent 必须绑定 workflow。异步 workflow 必须分别声明提交响应和查询响应中的 taskId、status、progress、errorCode、errorMessage 与 result/resultUrls，并明确 pending、success、failure 状态。`success` 只有在响应已含合规产物，或 workflow 继续执行 binary download 时才成立。

V1 可执行的真实业务 Intent 只有 `text.chat`。协议注册表可以为后续版本登记 `image.generate`、`image.edit`、`video.text_to_video`、`video.image_to_video`、`video.first_last_frame`、`video.multi_reference`、`video.video_to_video`、`video.audio_reference`、`audio.tts` 和 `audio.music` 的设计输入，但这些 Intent 在 V1 不进入可执行任务入口，也不计入 V1 首发验收。不确定或仅由模型名称推测的能力不得注册。画布节点专用的复合 Intent 属于 V3–V5。

能力协议 JSON 是执行唯一真源，但不是可执行脚本。V1 只接受版本化声明式结构：`schemaVersion`、`kind`、`executor`、`capabilities`、`operations`、`workflows`、`modelProfiles`、`defaults`、`limits`、`uiSchemas` 和 `assets`。DGOS 内部版本使用 `dgos-capability/v1`，不兼容 DX OS 的 `dx-protocol/v2`。

参数映射只允许白名单原语 `$map`、`$concat`、`$merge`、`$coalesce`、`$cardinality`、`$dataUrlBase64`、`$keyValue` 和 `omitEmpty`。禁止 `script`、`eval`、函数体、Shell 命令、任意 URL 拼接和按模型名称猜测参数；只有文档明确允许幂等重试时才允许 operation 配置 `retry`。协议校验失败、未声明字段、未绑定 Profile 或未满足权限时不得进入 Ready。

素材规则必须声明 `public_url`、`data_url`、`remote_name` 或 `upload_operation` 模式；使用上传 operation 时，workflow 必须绑定素材类型和 operation，已存在的合规 URL 应复用，避免重复上传。JSON 内嵌图片可声明 `maxDimension`，由 Agent 在内存中等比缩小。需要裸 Base64 的上游字段使用 `$dataUrlBase64`；响应 Base64 与 MIME 分别映射为 resultData/resultMimeTypes 并生成二进制 Artifact。需鉴权的产物下载必须使用 `responseMode=binary` 的 download operation。

能力协议的 UI schema 只声明文档支持的参数。统一参数名 `aspect_ratio`；枚举比例使用 select，支持任意比例时使用 text 并说明“宽:高”，支持超宽屏时显式包含 `21:9`。供应商的 `ratio`、`size` 或 `aspectRatio` 只能在 bodyTemplate 中映射，不能泄漏为 DGOS APP 参数。

#### 用户面与开发者面边界

| 使用者 | 入口 | 可见/可执行内容 | 不暴露内容 |
| --- | --- | --- | --- |
| 普通用户 | Provider 设置 | 选择已发布 Adapter、填写 Base URL/凭据、验证、拉取模型、勾选启用、设置默认模型 | 能力协议 JSON、operation 路径、状态 selector、映射原语、协议发布操作 |
| 开发者/平台管理员 | 开发者中心/协议中心 | 注册和校验连接协议、能力协议、Model Profile；运行真实 API 测试；发布、停用、回滚兼容版本 | 其他用户的明文凭据；未授权 Provider 的秘密 |

协议中心的开发者操作不等于用户 Provider 配置。发布新的 Adapter 或能力协议后，已有用户配置不会自动切换协议或模型；用户需要在 Provider 设置中主动选择新 Adapter、重新验证并拉取模型。停用协议不会删除用户的 Provider 配置，但会阻止新任务提交并显示原因。

V3/V4 的工作流和供应商运行配置只在[后续版本规划](../../../02-产品与版本/后续版本/README.md)维护，本版不定义其 AC。

不包含：供应商计费、密钥明文回显、在 DGOS 自建代理、绕过 DGOS 权限服务的 endpoint 拼接和模型训练。

## 完成定义

用户能新增或选择一个平台配置，验证成功后看到模型目录和图片/视频/LLM 标签；验证失败时配置不可用于任务，且秘密不出现在页面日志、项目文件或 APP 包中。

## 需求说明

### 用户故事

作为用户或开发者，我希望集中管理 Provider 和文本模型配置，以便线性任务使用可验证的模型能力而不重复填写凭据。

### 业务规则

1. Base URL、API Key 和 Provider 状态由 DGOS Secret/Config 服务管理；APP 只能提交输入和读取脱敏结果。API Key 只作为一次性写入值进入秘密边界，后续响应只返回凭据状态。
2. 验证成功后才允许 Provider 拉取模型目录；配置更新或验证失败时 Provider 必须进入 `disabled/error`，不得被 `V1-FR-005` 的新任务静默使用。已有任务按原 taskId 收敛，不因停用伪造成功或回滚终态。重新验证成功后仍需显式刷新目录。验证成功不等于目录已刷新。
3. 每个拉取模型都保存供应商原始能力、DGOS 规范化能力和用户分类状态。能力分类至少支持 `text`、`image-generation`、`video-generation`、`audio-generation`、`image-understanding`、`video-understanding`、`audio-understanding`、`embedding`；分类枚举可由能力注册表扩展。
4. 用户可以修改模型分类、启用/停用模型并设置每个能力的默认模型。只有 Provider 为 `active`、模型 `availability=available`、策略 `enabled=true` 且包含目标能力的模型，才进入对应任务选择器；未分类、停用、不可用或过期模型只能出现在模型管理页，不能被任务误选。
5. 每个 Provider 作用域内，每个能力最多有一个默认模型；设置新默认值时原默认值自动清除。默认模型必须满足当前任务入口的可用筛选条件；没有符合条件的模型时，该能力入口显示“未配置默认模型”，不得静默选择其他能力模型。
6. 用户分类不能绕过协议和 Provider 能力边界。若 Provider descriptor 明确声明不支持某能力，UI 必须显示不兼容原因；对于供应商未声明能力的模型，允许用户显式标记，但任务提交前仍需通过目标输入、模型 descriptor 和适配器校验。
7. 每个协议适配器必须发布版本化 `ProviderCapabilityDescriptor`，描述输入/输出类型、任务模式、模型目录来源、取消能力和文本流式能力；前端根据 descriptor 渲染配置与任务参数。
8. V1 的 `openai-compatible` 适配器至少支持配置 Base URL、鉴权引用、远程模型目录、模型能力映射和 SSE 文本增量；其他协议以后通过新增适配器接入，不修改 AI Task 公共契约。
9. API Key 更新通过重新提交凭据完成，旧凭据在新凭据验证成功后替换；删除凭据将 Provider 转为 `error` 或 `disabled`，清除该 Provider 下所有任务选择资格，但不删除模型分类历史。

### 前置依赖与执行边界

本功能依赖 DGOS Config、Secret、Provider Adapter Registry、Model Catalog、Permission、审计服务和 `V1-FR-005` 的模型解析入口。调用前必须确认主体有配置权限、协议/能力 descriptor 已发布、Provider 作用域明确、秘密只通过 SecretRef 或短时句柄传递；模型目录操作必须基于已验证的 Provider。V1 只执行 `openai-compatible` 文本能力，V3/V4 workflow、媒体能力和 Provider 私有 endpoint 不属于本版前置依赖。所有字段类型、必填项、枚举和响应 schema 以 OpenAPI/注册表机器契约为权威。

### 主流程

1. 用户打开快速设置或渠道配置。
2. 选择平台并填写 Base URL、API Key 或 DGOS 支持的授权方式。
3. 执行验证，DGOS 保存秘密或秘密引用并返回脱敏状态。
4. 用户点击“拉取模型”，查看供应商返回的模型与检测能力；目录刷新不自动启用模型。
5. 用户为模型分配能力分类、启用需要的模型，并按能力设置默认模型；未启用或未分类模型不进入任务选择器。
6. `V1-FR-005` 按目标能力筛选当前可用的 V1 模型；任务只调用 DGOS Provider Adapter，不直接访问供应商 endpoint 或凭据。

### 异常与边界

- URL 格式、授权或网络验证失败：保留用户输入的非秘密字段，将 Provider 原子转为 `disabled/error`，新任务选择器立即移除该 Provider 并给出可重试原因；不删除秘密引用、模型目录或分类历史。
- 模型目录为空或过期：显示空态或过期标记，不把上一次目录伪装成实时可用；刷新不会自动启用模型，也不会清除仍存在模型的用户分类；已不存在的模型转为 `stale`。
- 模型没有供应商能力声明：允许进入“待分类”列表；未完成用户分类前不得出现在生图、生视频或其他能力选择器。
- 用户将模型标记为与检测能力冲突的分类：保留显式警告，并在任务提交前由适配器再次校验；校验失败时返回 `capability_mismatch`。
- 配置被 DGOS 撤销：正在运行的任务按任务终态处理，新任务不得继续提交。
- 无权限读取/修改：拒绝操作并记录 request id，不回显 API Key。

### 页面与交互

V1 普通用户配置页提供快速设置与 Provider 列表、已发布 Adapter 选择、启用开关、脱敏状态、验证协议按钮和模型拉取按钮。模型区显示拉取数量、更新时间、待分类数量和能力分组；每个模型可勾选启用/停用，并按能力设置默认模型。验证中、成功、失败、停用、模型过期和权限不足状态都可见。开发者中心提供协议中心入口，但普通用户不进入协议编辑界面。

### 领域数据语义

V1 的 `ProviderConfig`、`ModelCatalog` 和 `ModelCapabilityPolicy` 由 DGOS Config/Model 服务持有。DGOS 保存秘密或受控秘密引用，应用只获得脱敏状态和短时使用句柄。

### 本版本不做

不实现配置导入/导出、计费、配额、供应商账号注册、跨设备同步和自建模型网关。

## 接口契约

V1 使用 DGOS `provider.*`、`config.*`、`secret.*` 和 `model.*` API，并提供协议注册表/能力描述符查询；V3/V4 再接入工作流运行时 API。具体 operationId、权限和错误键以 DGOS 机器可读契约为准。Provider Adapter 必须把不同协议映射成统一的 DGOS 模型和任务契约，不得新增绕过 DGOS 权限服务的供应商私有 HTTP 接口。

### 接口清单

| 能力 | 方向 | 业务约束 |
| --- | --- | --- |
| Provider 协议/能力目录 | 读 | 只返回已注册协议和能力声明 |
| Provider 配置 | 读/写 | 秘密只接收引用；验证成功切换 active，验证/更新失败切换 disabled/error |
| 模型目录/策略 | 读/写 | 刷新与策略更新可审计、可回滚 |

### 逐操作契约约束

r5配置成对绑定、配置CAS和Task文本参数统一见[Provider绑定与文本参数契约](../../../04-技术架构/当前版本/V1-Provider绑定与文本参数契约.md)。capabilityProtocolId/version不得半对推导；Task原子保存规范化参数及解析Profile/版本快照，submit/dispatch重检准入，执行不得重读可变defaults。AC08/09需用实际上游参数及独立worker恢复验证；resolve对象本身不是执行证明。

| operationId | 前置条件 | 成功终态 | 关键失败与无副作用 | 幂等 | 并发 | 重试/超时 | 观测/恢复 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `listProviderProtocols` | 主体有 registry read | 返回已发布协议和版本 | 越权不返回未发布配置和秘密 | 不适用：只读；替代验证：版本快照可复读 | 读取发布版本快照 | GET 2 次、2s | requestId、读取审计；重新拉取 |
| `listProviderCapabilities` | Provider 属于主体且 descriptor 已发布 | 返回脱敏 capability descriptor | 越权不返回配置/秘密，不改变 Provider 状态 | 不适用：只读；替代验证：descriptor digest | 按 provider/version 快照读取 | GET 2 次、2s | requestId、descriptor digest；重新读取 |
| `listCapabilityProtocols` | 主体有 protocol read | 返回能力协议注册表版本 | 未发布/非法协议不可见，不创建可执行目标 | 不适用：只读；替代验证：registry version | 发布版本条件读取 | GET 2 次、2s | requestId、发布审计；回到上一版本 |
| `validateCapabilityProtocol` | 管理主体、声明式 schema 可解析 | 返回校验结果和 protocol digest | 失败不发布、不启用、不调用外部 Provider | `requestId + protocolId + digest` | protocolId/version 唯一，发布锁防并发 | 真实 fixture 校验 2 次、10s | requestId、错误路径、审计；修订后重新校验 |
| `issueCapabilityProtocolConfirmation` | 显式审阅确认、新鲜Session、CSRF、provider.protocol.write | 五分钟票据，字段见主OpenAPI | 非法/跨Session/改参拒绝，不发布、不启停、不调用上游 | 同主体/requestId核对全部绑定，返回原票且不续期 | 主体/requestId唯一约束 | 不换ID盲重试；过期重新审阅 | requestId与脱敏digest；禁止记录票据秘密 |

## 数据与事务

配置更新至少具备 `draft -> validating -> active|error|disabled` 状态；验证/更新失败必须原子停用 Provider，不得继续接受新任务。秘密写入、验证结果和模型目录刷新必须具备 request id，日志只保留脱敏摘要。生成任务数据库、临时产物和诊断日志属于可清理缓存，不得与项目主数据混存。

### 涉及数据

Provider 协议与能力声明、ProviderConfig、秘密引用、验证结果、ModelCatalog、ModelCapabilityPolicy、刷新任务和脱敏审计。

### 约束与事务

配置采用 draft/active 双版本；验证成功才切换 active；验证失败切换 disabled/error；目录刷新失败不覆盖旧目录而标记 stale；策略更新与权限校验同一 requestId。

### 字段读写矩阵

| 数据 | 配置应用 | Config/Model 服务 | Provider Adapter |
| --- | --- | --- | --- |
| 配置字段 | 读写脱敏值 | 固化/验证 | 最小必要读取 |
| 秘密引用 | 写入引用 | 解析句柄 | 使用句柄 |
| 模型目录/策略 | 读取/更新策略 | 读写 | 提供能力 |

### 状态与生命周期

配置：`draft` -> `validating` -> `active`/`error`/`disabled`；模型目录：`fresh`/`stale`/`refreshing`/`unavailable`；策略：`enabled`/`disabled`。

### 物理约束与迁移

Provider 配置、模型和策略记录带 schema/version；秘密字段禁止明文落库；协议能力新增必须向后兼容或提供迁移。

### 数据所有权

DGOS Config/Model 服务拥有配置、目录和策略；凭据服务拥有秘密；Provider 只提供外部能力，不拥有 DGOS 配置记录。

### 安全与保留

秘密只以引用或短时句柄流转；日志脱敏；失效配置和刷新缓存按保留策略清理，审计保留验证与切换结果。

## 验收标准

#### AC01 配置并验证 Provider

Given 用户具有配置权限并填写合法的平台参数。

When 用户保存并点击验证。

Then DGOS 安全保存秘密或秘密引用，完成协议/地址/凭据验证并返回脱敏成功状态和能力 descriptor；Provider 进入可拉取模型目录的 active 状态，但不会隐式刷新或启用模型。

并且响应包含 `providerId`、`requestId`、状态和 descriptor digest；写入、验证失败时不得回显秘密、创建重复 Provider、隐式拉取目录或让未验证配置进入任务选择器。

#### AC02 验证失败保护

Given 新配置待验证，或已有 active 配置的更新草稿遇到 Base URL、凭据或网络不可用。

When 用户执行验证或刷新模型目录。

Then 配置更新或验证失败使 Provider 原子进入 `error/disabled` 且不能用于新任务；已有任务按原 taskId 查询并收敛，不能被伪造为成功。目录刷新失败只标记目录过期；失败不清空秘密引用、模型分类或策略历史。失败的配置版本不得继续作为新任务的旧 active 配置使用。页面和日志均不显示完整秘密。

#### AC04 首发协议与可扩展能力描述符

Given 用户选择 `openai-compatible` Provider 协议，或服务端注册了另一个符合接口的协议适配器。

When DGOS 验证配置并读取模型目录/能力描述符。

Then V1 能完成 OpenAI-compatible 配置、模型目录和流式能力映射；前端只消费统一 descriptor。新增协议适配器不要求修改 Provider 配置页和 AI Task 公共请求契约。

并且可观察到已发布 protocol/version、descriptor digest 和验证结果；未注册或不兼容协议不得进入 active、创建可执行模型或调用 Provider。

#### AC05 模型分类、启用和文本能力筛选

Given Provider 已验证并成功拉取多个模型，其中模型能力可能已检测、未声明或存在用户分类。

When 用户为模型分配能力分类、启用/停用模型并为某一能力设置默认模型。

Then 只有启用且分类匹配 `text` 能力的模型出现在 V1 文本任务选择器；未分类、媒体能力模型或已过期模型只出现在管理页，并显示原因；任务提交仍执行最终能力校验。

并且 `ModelCapabilityPolicy`、`policyVersion` 和任务筛选结果可读取；分类冲突不得改变 Provider 状态、已有任务终态或自动启用其他模型。

#### AC06 配置不提供导出

Given 用户查看 Provider 配置。

When 用户尝试迁移或导出配置。

Then V1 不提供配置导出入口；用户可以查看非秘密摘要，但 API Key、SecretRef 和连接状态不能被复制为可导入配置。

#### AC07 显式拉取、分类和筛选模型

Given Provider 已通过验证。

When 用户点击“拉取模型”，为模型分配能力分类，启用需要的模型，并为某一能力设置默认模型。

Then DGOS 保存本次目录快照和用户策略；只有 active Provider 下可用、启用且分类匹配 `text` 能力的模型出现在 V1 文本任务选择器。图片、视频和音频入口在 V1 不开放；未分类、停用、不可用或过期模型仍可在模型管理页查看并显示原因。

并且返回新的 `catalogVersion`/`policyVersion` 和审计记录；刷新失败不得清空旧目录、策略历史或创建可用模型，重复刷新不得并发覆盖目录。

#### AC08 能力协议与 Model Profile 完整映射

Given 已注册连接协议、能力协议和真实模型目录。

When DGOS 解析协议并刷新模型目录。

Then 每个可用 Intent 都能解析到一个已校验 workflow；每个进入选择器的模型都命中包含真实模型名或兼容别名的 Model Profile，并返回 capabilities、defaults、limits、uiSchemas 和 assets；没有 Profile 映射的模型只能显示在待配置列表。

并且 protocol/Model Profile 校验结果和未映射列表可观察；缺失映射不得创建成功任务、自动启用模型或执行未声明 operation。

#### AC09 声明式异步执行与安全结果闭环

Given 一个已校验能力协议为 V1 `text.chat` 声明受支持的 submit/query operation。

When 用户在 AI 工作台提交文本任务并等待结果。

Then DGOS 仅执行该文本 Intent 的白名单声明式 operation，按 workflow 的 pending/success/failure 状态追踪；成功结果写入统一 AI Task/Artifact 契约。脚本、任意 URL 拼接、未声明字段及媒体 upload/binary download 均不得在 V1 文本入口执行；失败不创建成功产物。

旧 `AC03` 为 V3/V4 工作流配置设计，验收方向移至 [V3 规划](../../../02-产品与版本/后续版本/V3-规划.md)与 [V4 规划](../../../02-产品与版本/后续版本/V4-规划.md)；V1 不复用该编号。
