# 系统智能助手与动作执行技术设计

来源：[功能主文档](01-系统智能助手与快捷指令.md)。

## 单元契约

| 单元 | 前置条件 | 返回 | 副作用 |
| --- | --- | --- | --- |
| `planAction` | 动作已注册、主体可见 | 脱敏计划与确认要求 | 无 |
| `executeAction` | schema、权限、确认票据均有效 | 同一 requestId 的运行记录 | 最多一次受控 handler 调用与审计 |
| `cancelActionRun` | 运行属于当前主体且可取消 | 可查询取消状态 | 向下游发送取消信号 |

## 伪代码

```text
plan = registry.resolve(actionId, version)             // B09-01
if not plan or not broker.visible(subject, plan): return denied
if plan.version not allowed_in_V1: return missing      // B09-02
if plan.requiresConfirmation and not confirmed: return awaiting_confirmation
if not broker.recheck(subject, plan): return denied    // B09-01
run = executor.submit_once(requestId, plan)           // B09-03
return run.snapshot()
```

## 1. 设计目标

在 DGOS 平台能力和应用业务之间增加一个受控动作层，使自然语言和快捷指令都调用同一套声明、授权、执行、任务和审计语义。助手不获得全局特权，不直接调用应用私有 API。

## 2. 组件边界

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| Assistant App | 收集输入、展示候选/计划/确认、显示结果与历史 | 直接执行系统副作用 |
| Intent Resolver | 将自然语言映射到动作候选和结构化输入 | 猜测未注册动作、绕过授权 |
| Action Registry | 保存动作声明、版本、来源、状态和依赖 | 代替执行时鉴权 |
| Capability Broker | 按主体、应用、资源和当前策略校验能力 | 解释自然语言 |
| Action Executor | 校验 schema、幂等、超时、取消、结果和状态 | 暴露内部服务对象 |
| Task/Audit Services | 持久化长任务状态和脱敏审计 | 保存秘密或完整提示词 |

## 3. 执行状态机

```text
candidate -> planned -> awaiting-confirmation -> authorized
          -> running -> succeeded
          -> denied | cancelled | failed | expired | missing
```

`candidate` 和 `planned` 不产生副作用；`authorized` 只代表本次执行已获准；所有副作用从 `running` 开始。相同 `requestId` 的重复提交返回原执行记录，不重新执行不可幂等动作。

## 4. 自然语言与快捷指令

- 快捷指令直接解析为版本化 `actionId + input`，不经模型。
- 自然语言先由已配置 Provider 生成候选意图，候选必须经过 Registry 的 schema、状态和权限过滤；模型返回的工具名、路径或权限不能直接执行。
- 候选超过一个或输入缺字段时进入澄清状态；不得选择“最像”的副作用动作自动运行。
- 低风险只读/导航动作可在解析后直接执行；其他动作必须生成可读计划，包含动作、目标、输入摘要、风险和确认要求。

## 5. 应用动作注册

应用安装时校验动作声明；启用时注册快照。动作更新必须递增版本并通过 schema/权限兼容检查。Registry 保存 `actionId`、`appId`、`actionVersion`、来源、输入/输出 schema、capabilities、风险、副作用、幂等、取消、handler 和状态。动作不能声明超过应用 manifest 的能力，也不能把展示名作为稳定引用。

## 6. 安全边界

1. Resolver 只能看到当前主体可见的动作摘要和经过脱敏的资源摘要。
2. Broker 在执行前重新检查主体、应用状态、动作版本、资源所有权、权限和确认票据。
3. Provider Adapter 只接收最小化的意图上下文；API Key、Cookie、私有路径、完整 System Prompt 和临时 URL 永不进入 Resolver 输入。
4. Action Executor 只调用已注册 handler；handler 继续使用 DGOS 公共 capability，不允许执行任意脚本或动态 API 路径。
5. 审计记录动作身份/版本、调用者、授权决定、确认结果、状态转换、错误分类和脱敏摘要。

## 7. 取消、重试与恢复

- 只读动作失败可由用户显式重试；有副作用动作是否可重试由动作声明的幂等性决定。
- 可取消动作在执行器和下游任务都收到取消信号后才进入 `cancelled`；无法确认下游状态时显示 `cancel-pending` 或等价的未决状态。
- 长任务保存 `taskId`、动作版本快照和输入摘要；助手窗口关闭不影响任务状态。
- 动作被卸载或禁用时，运行中的任务按任务策略继续、停止或进入 `missing`，结果必须可查询并写审计。

## 8. 版本边界

V1 允许系统导航/查询、系统设置和已公开应用配置动作；覆盖范围由动作注册、公开写 API、权限、风险确认和 E2E 就绪共同决定。写入、删除、权限/隐私、秘密/凭据、网络出口、不可逆或外部副作用动作必须在执行前确认并重新鉴权。项目、画布、资产和未具备公开契约的跨应用动作必须等上游领域稳定后再注册；不能通过助手提前暴露未完成能力。

## 9. 待 ADR 冻结

- 动作声明 JSON Schema、风险/副作用枚举、增强确认策略和设置/应用配置动作目录；
- Resolver 使用的模型、上下文裁剪和本地快捷指令语法；
- Assistant App 的历史保留、敏感内容脱敏和跨设备同步；
- 桌面/Web 容器中动作确认 UI 与 DGOS Host Adapter 能力差异。

## 稳定设计分支

- `B09-01`：动作注册、解析、授权、确认和执行必须共享同一版本化 `actionId` 与输入 schema。
- `B09-02`：V1 助手覆盖有公开契约的系统设置和应用配置；写入、删除、权限/隐私、秘密/凭据、网络出口和外部副作用必须确认。画布、资产及未具备上游契约的动作不得提前注册。
- `B09-03`：副作用动作使用 `requestId` 幂等提交，长任务使用 DGOS `taskId`，所有状态转换写入脱敏审计。
- `B09-04`：配置动作在提交前重检主体、动作版本、资源/设置版本、capability 与确认票据；拒绝、冲突或过期不产生目标写入。
