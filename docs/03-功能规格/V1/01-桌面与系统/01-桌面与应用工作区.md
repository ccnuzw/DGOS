## 目标

用户从 DGOS 自有桌面发现并打开应用，能在窗口、Dock/启动台和系统入口之间保持稳定的系统工作区上下文；V1 不提供 V2 项目文档的创建、读写或持久化。

## 功能边界

包含：桌面入口、启动台图标、窗口打开/关闭/聚焦、最近应用与窗口工作区摘要、系统信息入口、系统设置入口、已安装软件列表及安装/卸载/更新状态的展示。系统设置在 V1 提供 DGOS 系统级外观、语言与地区、网络代理、隐私安全和应用权限管理；这些设置由 DGOS 系统服务维护，并通过运行时上下文提供给所有应用。

不包含：移动端完整适配、规模化商店运营/计费、组织级策略和 DX OS 私有协议兼容。

## 完成定义

## 需求说明

### 用户故事

作为 DGOS 用户，我希望从系统桌面快速进入已安装应用并恢复上次的窗口工作区，以便继续处理当前系统任务。

### 业务规则

1. 入口显示的 APP 名称、图标和版本以已安装包清单为准。
2. 系统版本、服务端口/访问地址、文件存储位置、权限入口和 API 设置入口由 DGOS 系统服务提供。
3. APP 关闭后再次打开不得清空 DGOS 自有设置、安装状态或窗口工作区摘要；V1 不承诺 V2 项目文档持久化。
4. “我的软件”中的安装、卸载和更新状态必须反映 DGOS 安装状态，不能由浏览器存储模拟。
5. 外观设置由 DGOS 统一提供 `appearanceMode`、窗口材质、界面模式、显示倍率和明暗壁纸；应用读取系统上下文，不得各自维护一套与系统冲突的主题、缩放或窗口生命周期。
6. 语言与地区至少区分界面语言、当前生效语言、地区格式、助手回复语言和项目内容语言。V1 只保存项目内容语言的未来默认语义，不操作 V2 项目文档；切换界面语言不得隐式翻译 Skill 内容或应用数据。
7. 网络代理支持跟随系统、手动和关闭三种模式。Provider 请求、模型拉取、Skill/MCP 在线导入和 DGOS 后台服务必须使用统一有效路由；修改代理后，受影响的后台服务标记为需要重启。
8. 系统权限采用 `allow`、`ask`、`deny` 三态，按主体、APP、capability 和 scope 计算。APP manifest 只能声明能力，不能覆盖系统的 `deny`；`ask` 必须在产生副作用前确认。
9. “允许打开 APP”和 APP 的 Agent 能力授权分开管理。应用可见或可启动不等于可以写文件、调用 MCP、运行 Skill、发送通知或打开外部页面。
10. 删除文件、修改文件、调用 MCP、运行 Skill 等副作用操作在执行层重新检查授权并写入脱敏审计；前端隐藏按钮和缓存授权不能作为安全边界。

### 前置依赖与执行边界

本功能依赖 DGOS 系统服务、窗口/桌面宿主、应用安装状态、Session 主体、Capability Broker 和版本化设置存储；调用方必须先建立主体 Session、确认 APP 已安装且 API 版本兼容，并按当前主体、APP、capability 和 scope 重新计算权限。`baseVersion`、`contextVersion` 和安装状态是跨桌面/Web 调用的并发边界。系统服务、权限服务或安装状态不可用时只能返回稳定的不可用/重试终态，不能以浏览器缓存冒充当前状态。V2 Project API、项目文件和未来版本项目状态不是本功能的前置依赖，也不能在本版流程中被写入。

### 主流程

1. 用户启动 DGOS，系统壳层加载桌面、Dock/启动台和应用目录。
2. 用户选择已安装应用；DGOS 校验安装状态、权限和兼容的 API 版本并创建窗口。
3. 应用读取当前主体已授权的最近应用和窗口工作区摘要。
4. 用户可从系统信息、应用目录或设置进入应用、权限和系统服务管理。
5. 用户在设置中修改外观、语言、地区或网络代理；DGOS 保存版本化设置并向已运行应用发送上下文变化事件。
6. 用户打开隐私安全或某个 APP 的权限页，按能力和范围调整 `allow / ask / deny`；下一次调用由 capability broker 重新判定。

### 异常与边界

- 包校验失败：阻止启动并展示可追踪错误。
- 工作区摘要读取失败：保留窗口，展示恢复/重试入口，不覆盖现有系统状态。
- DGOS 安装状态暂不可用：展示未知/加载中状态，不用缓存值冒充当前安装状态。
- 代理配置保存成功但后台服务未重启：显示“已保存、等待重启”，不能把旧路由显示为当前有效路由。
- 应用请求未声明或被系统拒绝的 capability：在副作用发生前返回稳定权限错误并保留 requestId。

### 页面与交互

桌面入口、启动台、窗口标题栏、最近应用/窗口工作区列表、系统信息入口和“我的软件”列表；设置页按外观、语言与地区、网络、隐私安全、应用权限和 Provider 入口分组。所有加载/失败状态可见，窗口尺寸变化不应破坏应用入口。设置页展示“当前生效值”和“待重启”状态，不把应用私有覆盖值冒充系统值。

### 领域数据语义

安装状态和最近窗口工作区摘要归 DGOS 对应系统服务所有；V2 项目文档不属于 V1 桌面工作区的数据范围。应用只能读取当前主体授权的运行时上下文和经 broker 授权的能力结果。

### 本版本不做

V1 不实现 V2 Project API/项目文档持久化、规模化商店运营、计费和移动端桌面；DGOS 自有桌面管理、应用目录、更新回滚、系统设置和秘密边界属于本功能或相关 V1 平台功能。

## 接口契约

使用 DGOS `system.*`、`app.*` 和 `permission.*` API；设置读写通过 `system.settings.read/write`，运行时上下文通过 `dgos.system.context.read` 和变更订阅提供。传输方式与字段 schema 以 V1 接口契约和 OpenAPI 草案为准，最终认证方式仍待 ADR 冻结。

### 接口清单

| 能力 | 方向 | 业务约束 |
| --- | --- | --- |
| 系统设置读写 | 读/写 | 按设置域校验，写入返回版本与待重启状态 |
| 系统上下文 | 读/订阅 | 只返回当前主体可见的脱敏上下文 |
| 权限判定与请求 | 读/写 | 执行副作用前重新判定，`deny` 优先 |

### OpenAPI operation 映射

| 业务能力 | operationId | 当前状态 |
| --- | --- | --- |
| 读取系统设置 | `readSystemSettings` | V1 OpenAPI 已声明 |
| 写入系统设置 | `writeSystemSettings` | V1 OpenAPI 已声明 |
| 读取系统上下文 | `readSystemContext` | V1 OpenAPI 已声明 |
| 订阅系统上下文 | `subscribeSystemContext` | V1 OpenAPI 已声明 |
| 检查权限 | `checkPermission` | V1 OpenAPI 已声明 |
| 请求权限 | `requestPermission` | V1 OpenAPI 已声明 |

### 逐操作契约约束

HTTP 字段类型、必填项、枚举和响应 schema 只以 [V1-openapi.yaml](../../../04-技术架构/当前版本/V1-openapi.yaml) 为权威；下表补充业务前置、终态、失败副作用和运行治理。

| operationId | 前置条件 | 成功终态 | 关键失败与无副作用 | 幂等 | 并发 | 重试/超时 | 观测/恢复 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `readSystemSettings` | Session 有效且主体有 settings read | 返回脱敏 settings snapshot 与 `settingsVersion` | 无权返回 `permission_denied`，不返回私有设置 | 不适用：只读；替代验证：相同版本读取结果一致 | 以返回的 `settingsVersion` 标识快照 | GET 可重试 2 次，单次 2s；不得创建写入 | requestId、读取审计；失败显示加载/重试 |
| `writeSystemSettings` | 主体有 settings write，patch 只含一个域且带 `baseVersion` | 原子返回新 `settingsVersion`、生效值和 `restartRequired` | 校验/版本冲突返回错误，不部分写入、不改变旧设置、不调用受影响服务 | `requestId + subject + domain + baseVersion`；重复请求返回同一结果 | `baseVersion` 乐观并发条件，冲突返回 `conflict` | 相同 requestId 最多重试 2 次，3s 超时；不得用新 requestId 重复写入 | requestId、审计、冲突指标；返回当前版本供重载 |
| `readSystemContext` | APP 已安装、Session 有效且有 context read | 返回脱敏 `SystemContextSnapshot` 与 `contextVersion` | 无权/服务不可用不泄露网络、代理或路径，不写入上下文 | 不适用：只读快照；替代验证：contextVersion 可复核 | 以 `contextVersion` 去重 | GET 可重试 2 次，2s 超时；过期快照不得覆盖当前值 | requestId、读取审计；重新读取最新快照 |
| `subscribeSystemContext` | APP 有订阅权限且已读取初始快照 | SSE 返回递增事件和 `contextVersion` | 断线不改设置、不重复写事件、不泄露秘密 | 不适用：订阅；替代验证：Last-Event-ID/版本去重 | 单主体/APP 订阅以版本序列排序 | 断线可重连 3 次，1s/2s/4s；连接 5s 无事件超时 | requestId、连接/断线指标；断线后重新读快照 |
| `checkPermission` | 主体、APP、capability、scope 均已规范化 | 返回 `decision`、`reasonCode`、`policyVersion`、`requestId` | 拒绝只返回判定，不执行目标副作用、不写业务实体 | 不适用：纯判定；替代验证：同 policyVersion 可复核 | 按 policyVersion 快照计算，不锁业务实体 | 纯本地判定 1s；服务不可用返回 `service_unavailable` | requestId、脱敏审计；调用方按 reasonCode 处理 |
| `requestPermission` | 主体已登录，capability 已注册且请求范围明确 | 创建待确认请求并返回 requestId | 未确认不写授权决定、不调用外部服务、不执行副作用 | `requestId + subject + app + capability + scope` | 同一待确认请求只能有一个活动版本 | UI 重复提交复用 requestId，2s 超时；不自动重试确认 | requestId、确认事件审计；过期后重新请求 |

### 错误矩阵

| 场景 | error_key/结果 | 处理要求 |
| --- | --- | --- |
| 设置字段无效 | `invalid_request` | 整体拒绝，不得部分写入 |
| 权限拒绝 | `permission_denied` | 返回 `requestId`，不得执行副作用 |
| 上下文暂不可用 | `service_unavailable` | 展示加载/重试，不以缓存冒充当前值 |

## 数据与事务

系统设置写入按设置域分别校验和版本化；无效字段不得部分写入。代理变更需记录 `restartRequired` 和受影响服务。工作区摘要读取失败不得写入空状态覆盖现有系统状态。

### 涉及数据

系统设置、版本化系统上下文、应用安装状态、窗口工作区摘要、权限决定、代理路由和脱敏审计事件。

### 约束与事务

设置域采用原子写入；权限决定在提交副作用前再次读取；代理变更与 `restartRequired` 同一事务提交；工作区摘要失败不得覆盖最后一个有效值。

### 字段读写矩阵

| 数据 | DGOS 系统服务 | 桌面/应用 | 助手 |
| --- | --- | --- | --- |
| 设置值 | 读写 | 只读上下文 | 仅经动作授权读取 |
| 权限决定 | 读写 | 请求 | 读取判定结果 |
| 安装/窗口状态 | 读写 | 读取 | 只读摘要 |

### 状态与生命周期

设置：`draft` -> `active` -> `pending_restart`；应用安装：`installed`/`updating`/`failed`；权限：`allow`/`ask`/`deny`。

### 物理约束与迁移

设置记录必须带 schema 版本和主体/作用域键；新增字段向后兼容，破坏性变更需迁移脚本和回滚方案。窗口摘要不得持久化项目文档或秘密。

### 数据所有权

DGOS 系统服务拥有设置、安装状态、权限决定和窗口摘要；应用只拥有其私有数据，不能覆盖系统权威值。

### 安全与保留

权限和代理凭据按安全基线加密存储；审计只保留脱敏摘要和 requestId；窗口摘要按系统保留策略清理，不进入 URL、日志或项目文档。

## 验收标准

#### AC01 启动 DGOS 桌面并打开应用

Given DGOS 已启动，应用目录包含一项已安装且 manifest/API 版本兼容的应用。

When 用户从 Dock、启动台或应用目录启动该应用。

Then DGOS 创建可聚焦和最大化的应用窗口，并显示该应用授权可访问的入口；该流程不调用 V2 Project API。

#### AC02 包校验失败

Given 安装包签名或本地资源校验失败。

When 用户尝试启动 APP。

Then DGOS 阻止运行并显示可追踪错误，现有已安装版本仍可恢复。

并且返回稳定的校验错误和审计 requestId；不得创建新的安装记录、窗口运行记录或外部调用，现有活动版本和窗口状态保持不变。

#### AC03 查看 DGOS 系统与应用状态

Given DGOS 系统服务可用，且系统中存在已安装和更新中的应用。

When 用户打开系统信息或“我的软件”。

Then 页面显示 DGOS 版本、系统服务状态、存储/权限/API 设置入口，以及每个应用的安装、卸载或更新状态；显示值来自 DGOS 权威系统服务。

并且页面可观察到每项状态的来源和读取 requestId；服务不可用时显示 `service_unavailable`/加载终态，不得写入空状态或用缓存覆盖权威状态。

#### AC04 系统外观和倍率统一注入应用

Given DGOS 设置为深色模式、窗口材质为系统玻璃、显示倍率为 125%，且已安装的 APP 声明读取系统上下文。

When 用户打开 APP 或在设置中修改主题/倍率。

Then APP 收到同一份版本化系统上下文，应用界面跟随 `colorScheme`、`windowMaterial` 和 `displayScale` 更新；APP 不需要也不能自行覆盖 DGOS 宿主窗口或用 CSS 缩放替代系统倍率。

#### AC05 语言、地区和助手语言分离

Given 用户把界面语言切换为英文、地区格式保留为中国大陆、助手回复语言设置为中文。

When 用户重新打开系统应用和系统助手。

Then 菜单和系统按钮使用英文，日期/数字使用中国大陆格式，助手回复使用中文；未迁移 APP 显示明确的语言回退状态，V1 不隐式翻译应用私有数据。

#### AC06 代理保存与重启状态

Given 用户选择手动代理并填写合法地址。

When 用户保存网络设置。

Then DGOS 返回脱敏的有效路由、受影响服务和 `restartRequired=true`；Provider、模型拉取和在线扩展导入在服务重启前不得宣称已切换到新路由。

#### AC07 系统拒绝优先于 APP 声明

Given APP manifest 声明 `dgos.file.write`，但当前主体对目标作用域的决定为 `deny`。

When APP 或系统助手请求写入文件。

Then capability broker 在写入前拒绝请求，返回稳定权限错误和 requestId，并生成不含秘密和私有路径的审计摘要。

并且不写入目标文件、不调用 MCP、不改变权限决定或应用状态；这些无副作用事实通过权限响应、审计记录和目标状态未变化共同验证。

#### AC08 APP 启动权限与能力授权分离

Given 用户允许打开某 APP，但未授权该 APP 调用 MCP。

When APP 请求调用 MCP 工具。

Then APP 可以启动和读取允许的系统上下文，但 MCP 调用显示 `denied`，不会因 APP 已打开或 manifest 已声明而自动获得授权。

并且返回可观察的 `permission_denied` 响应和审计事件，不调用 MCP、不写入外部资源、不改变原有权限决定；APP 的启动状态保持不变。
