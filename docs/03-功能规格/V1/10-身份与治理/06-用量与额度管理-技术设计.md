# 用量与额度管理：技术设计

来源：[功能主文档](06-用量与额度管理.md)，ADR-0005/0006；FR-005拥有任务事实。本设计不引入支付、用户余额或供应商账单。

## 单元契约

| 单元 | 前置条件 | 返回/后置条件 | 副作用 |
| --- | --- | --- | --- |
| preflight(input) | 有效主体/模型/账号/策略 | allow/deny，不预先创建Task | 拒绝无Task/attempt/reservation/上游调用 |
| admitAndReserve(input) | 预检通过、事务内再次比较余额度 | 并发硬限额不超发、唯一请求关联 | Task准入与reservation原子或可证明回滚 |
| settleTerminal(task, attempt) | 权威终态与真实调用事实 | 唯一settled/released及usage | 终态/outbox/usage恢复一致 |
| reconcile(checkpoint) | 有效任务/调用/预留事实 | 补结算或显式待核对 | 不重发Provider |

## 伪代码

```text
admit(input): Result<Task>
  // B15-01
  validate authority/model/account; preflight before any task persistence
  if denied: return quota_exceeded with no task/attempt/reservation
  // B15-02
  BEGIN TRANSACTION; lock quota window; recheck policy and remaining quota
  if insufficient: ROLLBACK; no task or reservation survives
  persist unique task/request + reservation + outbox; COMMIT OR ROLLBACK
terminal(input): Result<Usage>
  // B15-03
  atomically commit or durably reconcile Task/Attempt/Event/Artifact/reservation
  deduplicate taskId+attemptId+metric; settle/release once
  // B15-04
  if upstream usage missing: record unavailable, never invent tokens/cost
  if provider submission uncertain after crash: no blind replay, explicit diagnostic terminal
queryOrSetPolicy(input): Result<Summary>
  // B15-05
  check subject/resource authorization and policy version; conflict => no mutation
reconcile(checkpoint): Result<Checkpoint>
  // B15-03
  read authoritative task/attempt/call facts; repair settlement/release once
  mere expiry is not sufficient evidence of task outcome; unresolved => needs review
```

## 约束备注

复用既有quota表/唯一结算，不重建平行账务。预检与真正reserve之间仍需行锁重检，不能只信一次allow。多资源跨域通过数据库事务或持久恢复记录维持不变量；不能将串行调用当成原子。只使用已冻结额度策略，不自启用fail-open。UTC窗口，过期预留不能凭时间猜测上游事实。具体资产与命令见[AC资产核对](../V1-AC资产核对-2026-10-02.md)。
