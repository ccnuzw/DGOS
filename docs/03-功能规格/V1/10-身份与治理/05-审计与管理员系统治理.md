## 目标

为 DGOS 高权限操作提供统一、只追加、可查询且脱敏的审计事实，并为管理员提供策略、服务状态、保留策略和受控恢复的治理入口。

## 功能边界

为 DGOS 高权限操作提供统一、只追加、可查询且脱敏的审计事实，并为管理员提供策略、服务状态、保留策略和受控恢复的治理入口。管理员登录由 `FR-010` 提供；具体业务写操作仍由各领域服务执行，本功能不成为绕过领域授权的万能管理 API。

包含认证/会话、权限判定与变更、APP 审核/安装、Provider/Secret 管理、系统设置、Agent/MCP/Skill 外部副作用、密钥轮换/撤销、保留作业的审计与治理。V1 不包含组织合规报表、法务保全、SIEM 商业集成或不可变 WORM 存储承诺。

## 需求说明

### 业务规则

1. 审计事件由执行副作用的领域服务在提交边界写入；关键状态变更与审计事件同事务提交或使用可恢复 outbox，禁止先成功后无记录。
2. 事件只追加，不允许业务 API 更新/删除；更正通过补充事件表达。系统管理员不得通过日常 UI 修改历史事件。
3. 最低字段：eventId、occurredAt、requestId、actor、actorType、action、targetType/targetId、decision/result、reasonCode、policyVersion、deploymentId 和脱敏摘要。
4. 禁止记录密码、API Key、Cookie、Token、Authorization、完整代理凭据、完整上游 body、私有文件绝对路径和不必要个人数据。
5. 管理员查询受 `audit.read`、主体范围、时间范围和分页限制；批量导出 V1 不开放。读取自身审计访问也产生审计事件。
6. 权限/Provider/网络策略更新必须带 baseVersion，冲突不部分写入；高风险操作要求确认与新鲜认证，并保存操作者、理由和前后摘要。
7. 保留与清理使用分类策略和 dry-run 预览；审计法定保留例外待治理 ADR，清理不能删除未到期事件或破坏调查关联。
8. 服务降级必须显式显示不可用；对必须审计的高风险副作用，Audit Store/outbox 无法接受事件时 fail closed。

### 前置依赖与执行边界

前置：管理员会话有效、角色含目标治理能力、Policy/Audit 服务可用。治理入口读取状态 -> 管理员提交版本化变更及理由 -> 领域服务重新鉴权并校验 -> 原子提交状态和审计 -> 提供 eventId 与新版本。审计搜索只返回授权范围内脱敏记录。

错误：`permission_denied`、`version_conflict`、`audit_unavailable`、`invalid_retention_policy`、`target_in_use`、`service_unavailable`。失败不部分修改策略、不清理数据、不创建无审计的成功副作用。

### 主流程

治理入口读取状态 -> 管理员提交版本化变更及理由 -> 领域服务重新鉴权并校验 -> 原子提交状态和审计 -> 提供 eventId 与新版本。

### 异常与边界

错误包括 `permission_denied`、`version_conflict`、`audit_unavailable`、`invalid_retention_policy`、`target_in_use`、`service_unavailable`。失败不部分修改策略、不清理数据、不产生无审计成功副作用。

### 页面与交互

治理页提供脱敏审计查询、策略版本、保留预览和失败恢复状态；不提供批量导出或历史事件编辑。

### 领域数据语义

`AuditEvent` 追加记录；`GovernanceChange` 保存策略/设置变更摘要、操作者、审批/确认引用、baseVersion/newVersion 和回滚关联；`RetentionJob` 保存预览、执行范围、跳过/失败计数和可重试状态。数据保留期限由安全基线与治理 ADR 冻结，不能由页面任意缩短。

事件状态：领域结果事实 immutable；清理任务 `planned/running/completed/partial/failed`。审计写入允许 outbox 重试，但 eventId 去重，禁止重复业务副作用。

### 本版本不做

不承诺组织合规报表、法务保全、SIEM 商业集成或 WORM 存储；具体保留例外由 ADR 冻结。

## 数据与事务

### 涉及数据

`AuditEvent`、`GovernanceChange`、`RetentionJob`、策略版本和 outbox 事件。

### 约束与事务

领域状态与审计事件同事务或经 eventId 去重的 outbox 提交；清理批次有 checkpoint，重试不重复副作用。

### 字段读写矩阵

| 数据 | Governance | 管理员应用 | Audit Store |
| --- | --- | --- | --- |
| 治理策略 | 读写 | 脱敏提交 | 版本摘要 |
| 审计事件 | 追加/查询 | 授权查询 | 权威持有 |
| 清理任务 | 创建/执行 | 查询/确认 | 结果摘要 |

### 状态与生命周期

AuditEvent immutable；RetentionJob `planned -> running -> completed/partial/failed`。

### 物理约束与迁移

eventId 唯一、追加写；治理策略带版本；RetentionJob checkpoint 可恢复。物理约束、事务 outbox 和恢复规则遵循 ADR-0006；当前仍无 migration 证据。

### 数据所有权

Audit Store 拥有事件，Governance 服务拥有策略与清理任务，领域服务拥有业务状态。

### 安全与保留

秘密、完整路径、完整上游 body 和不必要个人数据不进入事件；保留期限遵循安全基线和治理 ADR。

## 验收标准

#### AC01–AC05 审计与管理员系统治理

Given 管理员拥有治理权限且目标服务可用或显式注入不可用。

When 执行高风险变更、审计查询、策略更新或保留清理。

Then 成功状态可关联 eventId/requestId，失败不产生无审计副作用，脱敏查询和清理 checkpoint 受权限与引用保护约束。

| AC | Given / When | Then 与无副作用断言 |
| --- | --- | --- |
| AC01 高风险操作审计 | 管理员执行设置、权限、Provider 或审核变更 | 状态变更与审计事件可关联到 requestId；失败/冲突不改变目标状态 |
| AC02 脱敏查询 | 有 `audit.read` 权限的管理员查询记录 | 只返回授权范围内分页记录；秘密和私有路径被删除或结构化脱敏，读取本身留审计 |
| AC03 审计服务不可用 | 必须审计的高风险写入期间 Audit Store/outbox 不可用 | 写操作 fail closed 或可证明事务 outbox 原子落盘；不得产生无审计成功状态 |
| AC04 保留预览与执行 | 管理员按冻结策略启动清理 | 先显示分类、数量和引用保护；执行只删除到期且可清理数据，失败可恢复/重试并记录结果 |
| AC05 策略版本冲突 | 两个管理员基于相同旧版本修改治理策略 | 仅一个版本提交，另一个返回 conflict；不得覆盖最新策略或丢失审计 |

## 安全、观测与恢复

审计事件按 eventId/requestId/actor/action 查询，记录完整性校验摘要和写入延迟；不得将摘要宣称为不可篡改证明，除非底层存储与密钥轮换方案另行冻结。outbox 按 eventId 安全重试；保留作业失败时保留 checkpoint 和跳过原因，人工恢复不得重放已成功删除动作。
